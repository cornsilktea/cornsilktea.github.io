## 프롬프트

42번 타워 클라임에 **스피드런 모드**를 만들어 줘. 시작 전에 `docs/42.tower-climb/42.tower-climb-notes.md`(특히 3절 규칙 엔진, 4-7절 스테이지 7, 5절 화면)와 사양 `docs/42.tower-climb/42.tower-climb-proposal.md` 를 읽고, 저장소 `CLAUDE.md` 규칙(TypeScript·객체지향·전역 금지·주석 없이 이름으로·`?v=` 올리기·커밋·푸시)을 지켜.

### 1. 두 모드로 나누기

- **일반 모드(지금 모드)**: 허브의 스테이지 포탈(2~7)을 그대로 쓴다. 연습용이다. 기록은 **개인 최고 높이**(기기 `towerclimb_best_v1` 의 `h` + 계정 동기화)와 클리어한 스테이지(`s`, 포탈 열기용)만 남긴다.
  - 지금 일반 모드에 있는 **시간 기록은 없앤다**: 스테이지 1 시간(`stageOneTime`, `t`, `offerTime`)과 꼭대기까지 시간(`f`, `offerClimbTime`, 결과 화면의 "꼭대기까지 최고 기록"). 저장된 옛 `t`·`f` 값은 읽을 때 버린다(`ClimbRecords.parse`·`merge` 정리).
  - 일반 모드에서 꼭대기에 닿으면 결과 화면은 "꼭대기 도착!"·떨어진 횟수·포탈 사용 횟수만 보여 주고 시간 기록은 남기지 않는다.
- **스피드런 모드**: 허브에 **스피드런 포탈** 하나를 새로 둔다(스테이지 포탈과 색·글자가 다르게, 예: 금색 문 + "스피드런" 판). 처음부터 열려 있다(스테이지 클리어와 상관없음).
  - 일반 모드에서 스피드런 포탈에 들어가면 **그 순간부터 스피드런 모드**다. 화면이 하얗게 넘어간 뒤 허브의 시작 지점(`level.spawn`)에 선 채로 시작하고, **들어간 순간(포탈에 닿은 틱)부터 시간이 흐른다**(첫 입력을 기다리지 않는다).
  - 스피드런 중에는 **스테이지 포탈 2~7 을 쓸 수 없다**: 잠긴 회색으로 보이고 닿아도 들어가지지 않는다. 가까이 가면 "스피드런 중에는 포탈을 쓸 수 없어요" 안내.
  - 스피드런 중에 **스피드런 포탈을 다시 타면 나가기**다: 기록 없이 일반 모드로 돌아와 허브 시작 지점에 선다. 그 포탈 판 글자는 스피드런 중에 "나가기"로 바뀐다.
  - 떨어져서 허브로 돌아와도(`fellHome`·`voidReturn`) **시간은 멈추지 않고** 스피드런은 계속된다.
  - 시간과 함께 **높이도 잰다**: 이번 스피드런의 최고 높이, 스테이지마다 처음 닿은 시각(구간 기록 split: 30m·60m·…·180m 쉼터, 200m 꼭대기).
  - **꼭대기 깃발(`summit`)에 서는 순간의 시간**이 기록이다. 결과 화면: 걸린 시간, 구간 기록(스테이지별), 떨어진 횟수, 개인 최고 기록과 비교·`NEW`, 다시 하기(스피드런으로 바로 다시) / 나가기(일반 모드) 버튼.
  - 멈춤 화면(`Esc`)을 열어도 스피드런 시간은 멈추게 할지 선생님께 먼저 물어(★기본값: 멈춤 중에는 시간도 멈춤, 대신 멈춤 화면을 연 횟수는 결과에 안 남김).
  - 스피드런 중 "처음 지점에서 다시"·"시작 화면으로" 를 누르면 그 스피드런은 기록 없이 끝난다.

### 2. 기록

- 스피드런 개인 최고 시간: 기기 저장(키는 새로 `towerclimb_speed_v1`, try/catch) + 계정 동기화(`WorldRecord.syncBest`, `merge: WorldRecord.betterOf(…, lower)`), 시작 화면·HUD·결과 화면 세 곳에 표시(갱신 시 `NEW`). 구간 기록도 같이 저장해 결과 화면에서 개인 최고 판과 구간별로 비교(빨강 느림 / 초록 빠름 같은 표시).
- **세계 신기록·우리 반 신기록**: 새 게임 키 `towerclimbspeed`(소문자 영문만), `WorldRecord("towerclimbspeed", { lower: true, format: 분:초.십분의 일초 })`, 꼭대기 도착 때 `WR.prompt(값)`. `데이터베이스규칙.json` `.validate` 에 점수 상한 한 줄(`lower:true` 라 `10억 - 값` 으로 저장되는 것 고려, 너무 빠른 시간(예: 60초 미만)은 막는 하한)을 넣고, 선생님께 콘솔 게시가 필요하다고 알려.
- 높이 세계 기록(`towerclimb`)을 일반 모드에서도 계속 올릴지, 스피드런 판의 높이만 인정할지는 선생님께 먼저 물어(★기본값: 두 모드 모두 지금처럼 높이 기록을 올림).

### 3. 구조(객체지향)

- 규칙 엔진(`42.climb-rules.ts`)에 모드 클래스를 둔다: 부모 `ClimbRunMode` ← `ClimbPracticeMode`(일반)·`ClimbSpeedrunMode`(스피드런). 모드가 정하는 것: 스테이지 포탈을 쓸 수 있는지, 시간이 언제부터 흐르는지, 구간 기록을 남기는지, 꼭대기 도착 때 무슨 이벤트를 내는지. `ClimbRules` 안에서 `if (speedrun)` 분기를 늘리지 말고 모드 객체에 맡긴다.
- 포탈 종류도 클래스로: `ClimbPortalSpec` 에 `kind`(`stage` / `speedrun`)를 더하고, 들어갔을 때 하는 일(스테이지 시작점으로 이동 / 모드 바꾸기)을 포탈 종류 클래스가 정한다. `StageProgress.portalOpen` 은 모드를 보고 판단.
- 새 이벤트: `speedrunStart`, `speedrunExit`, `split`(스테이지·시각), `speedrunFinish`(시간·구간·떨어진 횟수). 화면(`42.tower-climb.ts`)은 이벤트 처리 표에만 추가한다.
- 허브 배치(`TowerHubLayout`)에 스피드런 포탈 자리를 더한다. 스테이지 포탈(ρ 15, -50°~50°)·시작 지점(0, 10)·스테이지 1 첫 발판과 겹치지 않는 곳(예: ρ 15, 180°)을 고르고 `climb-reach.js` 의 "포탈 앞이 막히지 않음"·"허브 위" 검사에 스피드런 포탈도 넣는다.
- 화면: 포탈 그림(`PortalLooks`·`StagePortal`·`PortalHub`)은 스피드런 포탈용 색·판 글자(스피드런 ↔ 나가기)를 더하고, 스피드런 중에는 스테이지 포탈을 흑백으로. HUD 에 모드 표시("스피드런" 배지)와 큰 시계, 직전 구간 기록 알림(배너 "스테이지 3 · 2:41.3 (−4.2)"). 카운트다운 `warmUp` 에 새 포탈 그림도 한 번 그려 둔다.
- 시작 화면 기록 칸: 개인 최고 높이 / 스피드런 개인 최고 시간 / 우리 반·세계 스피드런 신기록 / 클리어한 스테이지. 규칙 칸에 스피드런 설명 한 줄(포탈 못 씀, 다시 타면 나가기, 떨어져도 시간은 계속).

### 4. 검사

- `tools/climb-unit.js` 에 추가: 스피드런 포탈에 닿은 틱부터 시간이 흐름 / 스피드런 중 스테이지 포탈에 닿아도 이동 안 함 / 스피드런 포탈을 다시 타면 일반 모드로 돌아오고 기록 이벤트 없음 / 떨어져서 허브로 와도 시간 계속 / 쉼터마다 `split` 한 번씩 / 꼭대기에서 `speedrunFinish` 한 번, 시간 = 들어간 틱부터 꼭대기 틱까지 / 일반 모드에서는 시간 기록 이벤트가 없음 / 같은 입력이면 같은 시간(슬로 써도 판 시간 기준은 같지만 기록은 실제 시간인지 판 시간인지 정하고 검사 — ★기본값: 기록은 실제 시간 `clock`, 슬로를 쓰면 그만큼 느려짐).
- `tools/climb-bot.js` 로 허브 → 스테이지 1~7 을 이어서 가는 스피드런 봇 한 판(`climb-reach.js` 에 "스피드런 봇 완주"와 걸린 시간 줄 추가).
- `npx tsc -p .`, `node tools/climb-unit.js`, `node tools/climb-reach.js -v`, `node tools/climb-sim.js 900 240 7` 모두 통과.
- 브라우저(`node tools/climb-test-page.js` → `.claude/climb-test.html`)에서: 스피드런 포탈 들어가기 → 시간이 바로 흐름 → 스테이지 포탈이 회색이고 안 들어가짐 → 포탈 다시 타서 나가기 → 다시 들어가 `__game.rules.body.place(...)` 로 꼭대기 근처로 옮겨 결과 화면·NEW·구간 기록 확인. 콘솔 오류 없음, 갤럭시탭 가로(1280×800)와 좁은 화면(640px)에서 HUD·결과 화면이 겹치지 않는지 사진으로 보고.
