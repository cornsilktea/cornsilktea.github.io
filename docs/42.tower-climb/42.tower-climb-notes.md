**에셋 밑면(2026-11-17 선생님 요청)**: KayKit 모델은 밑면이 없어 아래에서 보면 뚫려 보였다. 모델 재질을 모두 양면(`DoubleSide`, `ClimbModelLibrary.closedBelow`)으로 그려 아래에서도 막혀 보인다. 그림자는 전처럼 뒷면(`shadowSide = BackSide`)으로만 그려 그림자 얼룩이 생기지 않게 했다.

아직 안 만든 것: 결과 화면(꼭대기가 없어 1단계에서는 알림만), 배경 음악, 스테이지 7, 스테이지 3 의 움직이는 발판(사양서 표 — 엔진은 스테이지 6 에서 만들었으니 놓기만 하면 됨), 스테이지 6 얼음, 스테이지마다 하늘·안개 색 바꾸기, 전체 시간 세계 기록, 카메라 자동 정렬 끄기 버튼.

13절의 ★ 기본값(매달리기 자세 `Jump_Idle`, 1단계 기록은 최고 높이 + 기기 시간, 효과음만)은 **기본값대로** 만들었다. 슬로 게이지는 2026-11-17 선생님 요청으로 없앴다(누르는 동안 끝없이 슬로).

**움직이는 발판 규칙(2026-11-17)**
- 충돌 격자(`ClimbCollisionWorld`)에는 넣지 않고 따로 목록으로 둔다(`near` 가 가까운 것만 덧붙임).
- 매 틱 맨 앞에서 발판을 옮기고(`moveMovers`) 그 위에 **서 있거나 매달렸거나 기어오르는 중**이면 몸·잡은 곳·기어오르는 경로를 발판과 같이 옮기고 돌린다(`carry`, 발판 기준 좌표를 그대로 둠).
- **관성**: 움직이는 발판에서 떨어지는 순간(점프·걸어 나감·점프대 튕김) 발판의 수평 속도를 `body.driftX/Z` 로 싣고, 땅에 서거나 잡을 때까지 그대로 더해진다(공중 조종과 따로). 그래서 달리는 기차에서 제자리 점프하면 같은 칸에 다시 내려앉고, 움직이는 점프대는 목표 쪽으로 갈 때 밟아야 멀리 간다. 벽에 막히면 그 방향 관성은 없어진다.

- 고정 간격 1/120초. `advance` 가 실제 시간 × 슬로 배율을 모아 틱 단위로만 진행하므로 슬로를 써도 궤적이 같다(단위 검사로 확인). 화면은 `body.prevX…` 와 `rules.blend` 로 보간한다.
- 캐릭터는 세운 원기둥(반지름 0.4, 키 2.0)으로 계산한다. **서 있는지는 중심점이 발판 바닥 모양 안에 있는지**로 정한다(가장자리에서는 코요테 시간 0.12초가 돕는다). 옆면은 반지름만큼 밀어낸다. 0.35m 이하 턱은 그냥 올라선다.
- **잡기는 완전 자동**(2026-11-17 선생님 결정, `E`·잡기 버튼 없음): 공중에 있을 때 매 틱 이동이 끝난 뒤 `canAutoGrab` 이 잡을 곳을 찾는다. 서 있을 때는 잡지 않는다. 올라가는 중에는 지금 속도로 닿는 꼭대기(+`CLEAR_MARGIN` 0.15m)보다 높은 곳만 잡아 점프로 넘을 수 있는 발판은 그냥 올라선다. 벽 반대쪽으로 움직이는 중(`MANTLE_PUSH` 이상)이면 잡지 않는다. 손을 놓은 곳(`letGo`)은 땅에 닿을 때까지 다시 잡지 않는다. 매달린 채 벽 반대쪽(S·조이스틱 아래)으로 당기면 손을 놓는다.
- 잡기 범위(공중): 잡을 곳 높이가 발에서 0.9~2.8m, 수평 1.4m 안(`findFor`). `find`(서 있을 때 1.2~2.6m·1.0m)는 검사 도구만 쓴다. 공중 잡기는 캐릭터가 보는 방향(벽 바깥 방향과 각 cos ≥ 0.4) 안의 가장 가까운 곳을 먼저 잡고, 없으면 다른 방향의 가장 가까운 곳을 잡는다. 잡을 때 0.2초 `GRAB_SWING` 동안 화면이 위치를 따라가며 몸을 천천히 돌린다(`SWING_TURN_RATE`), 그동안 누른 점프는 남겨 둔다. 매달리면 발이 잡은 곳보다 2.0m 아래. 모서리는 **저절로 올라가지 않는다**(2026-11-17 선생님 요청): 매달리고 0.2초 지난 뒤 점프를 누르거나 벽 쪽으로 밀면(`MANTLE_PUSH`, W·조이스틱 위) 기어오른다(`climbUp` 상태 0.5초, `ClimbUpPath` 가 앞 60% 동안 윗면 +0.15m 까지 끌어올리고 나머지 동안 앞으로 넘어가 선다. 화면은 `Jump_Idle` → `Jump_Land` 와 앞으로 숙이기). 그 동안은 입력을 받지 않는다, 손잡이는 `Space` 로 위 손잡이(높이 차 0.2~1.6m, 수평 1.3m 안)로 옮긴다. 위에 없으면 손을 놓으며 점프한다.
- 최고 높이(`rules.peak`)는 **서 있거나 매달린 높이**만 센다(점프 중 높이는 안 셈).
- 스테이지 1 시간(`stageOneTime`)은 첫 입력부터 30m 쉼터까지 실제 시간, 포탈을 쓴 판은 기록하지 않는다.

## 4. 스테이지 1 배치 (`TowerStageOneLayout`)

가운데 큰 나무 줄기(반지름 3m, 높이 29.5m)를 돌며 오른다. 각도 a·반지름 ρ 로 놓는다(x = ρ·sin a, z = ρ·cos a).

| 높이 | 발판 | 내용 |
|---|---|---|
| 0 | `hub` | 반지름 22m 섬. 시작 지점 (0, 10), 포탈 6개는 ρ 15, a -50°~50° |
| 1~8.4 | `t1`~`t8` | (발판은 줄기·쉼터·손잡이·섬만 원, 나머지는 상자) 연속 점프 3회 → 좁은 통나무 `t4` → 쉼터 `t5` → 첫 모서리 잡기 `t6`(2.4m 위) → 쉼터 `t8` |
| 8.4 → 12 | `pad` → `mid` | 작은 점프대, 12m 쉼터(5×5) |
| 12 → 26.5 쉬운 길 | `c1`~`c13`, `join` | (2026-11-17 바꿈: 짧은 발판 28개 대신) 3.4m 큰 블록이 바깥 고리(ρ 7)를 한 바퀴 반 돈다. `CLIMB_PATH` 표 = [각도, 윗면]. 2.2~2.6m 높은 블록(벽, 점프하며 모서리 잡기)과 0.6~0.9m 간격의 평평한 점프가 섞임. 마지막 `join`(ρ 6.3) → `rest2` 는 3.5m 기어오르기 |
| 잡기 오르막 | `n0`, `h1`~`h4`, `n1` | 줄기의 손잡이 4개(간격 1.0m) → `n1` 에서 두 바퀴째 `c9` 로 걸어 합류(쉬운 길 8개를 건너뜀) |
| 30 | `rest2` | 줄기 꼭대기 쉼터(반지름 4.2m) = 스테이지 2 시작점. `join` 에서 기어올라 닿는다 |

봇 완주(실수 없음, 슬로 없음, 2026-11-17 배치): 쉬운 길 24.4초, 잡기 오르막 18.3초. 사람은 2~3배로 본다(기어오르기마다 매달림 → 오르기 입력이 필요). 길이를 늘리려면 `CLIMB_PATH` 에 [각도, 윗면] 을 더하고 `JOIN_DEG` 를 옮긴다. 둘째 길(잡기 오르막)이 쉬운 길보다 빨라야 한다(`climb-reach.js` 가 확인).

| ④ 승강 상자 ×2 → 도착 | `xe4`·`xp5`·`xe5` → `xq1` → `xw1` | ②와 같은 승강 상자 두 번(안쪽으로 들어오며 ρ 17 → 13.6), 180m 도착 상자(ρ 12)와 다리 |

- 높이: 역 154.2 → 승강 상자 5개가 4.58m 씩, 멀리뛰기 +2.3m 로 정확히 180m(`TowerStageSixLayout.gain`).
- 기차 높이는 스테이지 5 의 멀리뛰기 목표(`mq3`, 147.8m) 위에 선 학생의 머리(149.8m)보다 칸 밑면(150m)이 높게 골랐다. 움직이는 발판이 다른 발판·서 있는 머리 높이와 겹치는지는 `.claude/` 밖 임시 스크립트로 한 주기를 돌려 봤다(겹침 없음).
- 배경: ρ 33~36 에 눈 섬 6개(눈 블록 + 생강빵 집 + 눈사람 + 등 + 선물, `SNOW_ISLANDS`).
- 연속 점프는 3.1m 쉼 발판(`xt1`·`xp3`·`xg1`)에서 끊긴다.
- 봇 완주 36.4초. 시뮬레이션(`node tools/climb-sim.js 900 240 6`, 스테이지만 고르는 셋째 인자 추가)은 세 실력 모두 100%·36.4초로 같다 — 봇은 발판이 올 때를 계산해 기다리므로 조준이 흔들려도 놓치지 않고, 걸리는 시간도 발판 주기에 맞춰져 같아진다. **스테이지 6 의 어려움(뛰는 때 맞추기)은 이 시뮬레이션으로 잴 수 없다** — 학생 시험 플레이로 확인한다.

- **그림**: 발판은 Block Bits(`assets/kaykit/blocks/` 풀·흙·돌·나무·노란 줄무늬·빨강), 줄기와 쉼터는 `dungeon/barrel_large`, 포탈은 `dungeon/wall_doorway`, 허브 장식은 `forest/`. 발판 모양이 충돌 상자와 정확히 같도록 블록을 크기에 맞춰 늘린다(바위 모델은 윗면이 둥글어 쓰지 않음). 섬 바닥만 직접 만든 원기둥이다.

- 세계·우리 반 기록(`towerclimb`, 정수 m, 규칙 상한 200)은 추락·클리어·시작 화면으로 나갈 때 `WR.prompt` 로 올린다.
- 카운트다운 첫 프레임에 포탈을 컬러·흑백으로 한 번씩 그려 둔다(`ClimbWorldView.warmUp`).
- **화면 확인**: 등록 전이라 `?c=test` 도 잠겨 있다. `node tools/climb-test-page.js` → `http://localhost:포트/.claude/climb-test.html`. 콘솔의 `__game` 으로 `__game.rules.body.place(x, y, z)` 처럼 옮겨 볼 수 있다(다른 상태에서 옮기면 `body.mode = "free"` 도 같이).

## 6. 검사

```
npx tsc -p .
node tools/climb-unit.js      # 수치·잡기·점프대·슬로·포탈·추락 규칙
node tools/climb-reach.js -v  # 길마다 이웃 발판 분류와 점프 비율, 봇 완주, 발사대 없음, 갇힘
node tools/climb-sim.js 5000  # 실수하는 봇 5천 판(약 4분)
```
세 가지가 모두 통과해야 푸시한다. 발판을 옮기면 `climb-reach.js -v` 의 간격·비율 줄을 먼저 본다.

**움직이는 발판 검사(2026-11-17)**: `climb-reach.js` 는 움직이는 발판이 낀 이음을 한 주기 360칸으로 나눠 이어지는 순간 중 가장 쉬운 것을 고르고 `열린 시간`(이어지는 시간 비율, 5% 이상이어야 함)을 적는다. 움직이는 점프대는 튕길 때 실리는 관성까지 넣어 비율을 재고 `멈춘 점프대였다면` 비율을 같이 적는다. 길이 하나뿐인 스테이지(`hard*`)는 둘째 길 비교를 건너뛴다. 봇(`climb-bot.js` 의 `driveTimed`)은 움직이는 발판이 끼면 발판이 앞으로 있을 곳을 내다보고 관성을 빼서 조준하며, 될 때까지 가장자리(움직이는 칸에서는 칸 가운데)에서 기다린다. 기차처럼 같은 무리 칸이 여럿이면 가장 가까워질 칸을 고른다.
