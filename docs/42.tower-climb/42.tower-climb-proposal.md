# 42번 「동마 타워 클라임」 — 사양서 (v0.3, 2026-11-16)

「Only Up!」처럼 **끝없이 이어진 잡동사니 탑을 3인칭으로 뛰어 올라가는** 개인전 3D 플랫포머. "한 번 삐끗하면 처음까지 떨어진다 → 그래도 다시 간다"가 핵심이다.
선생님이 읽고 고친 뒤 확정한다. 그림은 **KayKit 3D 에셋**만 쓴다. 용어: 탑을 나눈 한 칸을 **스테이지**라 부른다(옛 "구간").

**표식**: **【조사】** 원작·장르 공통 규칙 / **【제안】** 이 게임에서 새로 넣는 것 / **【확인】** 선생님이 정할 값(기본값 ★). 수치는 모두 초기값이며 도달 검사(9절)와 시험 플레이로 확정한다.

## 바뀐 것 (v0.3, 2026-11-16 선생님 요청)

1. **사다리를 없앴다.** 올라가는 느낌은 **잡기(`E`)만으로** 만든다(손잡이를 이어 잡고 올라가는 "잡기 오르막", 6-3절).
2. **저장 시스템(체크포인트)을 없앴다.** 떨어졌는데 땅에 서지도, 잡지도 못하면 **계속 떨어져 맨 처음 시작 지점까지** 내려간다. 종료 직전이었어도 마찬가지다(5절). 모험·도전 모드 구분과 중간 깃발·`R`/`깃발로` 복귀·받침 발판은 모두 없앴다. **모드는 하나**(원작식).
3. **스테이지 포탈 6개**를 맨 처음 시작 지점에 둔다. 스테이지를 클리어하면 다음 스테이지 시작점으로 가는 포탈이 열린다(3-5절).
4. 구간 이름을 스테이지로 바꾸고, 만드는 순서(12절)와 확인 항목(13절)을 이에 맞게 고쳤다.

## 1. 원작 「Only Up!」 분석 【조사】

내가 아는 원작 기준이며 인터넷으로 다시 확인하지는 못했다.

| 요소 | 원작의 모습 |
|---|---|
| 시점·조작 | 3인칭. `WASD` 이동, `Space` 점프, `Shift` 달리기, 마우스 카메라. 전투·아이템 없음 |
| 구조 | 서로 어울리지 않는 현실 물건을 쌓은 **거대한 탑**. 길이 여러 갈래 |

**결론**: 이 게임의 추락 규칙은 원작과 같다(저장 없음). 대신 수업 시간을 위해 **스테이지 클리어 포탈**로 이미 깬 스테이지의 시작점으로 빨리 돌아갈 수 있다(3-5절).

## 2. 조작

### 2-1. 키보드 (PC)
| 입력 | 동작 |
|---|---|
| `W A S D` / 방향키 | 이동(카메라 방향 기준, **항상 달리기**). 방향키는 `e.key`, WASD 는 `e.code`(한글 IME 대비) |
| 마우스 이동 | 카메라 회전(포인터 잠금, `Esc` 로 풀기). 잠금이 안 되면 드래그 |
| `Space` | 점프. 발사대 위에서는 **발사**. 매달린 동안에는 **위의 다음 손잡이로 뛰기** |
| `E` | 손잡이·모서리 **잡기**, 매달린 상태에서 **놓기** |
| `Shift`(누르는 동안) | **슬로 모션**(6-6절) |
| `Esc` | 일시정지(메뉴·조작 설명·나가기) |

### 2-2. 터치 (갤럭시탭 S7 FE 가로)
| 입력 | 동작 |
|---|---|
| 왼쪽 가상 조이스틱 | 이동. **거리와 상관없이 그 방향의 최고 속도**, 가운데 무감 구역 안에서만 멈춤 |
| 오른쪽 화면 드래그 | 카메라 회전 |
| 오른쪽 아래 `점프` 큰 버튼 | 점프(허공에서 누르면 점프 예약). 발사대 위에서는 발사. 매달린 동안은 다음 손잡이로 뛰기 |
| `점프` 위쪽 작은 `슬로` 버튼 | **누르고 있는 동안만** 슬로 모션 |
| `슬로` 위쪽 작은 `잡기` 버튼 | 잡기·놓기. 잡을 수 있는 곳 근처에서만 나타남 |

- 걷기가 없으므로 좁은 발판에서는 조이스틱·키를 놓아 멈춘다(0.05초 안에 멈추는 짧은 감속). 좁은 발판 앞에는 "멈춤 쉼터"를 둔다(4절). 정밀한 곳은 슬로 모션이 돕는다.
- 캔버스는 `touch-action:none`. 고정 HUD 는 `← 목록으로` 버튼 때문에 46px 아래로.

## 3. 게임 구조

### 3-1. 장면 흐름
```
시작 화면 → 카운트다운 3·2·1 → 처음 시작 지점(허브)에서 플레이 ⇄ 일시정지
        ├ 올라가다 스테이지 시작 쉼터에 닿음 → 클리어 알림, 다음 포탈 열림
        ├ 추락 → 계속 떨어져 처음 시작 지점에 도착 → (포탈로 돌아가거나 다시 오르기)
        ├ 포탈에 들어감 → 잠시 뒤 해당 스테이지 시작점으로 이동
        └ 마지막(꼭대기) 깃발 → 결과 화면(기록 갱신 NEW) → 다시 하기/목록으로
```

### 3-2. 탑의 구조 【제안】
- 최종 탑은 **7개 스테이지**, 한 스테이지는 약 30m. **스테이지 k 를 클리어한다 = 스테이지 k+1 의 시작 쉼터에 닿는다.** 쉼터에는 그 스테이지의 깃발이 있어(저장 기능 없음, 표지·알림용) 닿으면 "스테이지 k 클리어!"를 띄운다.
- 한 스테이지 안에 **경로 3갈래**: ① 쉬운 길(길고 안전), ② 보통 길(짧음), ③ 어려운 길(가장 짧고 위험, **발사대**가 숨어 있다). 갈래는 위에서 합쳐진다.
- 스테이지마다 다른 에셋 팩으로 꾸미고 물건을 **크게(×3~×8) 확대해 쌓아** "안 어울리는 물건이 쌓인" 맛을 낸다.

| 스테이지 | 높이 | 테마 | 주 에셋 팩 | 처음 나오는 요소 |
|---|---|---|---|---|
| **1 뿌리 숲** (1단계) | 0~30 | 숲 바닥, 쓰러진 나무·바위 | Forest Nature(`Tree_*`·`Rock_*`), Block Bits | 고정·좁은 발판, 경사, **잡기·잡기 오르막**, **작은 점프대**, **발사대**, 슬로 모션 |
| 2 폐허 마을 | 30~60 | 무너진 성벽·지붕 | Medieval Hexagon, Medieval Builder | 긴 잡기 오르막(벽 손잡이) |
| 3 지하 던전 | 60~90 | 계단·기둥·술통·상자 | Dungeon Pack | 움직이는 발판, 연쇄 발사대 |
| 4 거인의 주방 | 90~120 | 거대한 식탁·상자 | Restaurant Bits, Furniture Bits | 무너지는 발판 |
| 5 묘지 | 120~150 | 호박·울타리·유령집 | Halloween Bits, Mixed Bag 2 | 도는 막대 |
| 6 눈 덮인 장난감 마을 | 150~180 | 선물 상자·눈 덮인 나무 | Holiday Bits | 미끄러운 얼음, 큰 발사대 |
| 7 우주 기지 | 180~200 | 패널·타워·안테나, 꼭대기 | Space Base Bits, Prototype Bits | 바람, 최종 깃발 |

- 모델 파일명·크기는 만들 때 `node tools/kaykit-find.js 단어` 로 확인하고 `assets/kaykit/` 에 없는 것만 `organized` 에서 복사한다.
- **맨 아래는 진짜 땅**이다: 탑 아래에 넓은 둥근 섬(허브, 3-5절)이 있고 바깥은 안개·구름. 허브 가장자리 밖으로 나가 높이 -20m 밑으로 떨어지면 허브 가운데로 되돌려 보낸다.

### 3-3. 장애물·발판 목록 【제안】
| 종류 | 설명 | 판정 |
|---|---|---|
| 고정 발판 | 통나무·바위·술통·상자·기둥 머리·`Primitive_*` | 윗면에 선다 |
| 좁은 발판 | 폭 0.6~1.0 (쓰러진 나무·기둥·`Primitive_Beam`) | 정밀 점프 |
| 경사·미끄러운 면 | 지붕·`Primitive_Slope`·얼음, 서 있으면 미끄러짐 | 경사 > 40°(얼음 12°) |
| **손잡이·모서리(잡기)** | 발판 가장자리 모서리, 벽에서 튀어나온 바위·가지·빔. `E` 로 잡고 올라타거나, 매달린 채 `Space` 로 다음 손잡이로 뛴다 | 잡기 영역 |
| **작은 점프대** | 밟으면 위로 튕김(위 속도 15 m/s, 높이 약 4m = 일반 점프의 2.5배). 착지 쉼터가 넓고 보임 → 안전한 보너스 | 위로 튕김 |
| **발사대(대포)** | **하이리스크·하이리턴**: 올라서면 충전되고 `Space` 로 발사, 한 번에 **+12m 이상**을 건너뛰는 지름길(6-7절) | 발사 |
| 움직이는 발판 | 일정 경로로 오가는 판. 서 있으면 같이 움직임 | 발판 속도 더함 |
| 무너지는 발판 | 밟고 0.8초 뒤 흔들리다 떨어지고 3초 뒤 복구 | 타이머 |
| 도는 막대 | 회전 빔, 닿으면 튕겨 나감(피해 없음) | 밀기 |
| 바람 | 가로로 미는 구역 | 힘 +x |
| 스테이지 깃발 | 스테이지 시작 쉼터마다 하나. 닿으면 클리어 표시(저장 지점 아님) | 닿기 |

**원칙**: 한 번에 새 장애물 **하나**씩, 쉬운 형태로 먼저 보여 준 뒤 어려운 형태를 낸다. 사다리는 없다.

### 3-4. 스테이지 1 설계(1단계 범위) 【제안】
| 높이 | 내용 |
|---|---|
| 0m | **허브**(처음 시작 지점): 넓은 둥근 풀 섬, 모닥불 장식, **스테이지 포탈 6개**(3-5절), 탑 입구 |
| 0~8m | 튜토리얼: 고정 발판(바위·그루터기) 연속 점프 3회 → 쓰러진 통나무(좁은 발판) 1개 → 쉼터. 첫 **잡기**(낮은 모서리, 떨어져도 허브에 바로 닿는 높이) |
| 8~12m | 첫 **작은 점프대**(통나무 사이, 넓은 착지판) |
| 12m | 중간 쉼터(저장 기능 없음, 길을 보며 쉬는 곳) |
| 12~26m | 3갈래 ① 쉬운 길: 바위 계단 + 나무 위 발판(연속 점프 ≤ 4회, 아래에 발판이 많아 실수해도 걸림) ② 보통 길: **잡기 오르막**(벽처럼 서 있는 큰 바위의 튀어나온 손잡이 4~5개를 `E`+`Space` 로 이어 오름) + 경사 바위 1곳 ③ 어려운 길: 좁은 통나무 2개 + 최대 간격 0.9 점프 1회 → **발사대**(14m 높이) |
| 발사대 | 14m → 26m 높이의 작은 착지 발판(3m×3m)으로 발사. 일반 경로 약 50초 → 약 3초. **실패하면 바깥으로 떨어져 허브까지 추락** |
| 26~30m | 짧은 오르막 → **30m 쉼터 + 스테이지 깃발**. 닿으면 "스테이지 1 클리어! 포탈 2가 열렸어요" |
- 1단계에서 30m 쉼터는 "스테이지 2 시작점"이기도 하다(스테이지 2~7은 공사 중이라 그 위는 막혀 있다).
- 소요 목표: 숙련 80초, 처음 하는 학생 3~4분. 슬로 모션은 좁은 통나무·손잡이 오르막·발사대 조준에서 가장 유용하도록 배치한다.

### 3-5. 허브와 스테이지 포탈 【제안】
- **위치**: 맨 처음 시작 지점(스테이지 1 시작점, 높이 0m)의 넓은 풀 섬. 탑 입구 앞에 반원으로 **포탈 6개**를 세운다. 추락하면 이곳으로 떨어진다.
- **의미**: 포탈 `n`(n = 2~7) = **스테이지 n 시작점**으로 가는 문. **스테이지 n-1 을 클리어하면 열린다**(최고로 클리어한 스테이지의 다음 포탈뿐 아니라 그 앞의 모든 포탈이 열려 있다).
- **모양**: 문 모양 아치(Dungeon Pack 아치·`wall_doorway` 계열 또는 `Primitive_Doorway`, 파일은 `kaykit-find.js doorway arch` 로 확정) 안쪽에 소용돌이 판. 머리 위에 **스테이지 숫자**(2~7)를 크게 붙인다(숫자판은 캔버스로 미리 그려 둔 글자 텍스처).
  - **잠긴 포탈(미클리어)**: **흑백**(채도 0 재질, 소용돌이 정지, 숫자도 회색). 가까이 가면 "스테이지 n-1 을 클리어하면 열려요" 한 줄.
  - **열린 포탈**: **컬러**(스테이지 테마 색, 소용돌이 회전, 빛은 `MeshBasicMaterial`).
- **들어가기**: 열린 포탈 안(반경 1.2m)에 들어가면 입력이 잠기고 캐릭터가 빨려 들어가며 화면이 하얗게 번진다(약 1.5초, `opacity` 전환). **잠시 뒤 해당 스테이지 시작 쉼터 가운데에 `Spawn_Air`/`Spawn_Ground` 로 나타난다.** 포탈은 한 번 쓴 뒤 다시 쓸 수 있다.
- **클리어 알림**: 스테이지 깃발에 닿는 순간 "스테이지 k 클리어!" 알림 + 허브 포탈 k+1 이 컬러로 바뀐다(허브에 있지 않아도 상태는 바뀜). 슬로 게이지는 스테이지 시작 쉼터에 닿거나 허브에 있을 때 가득 찬다.
- **1단계**: 포탈 6개를 모두 만든다. 스테이지 2 포탈(시작점 = 30m 쉼터)만 실제로 작동하고, 포탈 3~7은 스테이지가 없어 **흑백 + "공사 중"**. 스테이지가 추가될 때마다 해당 포탈이 켜진다(2단계).
- **저장**: 클리어한 스테이지 번호는 기록처럼 기기·계정에 저장해 다음 접속에도 포탈이 열려 있다 ★ 【확인】. 체크포인트 저장은 없다.
- **높이 기록·시간 기록**: 포탈로 간 곳은 이미 도달한 곳이라 최고 높이에는 영향이 없다. 7스테이지 전체 클리어 시간 기록은 **포탈을 한 번도 쓰지 않은 판만** 인정한다(후속 단계, 8절).

## 4. 레벨 설계 규칙 【제안】

1. **연속 점프는 5회까지**, 그다음에 안전 쉼터(한 변 3m 이상). 쉼터에서는 멈춰서 카메라로 길을 볼 수 있다.
2. **보이게 만든다**: 다음 발판이 화면 안에 들어오도록 카메라 거리·각도를 조정. 눈에 띄는 색의 표지(`MeshBasicMaterial`).
3. **실수의 대가는 크지만 불공정하지 않게**: 저장이 없으므로
   - 쉬운 길은 아래에 발판이 많아 실수해도 아래 발판에 걸리게 한다(자연스러운 안전망, 길을 알려 주는 효과).
   - 어려운 길·발사대 주변은 **열려 있어** 걸리지 않고 허브까지 떨어진다(하이리스크).
   - 다시 올라오는 시간은 포탈이 줄여 준다(스테이지 시작점으로 바로).
4. **난이도 곡선**: 스테이지 1은 최대 점프 거리의 60% 이내(어려운 길만 0.9), 스테이지 7은 90%. 어떤 점프도 95% 를 넘지 않는다(9절).
5. **스테이지마다 분위기가 바뀐다**: 하늘색·안개 색·반구광 색.
6. **발사대 규칙(하이리스크·하이리턴)**:
   - 반드시 **어려운 길 ③** 위에 둔다(접근부터 위험). 쉬운 길만으로도 항상 완주 가능해야 한다.
   - 얻는 것: 한 번에 +12m 이상(스테이지의 40% 이상), 시간 40~60초 단축.
   - 잃는 것: 놓치면 **허브까지 추락**(스테이지 1 이후에는 포탈이 있어도 쉼터에서 다시). 착지 발판은 작게(3m×3m), 주변에 받침 없음.
   - 발사 경로는 밝은 점선(표지)으로 "도전할 만하다"고 알려 준다.
7. **잡기 오르막 규칙**: 손잡이 사이 수직 간격 ≤ 1.6m(점프 1회로 닿음), 4~6개 연속, 끝에는 쉼터. 매달린 곳 근처에는 항상 **놓았을 때 떨어질 자리**가 보이게(위험 표시).

## 5. 추락 규칙 【확정】

- **저장 시스템이 없다.** 깃발·체크포인트·되돌아가기 키·받침 발판(그물)·모드 구분이 없다.
- 땅이나 발판에 **서거나**, 모서리·손잡이를 **잡지** 못하면 계속 떨어진다. 중간 발판에 서면 거기서 계속 간다(아래 발판에 걸리면 걸린 곳에서 이어 감 — 원작과 같음).
- 아무것에도 걸리지 않고 **맨 아래까지 떨어지면 처음 시작 지점(허브)에 도착**한다. **스테이지 7 꼭대기 직전이었어도 마찬가지다.**
- 도착하면 `Hit_A` 쓰러짐·일어나기 후 바로 플레이. 화면에는 `떨어졌어요! 처음으로` 한 줄만(소리·시야 흐림 없음, 멀미 방지).
- 낙하 속도 상한 35m/s. 슬로 모션은 추락 중에도 쓸 수 있지만 낙하 시간만 길어질 뿐이다.
- 되돌아가기 방법: 올라간 적이 있는 스테이지는 **허브의 포탈**로 그 스테이지 시작점까지 바로 간다(3-5절).

## 6. 캐릭터·물리

### 6-1. 움직임 (월드 단위 = KayKit 미터, 캐릭터 키 ≈ 2.2)
| 값 | 초기값 | 비고 |
|---|---|---|
| **이동 속도** | **7 m/s 한 가지** | 키보드·터치 동일, 항상 달리기 |
| 가속 | 지상 40, 공중 12 m/s² | 공중 조종 가능. 입력 없을 때 지상 정지 0.05초 |
| 중력 | 28 m/s² | |
| 점프 속도 | 9.5 m/s | 높이 1.61m, 체공 0.68초 |
| 점프 수평 거리 | 약 4.75m (평지) | **설계 최대 간격 = 이 값의 0.9** |
| 코요테 시간 | 0.12초 | 가장자리를 벗어난 직후 점프 가능 |
| 점프 예약 | 0.15초 | 착지 직전 누른 점프를 착지 때 실행 |
| 낙하 상한 속도 | 35 m/s | |
| 경사 한계 | 40° 넘으면 미끄러짐 | 얼음 12° |
| 작은 점프대 위 속도 | 15 m/s | 높이 약 4m |
| 발사대 | 6-7절 | |

점프 높이는 고정(누른 시간과 무관) — 터치 학생이 불리하지 않게. 정밀함은 공중 조종과 슬로 모션으로 만든다.

### 6-2. 충돌 방식 【제안】
- **물리 엔진을 쓰지 않는다.** 캐릭터는 세운 캡슐(반지름 0.4, 높이 2.0), 월드는 **AABB·회전 상자·경사면** 목록. 이유: 갤럭시탭 성능, 결과가 늘 같아 검사 가능.
- 충돌 상자는 모델 크기에서 자동 생성(`Box3`)하고 필요하면 손으로 줄인다(잎·장식은 충돌 없음).
- 고정 시간 간격(1/120초) 갱신 + 그리기 보간. 프레임이 느려도 점프 거리가 같다. 슬로 모션은 이 간격에 곱하는 배율이라 **궤적이 같다**(6-6).
- 격자 분할: 스테이지 × 4m 셀에 상자를 넣고 캐릭터 근처 셀만 검사.

### 6-3. 잡기(매달려 올라가기) 【제안】 — 사다리 대신
- **잡을 수 있는 것**: ① **모서리**(발판 윗면 가장자리), ② **손잡이**(큰 바위 벽·나무 줄기·벽에서 튀어나온 빔·가지). 모두 모델 크기에서 만든 "잡기 영역"으로 표시하고, 가까이 가면 `잡기` 표지(작은 손 그림)가 떠오른다.
- **잡는 법**: 손잡이가 캐릭터 가슴~머리 위 약 1m 안에 있을 때 `E`(터치는 `잡기` 버튼). 점프 중에도 잡을 수 있다.
- **매달린 동안**:
  - 모서리를 잡았고 위에 설 자리가 있으면 0.4초 뒤 **자동으로 올라탄다**.
  - 손잡이는 계속 매달려 있다. `Space`(점프) = **위쪽의 다음 손잡이로 뛰어 오른다**(잡을 수 있는 거리 안에 있으면 자동으로 잡음). 이것을 이어 가면 사다리처럼 오르는 느낌이 난다.
  - 좌우로는 손잡이 간격만큼 `A`·`D` 로 살짝 옮겨 잡을 수 있다(0.3초 쿨다운).
  - `E` 를 다시 누르면 놓고 떨어진다(실수로 놓았다면 떨어지는 중에 다시 `E` 로 아래 손잡이를 잡을 수도 있다).
  - 매달린 동안 슬로 모션 사용 가능, **매달림에는 시간 제한이 없다**.
- 애니메이션: Rig_Medium 에는 매달리기 전용 클립이 없다 → ★`Jump_Idle` 포즈를 매달린 자세로 쓰고, 뛰어 오를 때 `Jump_Start`. 안 어울리면 이 장면만 `PrototypePete`(`Climbing` 클립). 만들기 전 `kaykit-find.js climb` 로 다시 확인.

### 6-4. 카메라
- 3인칭 궤도: 거리 6m(조절 4~9), 위 15°. 마우스·오른쪽 드래그로 회전.
- **벽 뚫림 방지**: 캐릭터→카메라 광선이 충돌 상자에 닿으면 거기까지 당긴다.
- 달릴 때 카메라가 진행 방향으로 천천히 따라 돈다(켜고 끄기 가능). 추락 중에는 낙하 방향이 보이게 위쪽 5° 올림.
- 슬로 모션 중에도 **카메라 회전은 실시간**이다.

### 6-5. 애니메이션 (KayKit `Rig_Medium`, 이름은 만들기 전 도감으로 확정)
- `Idle_A`, `Running_A`(걷기 클립은 쓰지 않음), `Jump_Start`·`Jump_Idle`·`Jump_Land`, 허브 도착 `Hit_A`, 포탈 도착 `Spawn_Air`, 완주 `Cheering`(Simulation).
- 모델: `CharacterModelFactory`(공용), 닉네임·외형은 `portal_profile_v1` 한 곳.

### 6-6. 슬로 모션 【확정: 누르는 동안만】
`Shift`(터치는 `슬로` 버튼)를 **누르고 있는 동안** 게임 시간이 느려진다.

| 항목 | 값 |
|---|---|
| 배율 | **0.3배**(이동·점프·낙하·움직이는·무너지는 발판·애니메이션·이펙트 모두). 켜고 끌 때 0.15초에 걸쳐 부드럽게 전환 |
| 안 느려지는 것 | **카메라 회전·HUD·입력**, 기록 시간(실제 시간) |
| 게이지 | ★**4초치**. 누르는 동안 1/s 감소, 누르지 않으면 0.5/s 회복(전부 차는 데 8초). **허브와 스테이지 시작 쉼터에서 즉시 가득**. 비면 자동으로 풀리고 0.5초 쿨다운 |
| 화면 | 가장자리에 푸른 안개빛 비네트(`opacity` 만), 효과음 재생 속도 0.6배 |
| 규칙 | 시간 기록은 실제 시간이라 **슬로를 써도 빨라지지 않고 정밀해지기만** 한다. 도달 검사(9절)는 슬로 없이 통과해야 한다(슬로는 보조) |

### 6-7. 점프대·발사대 【제안】
**작은 점프대**: 밟으면 위 속도 15 m/s. 공중에서 방향 조종 가능. 착지 쉼터가 넓고 보이게(4절).

**발사대(대포 모양, 통나무 위에 올린 큰 술통 `barrel_large` 형태)** — 하이리스크·하이리턴
1. 위에 올라서면 **충전**이 시작된다(막대·빛이 차오름, 0.8초에 100%).
2. `Space`(터치는 `점프`)를 누르면 발사. **너무 일찍 눌러도 최소 60% 힘**, 자동 발사는 0.8초 뒤 100%.
3. **힘 = 충전량**. 같은 대포에서 가까운 발판(60~80%)과 먼 발판(100%)을 노릴 수 있다 — 힘 고르기가 숙련도 차이.
4. 발사 방향은 대포 방향 고정(수직 속도 27 m/s, 수평 6.5~9 m/s, +12m 위 / 앞쪽 8m 지점이 기본 목표). 비행 중에는 **공중 조종 50%** 로 조정하고, 슬로 모션을 쓸 수 있다.
5. **비행 중 `E` 로 착지 발판의 모서리를 잡아 살릴 수 있다** — 한 뼘 모자랄 때의 구원. 잡지 못하고 착지 발판에도 서지 못하면 **계속 떨어져 허브까지**(5절).
6. 착지 발판이 작고(3m×3m) 놓치면 허브까지 추락 → **리스크 = 지금까지 번 시간**, **리턴 = 40~60초 단축**.
7. 발사 궤적 점선과 목표 지점 표지는 항상 보인다. 접근하는 어려운 길을 못 넘으면 발사대에 닿지도 못한다.
8. 도달 검사(9절)가 **모든 힘에서의 궤적**을 확인한다.

## 7. 화면 구성

### 7-1. 시작 화면 (30·31번 모양, `common/theme.css` `st-*`)
**제목**(`동마 타워 클라임`, 부제 없음) → **실행**(`시작` 한 개) → **기록**(`.st-recs`: 개인·우리 반·세계 최고 높이 + `WR.who()`, 클리어한 스테이지 `n / 7`) → **조작 방법**(`.st-keys`+`kbd`, 키보드·터치 접이식 `FoldCard`) → **규칙**(`.st-rules`: 떨어지면 처음으로, 포탈, 잡기, 점프대·발사대, 슬로 모션).
- 캐릭터 만들기(`data-maker-open`)·닉네임은 접힌 카드. 색은 `--st-*` 만 바꿔 하늘색 분위기, 강조 `#D97B4F`.
- **3D 배경**(`TowerMenuBackdrop`): 허브와 탑이 서서히 돌고, 캐릭터가 포탈 앞에서 `Idle_A`·`Cheering` 을 번갈아 한다. 판이 시작되면 치운다.
- 실행 카드 세로 간격은 10px. 이모지는 오래된 윈도우에서 깨지지 않는 것만.

### 7-2. 플레이 HUD (30번 틀, 어두운 반투명 `.hud-box`·주황 강조선)
- **위쪽 가운데**: 현재 높이 `14m`(크게) + 스테이지 이름 + 진행 막대.
- **왼쪽 위**(46px 아래): 경과 시간, 최고 기록.
- **오른쪽 위**: 탑 모양 미니 지도(스테이지 7칸, 내 위치 점, **클리어한 칸 표시**, 공사 중 칸은 회색).
- **오른쪽 아래**: **슬로 게이지**(작은 막대, 비었을 때 깜빡임). 터치 버튼은 2-2 위치.
- 방이 없어 방 코드는 없다. HUD 는 `transform`·`opacity` 만으로 움직인다. 글자는 카운트다운에 한 번 그려 둔다.

### 7-3. 결과 화면
꼭대기 도착 시: 높이·시간·**떨어진 횟수(처음으로 간 횟수)**·**고른 길**·발사대 성공/실패·포탈 사용 횟수. 기록 갱신은 `NEW`. 학생 순위표는 두지 않는다. `다시 하기`·`목록으로`. 1단계에서는 스테이지 1 클리어 화면 대신 알림만 띄우고 계속 플레이할 수 있다(포탈로 허브에서 다시도 가능).

## 8. 기록·계정

- **최고 높이**(키 `towerclimb`): `WorldRecord("towerclimb", {format: m})`. 기기 기록 `towerclimb_best_v1`(try/catch)을 시작 화면·HUD·결과 세 곳에 표시, 갱신 시 `NEW`. 계정 동기화 `syncBest`(+신기록 시 `pushBest`).
- **클리어한 스테이지**: `towerclimb_cleared_v1`(숫자, 클수록 좋음)를 기기·계정에 저장해 포탈 상태로 쓴다. `WorldRecord.syncBest` 의 `merge: betterOf`(큰 값) 사용 ★ 【확인】.
- **클리어 시간**: 1단계에서는 **기기 기록만**(`towerclimb_z1time_v1`, 허브에서 처음 출발한 뒤 스테이지 1 클리어까지, 추락해도 시계는 계속 간다). 세계 시간 기록(`towerclimbtime`, `lower:true`)은 7스테이지를 모두 만든 뒤 **포탈 없이 한 번에 클리어한 판만** 대상으로 도입한다.
- `데이터베이스규칙.json` 에 점수 상한 한 줄(높이 ≤ 200). 선생님이 콘솔에 다시 게시한다.
- 조작 방지(2차): 기록 제출 때 스테이지 통과 순서 해시를 같이 저장해 이상값 걸러내기에 쓸 수 있게만 열어 둔다.

## 9. 검사 (화면 없는 규칙 코드 + 도달 검사)

- 규칙 엔진 `ts/games/42.tower-climb/42.climb-rules.ts` 는 **화면을 모른다**: 캡슐·충돌 상자·이동·점프·잡기·점프대·발사대·이동 발판·시간 배율, 그리고 **스테이지 진행 규칙**(클리어 → 포탈 열림, 추락 도착 처리)만 계산한다. 같은 입력이면 항상 같은 결과.
- `node tools/climb-unit.js`: 점프 높이·거리·코요테·점프 예약·경사 미끄러짐·**잡기·손잡이 이어 오르기(간격 한계)**·작은 점프대(높이 4m)·발사대 힘별 궤적·슬로 배율에서 같은 입력 → 같은 궤적·**포탈 규칙(스테이지 n-1 클리어 → 포탈 n 열림, 클리어 안 한 포탈은 잠김)**·**추락이 허브에서 끝나는지**.
- **`node tools/climb-reach.js` — 도달 검사(가장 중요)**:
  - 허브부터 각 스테이지 시작 쉼터까지 **슬로 없이** 가는 **쉬운 길**이 최소 1개 있다(연속 점프 5회 이하).
  - 모든 점프의 필요 거리 ≤ 최대 거리의 0.9(스테이지별 상한 4절 4항, 95% 초과 금지). 손잡이 오르막의 수직 간격 ≤ 1.6m.
  - 발사대: 100% 힘 궤적이 목표 착지 발판 안에 들어가고, 다른 힘 단계의 결과가 정의돼 있으며(착지 또는 낙하), 접근하는 어려운 길이 도달 가능.
  - 움직이는·무너지는 발판은 주기 전체를 돌려 검사.
  - **막다른 길 검사**: 어떤 발판에서도 올라갈 길이 없는 곳(올라갈 수도 내려갈 수도 없이 갇힘)이 없는지 확인. 갇힘 방지를 위해 허브까지 떨어질 수 있는 길이 항상 있다.
- `node tools/climb-sim.js`: 간단 행동 규칙으로 5천 번 시뮬레이션해 스테이지 도착 비율·평균 시간 보고.
- 모두 통과해야 푸시한다. 푸시 뒤에는 사이트 파일 일치까지 확인하고 보고한다.

## 10. 성능 (3D 성능 지침, 기준 SM-T733 터치 60fps)

- **스테이지 단위 그리기**: 탑을 30m 스테이지로 나눠 **현재 스테이지 ±1** 만 장면에 둔다(셰이더 재컴파일 없이 붙이고 떼기). 허브는 항상 둔다. **포탈 이동은 도착 스테이지를 미리 붙여 한 번 그려 본 뒤(페이드 1.5초 동안) 이동**한다.
- **InstancedMesh**: 같은 모델은 스테이지·셀로 나눠 인스턴싱, `frustumCulled` 켬.
- **포탈**: 소용돌이 판 6개는 단순 평면, 컬러 재질과 흑백 재질 한 벌씩을 **카운트다운에 한 번씩 그려 둔다**(재질 교체가 게임 중 셰이더 재컴파일로 이어지지 않게). 흑백 재질은 원본 텍스처를 캔버스로 한 번 채도 0 으로 만든 복사본을 쓴다. 숫자판 글자는 미리 그린 텍스처.
- **그림자**: 캐릭터 주변 한 영역만, 해상도 1024. **조명**: 방향광 1 + 반구광 1, 점·스포트 없음. 빛나는 표지는 `MeshBasicMaterial`.
- **화질 자동 조절** `QualityGovernor`(배율 0.25씩 1.0까지 → 블룸 끄기 → 그림자 줄이기). 터치 배율 상한 1.25~1.5. 단계·저장 키는 24·31번.
- 게임 중 `clone`·`new` 금지(풀링). 텍스처 2048px 이하. 그리기는 `requestAnimationFrame`. `&fps` 로 확인.

## 12. 만드는 순서 (두 단계)

### 1단계 — 스테이지 1 + 허브·포탈 완성 + 사이트 업로드
1. 이 사양서 확정(13절 답).
2. 규칙 엔진 + `climb-unit.js` 통과(이동 7 m/s·점프·잡기·점프대·발사대·슬로·포탈 규칙·추락 규칙 수치 확정).
3. 허브(포탈 6개, 포탈 2만 작동)와 스테이지 1 레벨 데이터(3-4·3-5절)와 `climb-reach.js`·`climb-sim.js` 통과.
4. 화면: 조작(키보드·터치), 카메라, 캐릭터·애니메이션, HUD(슬로 게이지·미니 지도), 시작·결과 화면, 3D 배경, 효과음, 기록·계정, 클리어 단계 저장.
5. 갤럭시탭(`?c=test`) 터치 60fps 측정(제어판 렉 진단 `SM-T733`) 후 화질 단계 조정.
6. **등록**: `초기데이터.json` 에 `towerclimb` 추가(title·url·memo·order·open·units·unitsSet), `pwsh ./링크제목맞추기.ps1`, `데이터베이스규칙.json` 점수 상한 한 줄, `.ts` 와 컴파일 `.js` 같이 커밋·푸시, 사이트 파일 일치 확인. 학생에게는 선생님이 제어판에서 반별로 연다.
- **1단계 완료 기준**: ① 도달 검사·단위 검사 통과 ② 허브에서 스테이지 1을 쉬운 길·잡기 오르막·발사대 세 방법으로 직접 클리어 ③ 클리어 뒤 **포탈 2가 컬러로 바뀌고** 들어가면 30m 쉼터로 이동, 일부러 떨어져 허브로 돌아오기도 확인 ④ 터치 한 상태로 60fps 근처 ⑤ 콘솔 오류 없음(404 포함) ⑥ 기록·클리어 단계 저장·표시 확인 ⑦ 배포 확인.

### 2단계 — 스테이지 2~7 추가 (스테이지마다 반복)
순서 2→7. 각 스테이지: 새 요소 클래스(3-2 표 "처음 나오는 요소") → 스테이지 데이터 → 해당 포탈 켜기 → `climb-reach.js` 통과 → 터치 성능 확인 → 커밋·푸시·배포 확인. 스테이지 7 이후: **전체 클리어 시간 기록(`towerclimbtime`) 도입**.
