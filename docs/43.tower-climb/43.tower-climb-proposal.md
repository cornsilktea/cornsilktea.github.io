# 43번 「동마 타워 클라임」 — 사양서 초안 (v0.1, 2026-11-16)

「Only Up!」처럼 **끝없이 이어진 잡동사니 탑을 3인칭으로 뛰어 올라가는** 개인전 3D 플랫포머. "한 번 삐끗하면 한참 떨어진다 → 그래도 다시 간다"가 핵심이다.
선생님이 읽고 고친 뒤 확정한다. 확정 전에는 코드를 만들지 않는다. 그림은 **KayKit 3D 에셋**만 쓴다.

**표식**: **【조사】** 원작·장르 공통 규칙 / **【제안】** 이 게임에서 새로 넣는 것 / **【확인】** 선생님이 정할 값(기본값 ★). 수치는 모두 초기값이며 도달 검사(9절)와 시험 플레이로 확정한다.

## 1. 원작 「Only Up!」 분석 【조사】

내가 아는 원작 기준이며 인터넷으로 다시 확인하지는 못했다. 어긋나는 점은 선생님이 고쳐 주세요.

| 요소 | 원작의 모습 |
|---|---|
| 시점 | 3인칭, 마우스로 카메라 회전 |
| 조작 | 이동 `WASD`, 점프 `Space`, 달리기 `Shift`, 카메라 마우스. 전투·아이템 없음 |
| 구조 | 공원·건물·공사장 소품 등 **서로 어울리지 않는 현실 물건을 쌓아 만든 거대한 탑**. 길이 하나가 아니라 **여러 갈래 경로**가 있고, 눈에 보이는 큰 물체 위로 올라가는 느낌 |
| 도전 | 좁은 널빤지·기둥·간판·창틀 점프, 미끄러지는 면, 긴 도약. 정밀한 점프와 경로 읽기가 전부 |
| 체크포인트 | **없음** → 떨어지면 지금까지 올라온 높이를 거의 잃는다. 이것이 긴장과 "한 번 더"의 원천 |
| 실패 | 죽음 연출 없이 그냥 추락. 아래층에 걸리면 거기서부터 다시 |
| 보상 | 높이 올라갈 때 달라지는 풍경, 꼭대기 도착의 쾌감. 점수·재화 없음 |
| 분위기 | 다소 우스꽝스러운 잡동사니 + 쓸쓸한 음악. 길 찾기 자체가 놀이 |

**결론**: 규칙은 단순하다 — *점프 정확도 + 경로 읽기 + 추락의 공포*. 재미는 **발판 배치(레벨 디자인)와 추락 규칙**에서 나온다. 그래서 이 사양서의 무게는 4·5절에 둔다.
**이 게임은 학교 수업용**이라 원작처럼 3시간짜리 좌절을 주지 않는다: 모험 모드는 구간 깃발로 되돌아갈 곳을 만든다(5절).

## 2. 조작

### 2-1. 키보드 (PC)
| 입력 | 동작 |
|---|---|
| `W A S D` / 방향키 | 이동(카메라 방향 기준). 방향키는 `e.key`, WASD 는 `e.code`(한글 IME 대비) |
| 마우스 이동 | 카메라 회전(포인터 잠금, `Esc` 로 풀기). 잠금이 안 되는 환경은 드래그로 회전 |
| `Space` | 점프(누르고 있는 시간이 아니라 고정 높이. 6절) |
| `Shift`(누르는 동안) | 달리기. 놓으면 걷기 |
| `E` | 매달린 곳 잡기/놓기, 사다리 타기/내리기 |
| `R` | 마지막 깃발로 돌아가기(꾹 1초, 모험 모드) |
| `Esc` | 일시정지(메뉴·조작 설명·나가기) |

### 2-2. 터치 (갤럭시탭 S7 FE 가로)
| 입력 | 동작 |
|---|---|
| 왼쪽 가상 조이스틱 | 이동. **거리와 상관없이 그 방향의 최고 속도**(가운데 무감 구역 안에서만 멈춤, 프로젝트 공통 규칙). 최고 속도 = **달리기 속도** |
| 오른쪽 화면 드래그 | 카메라 회전(손가락 한 개) |
| 오른쪽 아래 `점프` 큰 버튼 | 점프. 허공에서 누르면 점프 예약(6절) |
| 점프 버튼 위쪽 작은 `잡기` 버튼 | 매달리기·사다리. 잡을 수 있는 곳 근처에서만 나타남 |
| 왼쪽 위 `깃발로` 버튼(꾹) | 마지막 깃발로 |

- 터치 때는 **걷기가 없고 항상 달리기**이다(조이스틱 규칙). 좁은 발판은 무감 구역 안에서 멈추고 점프로 건너는 방식으로 설계한다 → 좁은 구간 앞에 "멈춤 쉼터"를 넉넉히 둔다(4절).
- 키보드는 걷기(속도 4)와 달리기(7)가 있다. 걷기는 좁은 널빤지에서 정밀하게 갈 때 쓴다. 터치 학생이 불리하지 않도록 **모든 길은 달리기 속도로 갈 수 있게** 만든다(9절 검사로 보장).
- 캔버스는 `touch-action:none`(돋보기·복사 풍선 막기). 고정 HUD 는 `← 목록으로` 버튼 때문에 46px 아래로.

## 3. 게임 구조

### 3-1. 장면 흐름
```
시작 화면 → (모드 선택) → 카운트다운 3·2·1 → 플레이 ⇄ 일시정지
                                        ├ 구간 깃발 도착 → 구간 알림(높이·시간) → 계속
                                        ├ 추락 → 되살아나기(모험: 깃발 / 도전: 현재 바닥)
                                        └ 꼭대기 깃발 → 결과 화면(기록 갱신 NEW) → 다시 하기/목록으로
```

### 3-2. 탑의 구조 【제안】
- 탑은 **7개 구간**, 구간마다 약 30m. 구간 사이는 **넓은 쉼터 발판 + 구간 깃발**(체크포인트).
- 한 구간 안에 **경로가 2~3갈래**: ① 쉬운 길(길고 안전함), ② 보통 길(짧음), ③ 어려운 길(가장 짧고 위험). 원작처럼 "지름길을 믿어 볼까" 갈등을 준다. 갈래는 위에서 다시 합쳐진다.
- 구간마다 **다른 에셋 팩으로 꾸며** 높이가 오를수록 풍경이 바뀐다. 원작의 "안 어울리는 물건이 쌓인" 맛은 **물건을 크게(×3~×8) 확대해 쌓는 것**으로 낸다(큰 술통 위로 올라가기).

| 구간 | 높이 | 테마 | 주 에셋 팩(`kaykit-catalog`) |
|---|---|---|---|
| 1 뿌리 숲 | 0~30 | 숲 바닥, 쓰러진 나무·바위 | Forest Nature(`Tree_*`·`Rock_*`), Block Bits |
| 2 폐허 마을 | 30~60 | 무너진 성벽·지붕·사다리 | Medieval Hexagon(건물·`ladder`·`bridge`), Medieval Builder |
| 3 지하 던전 | 60~90 | 계단·기둥·술통·상자 더미 | Dungeon Pack(`stairs_*`·`pillar`·`barrel_large`·`crates_stacked`) |
| 4 거인의 주방 | 90~120 | 거대한 식탁·냄비·상자 | Restaurant Bits(`crate_*`), Furniture Bits |
| 5 묘지 | 120~150 | 호박·울타리·유령집 | Halloween Bits, Mixed Bag 2(`haunted_manor`) |
| 6 눈 덮인 장난감 마을 | 150~180 | 선물 상자·눈 덮인 나무·기차 | Holiday Bits(선물 상자·기차·`tree_with_snow`) |
| 7 우주 기지 | 180~200 | 패널·타워·안테나, 꼭대기 깃발 | Space Base Bits, Prototype Bits |

- 실제 모델 파일명·크기는 만들 때 `node tools/kaykit-find.js 단어` 로 확인하고 `assets/kaykit/` 에 없는 것만 `organized` 에서 복사한다(도감 6절).
- 바닥 쪽은 **구름 바다**로 가리고(큰 평면 + 안개) 떨어지는 사이 높이 숫자가 줄어드는 느낌만 낸다. 진짜 땅까지 그리지 않는다.

### 3-3. 장애물·발판 목록 【제안】
| 종류 | 설명 | 판정 |
|---|---|---|
| 고정 발판 | 술통·상자·기둥 머리·`Primitive_*`·널빤지(`Primitive_Beam`) | 위쪽 면만 서는 곳 |
| 좁은 발판 | 폭 0.6~1.0 (기둥·널빤지) | 정밀 점프 |
| 경사·미끄러운 면 | 지붕·`Primitive_Slope`·얼음. 서 있으면 미끄러져 내려감 | 경사 > 40° |
| 움직이는 발판 | 일정 경로로 오가는 판(2·4·6구간) | 서 있으면 같이 움직임 |
| 무너지는 발판 | 밟고 0.8초 뒤 흔들리다 떨어지고 3초 뒤 복구(5·6구간) | 타이머 |
| 도는 막대 | 회전하는 빔을 점프로 넘기, 닿으면 튕겨 나감(피해 없음) | 밀기 |
| 튕기는 발판 | 점프력 1.7배(4·6구간, 큰 선물 상자·술통) | 위로 튕김 |
| 사다리 | 위아래로 일정 속도, 끝에서 `점프`로 뛰어내림(모델 `ladder` 를 ×4 확대) | 사다리 영역 |
| 매달릴 모서리 | 발판 가장자리에 `E`/`잡기`로 매달려 올라오기(3~4m 위까지) | 모서리 영역 |
| 바람 | 가로로 미는 구역(7구간 일부) | 힘 +x |
| 구간 깃발 | 닿으면 저장(`flag_A_*`·`banner_*`), 색은 구간마다 다름 | 닿기 |

**원칙**: 한 번에 새 장애물 **하나**씩 소개하고 쉬운 형태로 먼저 보여 준 뒤 어려운 형태를 낸다(구간 안에서 튜토리얼 → 응용).

## 4. 레벨 설계 규칙 (재미를 만드는 곳) 【제안】

1. **연속 점프는 5회까지**, 그다음에 반드시 안전 발판(쉼터)을 둔다. 쉼터는 앉아서 카메라를 돌려 길을 볼 수 있게 한 변 3m 이상.
2. **보이게 만든다**: 다음 발판은 항상 화면 안에 들어오도록(카메라 거리·각도 조정). 눈에 띄는 색의 "표지"(노란 깃발·빛나는 상자, MeshBasicMaterial)를 길 위에 둔다.
3. **되돌릴 수 없는 실수는 하나만**: 한 번 잘못 뛰면 한 단계 아래 쉼터로 떨어지도록 아래에 받침 발판을 둔다(구간 안 "그물" 발판). 원작식 완전 추락은 도전 모드에서만 일어난다.
4. **난이도 곡선**: 구간 1은 전부 한 번에 점프 최대 거리의 60% 이내, 구간 7은 90%까지. 최고난도 한 곳은 "최대 거리의 95%"를 넘지 않는다(9절 검사가 막음).
5. **높이 감각**: 구간이 바뀔 때 하늘색·안개 색이 바뀌고(숲 초록 → 던전 어두움 → 노을 → 밤 → 우주), 오를수록 바람 소리·배경 음이 달라진다. 화질 자동 조절에서 안개를 줄여도 구분되게 색을 쓴다.
6. **한 구간 평균 소요**: 숙련 80초, 처음 하는 학생 3~4분. 쉼터에서 길 읽기가 이 시간의 절반을 먹는다.

## 5. 추락·체크포인트 규칙 【확인】

| 모드 | 규칙 |
|---|---|
| ★모험 | 구간 깃발에 닿으면 저장. 떨어지면 바닥(구름)까지 가지 않고 **약 2초 안에** 마지막 깃발에서 `Spawn_Air` 로 되살아남. 구간 안 그물 발판에 걸리면 그 자리에서 이어 감 |
| 도전 | 깃발 저장 없음. 떨어지면 **걸리는 가장 가까운 발판**(아래 구간의 어느 쉼터든)에 떨어져 거기서 계속, 아무것도 없으면 맨 아래 시작 지점. 최고 높이만 기록 |
- 도전 모드는 학생 선택 기능(시작 화면 버튼). 첫 클리어는 모험 모드로 하게 유도한다(도전은 모험 첫 클리어 후 열림 — 【확인】).
- 추락 중에는 소리·시야 흐림 없음(멀미 방지). 낙하 화면에 `떨어졌어요! 깃발에서 다시` 한 줄만 짧게.
- 추락 속도 상한 35m/s, 구름 위에서 착지 판정으로 사라짐(최대 낙하 거리 200m → 약 5초).

## 6. 캐릭터·물리

### 6-1. 움직임 (월드 단위 = KayKit 미터, 캐릭터 키 ≈ 2.2)
| 값 | 초기값 | 비고 |
|---|---|---|
| 걷기 / 달리기 속도 | 4 / 7 m/s | 터치는 달리기만 |
| 가속 | 지상 40, 공중 12 m/s² | 공중 조종 가능(원작 느낌) |
| 중력 | 28 m/s² | |
| 점프 속도 | 9.5 m/s | 최대 높이 1.61m, 체공 0.68초 |
| 달리기 점프 수평 거리 | 약 4.75m (평지) | **9절 기준: 설계 최대 간격 = 이 값의 0.9** |
| 코요테 시간 | 0.12초 | 발판 가장자리를 벗어난 직후 점프 가능 |
| 점프 예약 | 0.15초 | 착지 직전 누른 점프를 착지 때 실행 |
| 낙하 상한 속도 | 35 m/s | |
| 경사 한계 | 40° 넘으면 미끄러짐 | 얼음은 12° |
| 이동 발판 | 서 있는 동안 발판 속도 더함 | |

점프 높이는 고정(누르고 있는 시간에 따라 달라지지 않음) — 터치 학생이 불리하지 않도록 한다. 정밀함은 공중 조종과 달리기·걷기 선택으로 만든다.

### 6-2. 충돌 방식 【제안】
- **물리 엔진을 쓰지 않는다.** 캐릭터는 세워진 캡슐(반지름 0.4, 높이 2.0), 월드는 **축에 맞춘 상자(AABB)·회전 상자·경사면** 목록이다. 이유: 갤럭시탭 성능, 결과가 늘 같아 검사 가능.
- 모든 발판·장애물은 만들 때 **모델 크기에서 충돌 상자를 자동 생성**하고(`Box3`), 필요하면 손으로 줄인다(나뭇잎·장식은 충돌 없음).
- 움직임은 고정 시간 간격(1/120초) 갱신 + 그리기 보간. 프레임이 느려도 점프 거리가 같다.
- 바닥 찾기: 위에서 아래로 상자 윗면 검사 → 그 높이에 서기. 옆 충돌은 축별로 밀어내기. 천장은 머리를 박으면 상승 속도 0.
- 공간 분할: 구간(30m) × 4m 격자에 상자를 넣어 캐릭터 근처 셀만 검사.

### 6-3. 매달리기·사다리 【제안】
- 매달리기: 점프 중 앞에 모서리(상자 윗면 가장자리, 캐릭터 가슴~머리 높이)가 있으면 `E`/`잡기`를 누르면 잡는다. 0.4초 매달린 뒤 올라타거나(자동) `점프` 로 뛴다. 매달린 동안 좌우 이동은 하지 않는다.
- 사다리: 영역 안에서 `E`/`잡기` 또는 위로 이동하면 붙음. 위·아래 이동 3 m/s, 끝에서 자동으로 올라타거나 `점프` 로 이탈.
- 애니메이션: Rig_Medium 에는 사다리·매달리기 전용 클립이 없다. ① Jump_Idle 포즈를 위아래 움직임과 함께 쓰거나 ② 이 장면만 `PrototypePete`(전용 `Climbing` 클립)를 쓴다 — 만들기 전 `kaykit-find.js climb` 로 다시 확인하고 정한다 【확인】.

### 6-4. 카메라
- 3인칭 궤도 카메라: 거리 6m(조절 4~9), 위에서 15°. 마우스·오른쪽 드래그로 회전.
- **벽 뚫림 방지**: 캐릭터에서 카메라 쪽으로 광선을 쏴 충돌 상자에 닿으면 거기까지 당긴다.
- 달릴 때 카메라가 진행 방향으로 천천히 따라 돌아간다(켜고 끄기 가능). 추락 중에는 캐릭터를 따라 내려오되 위쪽 5° 더 올려 낙하 방향을 본다.
- 점프 직전에는 카메라 위치를 흔들지 않는다(정밀 점프 방해).

### 6-5. 애니메이션 (KayKit `Rig_Medium`, 이름은 만들기 전 도감으로 확정)
- `Idle_A`, `Walking_A`, `Running_A`(MovementBasic), `Jump_Start`·`Jump_Idle`·`Jump_Land`(점프 5단계), 착지 충격 `Jump_Land`, 되살아나기 `Spawn_Air`/`Spawn_Ground`(General), 넘어짐/튕김 `Hit_A`, 꼭대기 도착 `Cheering`(Simulation), 구르기는 쓰지 않음.
- 캐릭터 모델: `CharacterModelFactory`(공용), 닉네임·외형은 `portal_profile_v1` 한 곳.

## 8. 기록·계정

- **최고 높이**(키 `towerclimb`): 도전 모드 포함 최고 높이. `WorldRecord("towerclimb", {format: m})`.
- **최단 클리어 시간**(키 `towerclimbtime`, `lower:true`): 모험 모드에서 클리어한 시간 중 가장 작은 값. 게임 이름은 소문자 영문만(`^[a-z]+$`) 규칙.
- 기기 기록 `towerclimb_best_v1`·`towerclimb_time_v1`(try/catch)을 시작 화면·HUD·결과 세 곳에 표시, 갱신 시 `NEW`.
- 계정 동기화: `WorldRecord.syncBest(게임, {storageKey, merge: WorldRecord.betterOf(…), onApply})` + 신기록 저장 직후 `pushBest`.
- `데이터베이스규칙.json` 에 점수 상한 한 줄 추가(높이 ≤ 200, 시간 하한 ≥ 120초: **사람이 못 깨는 시간은 규칙으로 거른다**). 선생님이 콘솔에 다시 게시한다.
- 조작 방지(2차): 기록 제출 시 경로(깃발 통과 순서) 해시를 같이 저장해 이상값을 걸러낼 수 있게만 열어 둔다.

## 9. 검사 (화면 없는 규칙 코드 + 도달 검사)

- 규칙 엔진 `ts/games/43.tower-climb/43.climb-rules.ts` 는 **화면을 모른다**: 캡슐·충돌 상자·이동·점프·매달리기·사다리·이동 발판 계산만 한다. 같은 입력이면 항상 같은 결과.
- `node tools/climb-unit.js`: 점프 높이·거리·코요테·점프 예약·경사 미끄러짐·매달리기·튕김을 숫자로 확인.
- **`node tools/climb-reach.js` — 도달 검사(가장 중요)**: 레벨 데이터의 모든 발판 쌍에 대해 "시작 발판에서 다음 발판까지 조작 가능한 점프가 있는가"를 시뮬레이션으로 찾는다. 기준:
  - 모든 구간에 시작부터 깃발·꼭대기까지 **달리기 속도(터치 기준)로** 가는 길이 최소 1개 있다.
  - 모든 점프의 필요 거리 ≤ 최대 거리의 0.9(난이도 구간별 상한 4절 4항).
  - 쉼터에서 다음 쉼터로 가는 경로가 없는 구간은 오류. 갈래 3개 중 최소 1개는 쉬운 길(연속 점프 5회 이하).
  - 움직이는 발판·무너지는 발판은 주기 전체를 돌려 가며 검사.
- `node tools/climb-sim.js`: 무작위·간단 행동 규칙으로 5천 번 시뮬레이션해 깃발까지 도착하는 비율·평균 시간을 보고(달성 가능성 확인).
- 모두 통과해야 푸시한다. 푸시 뒤에는 38번처럼 사이트 파일 일치까지 확인하고 보고한다(37번 절차 참고).

## 10. 성능 (3D 성능 지침, 기준 SM-T733 터치 60fps)

- **구간 단위 그리기**: 탑을 7구간 × 30m 로 나눠 **현재 구간 ±1 구간**만 그린다(나머지는 `visible=false` 가 아니라 장면에서 빼 두고 다가오면 붙이기 — 셰이더 재컴파일 없음). 한 번에 보이는 구간 3개.
- **InstancedMesh**: 같은 모델(술통·상자·나무·바위)은 구간별로 한 덩어리 인스턴싱, 반드시 구간 셀로 나눠 `frustumCulled` 를 켠다.
- **그림자**: 캐릭터 주변 한 영역만(그림자 카메라가 캐릭터를 따라감), 해상도 1024. 터치는 그림자 단순화 단계 포함.
- **조명**: 방향광 1 + 반구광 1만. 점·스포트라이트 없음, 빛나는 표지는 `MeshBasicMaterial`. 구간 분위기는 안개·하늘색·반구광 색으로만 바꾼다.
- **픽셀 배율**: 터치 상한 1.25~1.5, 화질 자동 조절 `QualityGovernor`(배율 0.25씩 1.0까지 → 블룸 끄기 → 그림자 줄이기). 단계와 저장 키는 24·31번을 따른다.
- **첫 사용 끊김 없애기**: 카운트다운 동안 구간 1·2에 쓰이는 모든 재질을 한 번 그려 본다(보이지 않는 곳에서).
- **텍스처 2048px 이하**, 이펙트(먼지·착지 파편)는 풀링, 게임 중 `clone`·`new` 금지.
- 그리기는 반드시 `requestAnimationFrame`(60fps 제한은 `access-guard` 가 자동). 접속 주소 끝에 `&fps` 로 확인.

## 12. 만드는 순서
