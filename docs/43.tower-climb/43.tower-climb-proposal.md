# 43번 「동마 타워 클라임」 — 사양서 (v0.2, 2026-11-16)

「Only Up!」처럼 **끝없이 이어진 잡동사니 탑을 3인칭으로 뛰어 올라가는** 개인전 3D 플랫포머. "한 번 삐끗하면 한참 떨어진다 → 그래도 다시 간다"가 핵심이다.
선생님이 읽고 고친 뒤 확정한다. 그림은 **KayKit 3D 에셋**만 쓴다.

**표식**: **【조사】** 원작·장르 공통 규칙 / **【제안】** 이 게임에서 새로 넣는 것 / **【확인】** 선생님이 정할 값(기본값 ★). 수치는 모두 초기값이며 도달 검사(9절)와 시험 플레이로 확정한다.

## v0.2 에서 바뀐 것 (2026-11-16 선생님 요청)

1. **걷기·달리기 구분을 없앴다.** 키보드·터치 모두 **항상 달리기**(7 m/s). `Shift` 달리기 키는 없다.
2. `Space` 점프, `E` 잡기는 그대로 둔다.
3. **점프대를 넣었다**: 안전한 *작은 점프대*와, 구간을 통째로 건너뛰는 **하이리스크·하이리턴 발사대**(3-3·6-7절).
4. **슬로 모션 키**를 넣었다(`Shift` 를 누르고 있는 동안 모든 움직임이 느려짐, 6-6절).
5. **만드는 단계를 둘로 나눴다**: **1단계 = 구간 1만 만들어 완성·사이트 업로드**, **2단계 = 구간 2~7을 한 구간씩 추가**(12절).

## 1. 원작 「Only Up!」 분석 【조사】

내가 아는 원작 기준이며 인터넷으로 다시 확인하지는 못했다. 어긋나는 점은 알려 주세요.

| 요소 | 원작의 모습 |
|---|---|
| 시점·조작 | 3인칭. `WASD` 이동, `Space` 점프, `Shift` 달리기, 마우스 카메라. 전투·아이템 없음 |
| 구조 | 서로 어울리지 않는 현실 물건을 쌓은 **거대한 탑**. 길이 여러 갈래 |
| 도전 | 좁은 널빤지·기둥·간판·창틀 점프, 미끄러운 면, 긴 도약 |
| 체크포인트 | **없음** → 떨어지면 올라온 높이를 거의 잃는다. 긴장과 "한 번 더"의 원천 |
| 보상 | 높이 오를 때 달라지는 풍경, 꼭대기의 쾌감 |

**결론**: 규칙은 *점프 정확도 + 경로 읽기 + 추락의 공포*. 재미는 **발판 배치와 추락 규칙**에서 나온다. 수업용이라 모험 모드는 깃발로 되돌아갈 곳을 만든다(5절).

## 2. 조작

### 2-1. 키보드 (PC)
| 입력 | 동작 |
|---|---|
| `W A S D` / 방향키 | 이동(카메라 방향 기준, **항상 달리기**). 방향키는 `e.key`, WASD 는 `e.code`(한글 IME 대비) |
| 마우스 이동 | 카메라 회전(포인터 잠금, `Esc` 로 풀기). 잠금이 안 되면 드래그 |
| `Space` | 점프(고정 높이, 6절). 발사대 위에서는 **발사** |
| `E` | 모서리 매달리기·놓기, 사다리 타기·내리기 |
| `Shift`(누르는 동안) | **슬로 모션**(6-6절) |
| `R`(꾹 1초) | 마지막 깃발로 돌아가기(모험 모드) |
| `Esc` | 일시정지(메뉴·조작 설명·나가기) |

### 2-2. 터치 (갤럭시탭 S7 FE 가로)
| 입력 | 동작 |
|---|---|
| 왼쪽 가상 조이스틱 | 이동. **거리와 상관없이 그 방향의 최고 속도**(프로젝트 공통 규칙), 가운데 무감 구역 안에서만 멈춤 |
| 오른쪽 화면 드래그 | 카메라 회전 |
| 오른쪽 아래 `점프` 큰 버튼 | 점프(허공에서 누르면 점프 예약). 발사대 위에서는 발사 |
| `점프` 버튼 위쪽 작은 `슬로` 버튼 | **누르고 있는 동안** 슬로 모션 |
| `슬로` 위쪽 작은 `잡기` 버튼 | 매달리기·사다리. 잡을 수 있는 곳 근처에서만 나타남 |
| 왼쪽 위 `깃발로` 버튼(꾹) | 마지막 깃발로 |

- 걷기가 없으므로 **좁은 발판에서는 조이스틱을 놓아 멈춘다**(놓으면 0.05초 안에 멈추는 짧은 감속). 좁은 발판 앞에는 "멈춤 쉼터"를 둔다(4절). 정밀한 구간은 슬로 모션이 돕는다.
- 점프(오른손)와 슬로를 같이 눌러야 해서 엄지만으로는 불편하다 → 【확인】 터치 슬로 방식: ★누르는 동안(요청대로) / 탭으로 켜고 끄기. 설정 한 칸으로 고를 수 있게 한다.
- 캔버스는 `touch-action:none`. 고정 HUD 는 `← 목록으로` 버튼 때문에 46px 아래로.

## 3. 게임 구조

### 3-1. 장면 흐름
```
시작 화면 → (모드 선택) → 카운트다운 3·2·1 → 플레이 ⇄ 일시정지
                                        ├ 구간 깃발 도착 → 알림(높이·시간) → 계속
                                        ├ 추락 → 되살아나기(모험: 마지막 깃발 / 도전: 걸린 발판)
                                        └ 완주 깃발 → 결과 화면(기록 갱신 NEW) → 다시 하기/목록으로
```

### 3-2. 탑의 구조 【제안】
- 최종 탑은 **7개 구간**, 구간마다 약 30m. 구간 사이는 **넓은 쉼터 + 구간 깃발**.
- 한 구간 안에 **경로 3갈래**: ① 쉬운 길(길고 안전), ② 보통 길(짧음), ③ 어려운 길(가장 짧고 위험, 여기에 **발사대**가 숨어 있다). 갈래는 위에서 합쳐진다.
- 구간마다 다른 에셋 팩으로 꾸미고, 물건을 **크게(×3~×8) 확대해 쌓아** 원작의 "안 어울리는 물건이 쌓인" 맛을 낸다.

| 구간 | 높이 | 테마 | 주 에셋 팩 | 처음 나오는 요소 |
|---|---|---|---|---|
| **1 뿌리 숲** (1단계) | 0~30 | 숲 바닥, 쓰러진 나무·바위 | Forest Nature(`Tree_*`·`Rock_*`), Block Bits | 고정·좁은 발판, 경사, **매달리기**, **작은 점프대**, **발사대**, 슬로 모션 |
| 2 폐허 마을 | 30~60 | 무너진 성벽·지붕 | Medieval Hexagon(`ladder`·`bridge`), Medieval Builder | 사다리 |
| 3 지하 던전 | 60~90 | 계단·기둥·술통·상자 | Dungeon Pack | 움직이는 발판, 연쇄 발사대 |
| 4 거인의 주방 | 90~120 | 거대한 식탁·상자 | Restaurant Bits, Furniture Bits | 무너지는 발판 |
| 5 묘지 | 120~150 | 호박·울타리·유령집 | Halloween Bits, Mixed Bag 2 | 도는 막대 |
| 6 눈 덮인 장난감 마을 | 150~180 | 선물 상자·눈 덮인 나무 | Holiday Bits | 미끄러운 얼음, 큰 발사대 |
| 7 우주 기지 | 180~200 | 패널·타워·안테나, 꼭대기 | Space Base Bits, Prototype Bits | 바람, 최종 깃발 |

- 모델 파일명·크기는 만들 때 `node tools/kaykit-find.js 단어` 로 확인하고 `assets/kaykit/` 에 없는 것만 `organized` 에서 복사한다.
- 아래쪽은 **구름 바다**(큰 평면 + 안개)로 가린다. 진짜 땅까지 그리지 않는다.

### 3-3. 장애물·발판 목록 【제안】
| 종류 | 설명 | 판정 |
|---|---|---|
| 고정 발판 | 통나무·바위·술통·상자·기둥 머리·`Primitive_*` | 윗면에 선다 |
| 좁은 발판 | 폭 0.6~1.0 (쓰러진 나무·기둥·`Primitive_Beam`) | 정밀 점프 |
| 경사·미끄러운 면 | 지붕·`Primitive_Slope`·얼음, 서 있으면 미끄러짐 | 경사 > 40°(얼음 12°) |
| 매달릴 모서리 | 발판 가장자리에 `E` 로 매달려 올라오기(가슴~머리 높이 안) | 모서리 영역 |
| **작은 점프대** | 밟으면 위로 튕김(위 속도 15 m/s, 높이 약 4m = 일반 점프의 2.5배). 착지 쉼터가 넓고 눈에 보임 → **안전한 보너스** | 위로 튕김 |
| **발사대(대포)** | **하이리스크·하이리턴**: 올라서면 충전되고 `Space` 로 발사, 한 번에 **+12m 이상**을 건너뛰는 지름길(6-7절) | 발사 |
| 사다리 | 위아래 3 m/s, 끝에서 점프로 이탈(`ladder` ×4 확대) | 사다리 영역 |
| 움직이는 발판 | 일정 경로로 오가는 판. 서 있으면 같이 움직임 | 발판 속도 더함 |
| 무너지는 발판 | 밟고 0.8초 뒤 흔들리다 떨어지고 3초 뒤 복구 | 타이머 |
| 도는 막대 | 회전 빔, 닿으면 튕겨 나감(피해 없음) | 밀기 |
| 바람 | 가로로 미는 구역 | 힘 +x |
| 깃발 | 닿으면 저장(`flag_A_*`·`banner_*`), 구간마다 색이 다름 | 닿기 |

**원칙**: 한 번에 새 장애물 **하나**씩, 쉬운 형태로 먼저 보여 준 뒤 어려운 형태를 낸다.

### 3-4. 구간 1 설계(1단계 범위) 【제안】
| 높이 | 내용 |
|---|---|
| 0m | **시작 쉼터**(넓은 풀밭·모닥불 같은 장식)와 시작 깃발. 카메라 연습 공간 |
| 0~8m | 튜토리얼: 고정 발판(바위·그루터기) 연속 점프 3회 → 쓰러진 통나무(좁은 발판) 1개 → 쉼터 |
| 8~12m | 첫 **작은 점프대**(통나무 사이, 넓은 착지판) — "점프대가 뭔지" 배우는 곳 |
| 12m | **중간 쉼터 + 중간 깃발**(구간 1 은 짧아서 깃발이 두 개) |
| 12~26m | 3갈래 ① 쉬운 길: 바위 계단 + 나무 위 발판(연속 점프 ≤ 4회) ② 보통 길: **매달릴 모서리 2곳** + 경사 바위 1곳 ③ 어려운 길: 좁은 통나무 2개 + 최대 간격 0.9의 점프 1회 → **발사대**(14m 높이에 있음) |
| 발사대 | 14m 에서 발사 → 26m 높이의 작은 착지 발판(3m×3m)으로 날아감. 일반 경로로 약 50초 걸리는 구간을 **약 3초**에 건너뜀. 실패하면 12m 중간 깃발로 떨어짐(받침 없음) |
| 26~30m | 마지막 짧은 오르막 → **완주 깃발**(30m). 결과 화면에 "구간 1 완주! 다음 구간은 공사 중입니다" |
- 구간 1 소요 목표: 숙련 80초, 처음 하는 학생 3~4분.
- 슬로 모션은 좁은 통나무·발사대 조준에서 가장 유용하도록 배치한다.

## 4. 레벨 설계 규칙 【제안】

1. **연속 점프는 5회까지**, 그다음에 안전 쉼터(한 변 3m 이상). 쉼터에서는 멈춰서 카메라로 길을 볼 수 있다.
2. **보이게 만든다**: 다음 발판이 화면 안에 들어오도록 카메라 거리·각도를 조정. 눈에 띄는 색의 표지(노란 깃발·빛나는 상자, `MeshBasicMaterial`).
3. **한 번의 실수가 모두를 잃게 하지 않는다**: 모험 모드는 마지막 깃발, 구간 안에는 받침(그물) 발판을 둔다. 원작식 완전 추락은 도전 모드에서만.
4. **난이도 곡선**: 구간 1은 최대 점프 거리의 60% 이내(어려운 길만 0.9), 구간 7은 90%. 어떤 점프도 95% 를 넘지 않는다(9절 검사).
5. **구간마다 분위기가 바뀐다**: 하늘색·안개 색·반구광 색(구간 1은 밝은 초록 낮).
6. **발사대 규칙(하이리스크·하이리턴)**:
   - 반드시 **어려운 길 ③** 위에 둔다(접근부터 위험). 쉬운 길만으로도 항상 완주 가능해야 한다.
   - 얻는 것: 한 번에 +12m 이상(구간의 40% 이상), 시간 40~60초 단축.
   - 잃는 것: 놓치면 **마지막 깃발까지** 추락(모험) / **한 구간 아래 발판**까지(도전). 착지 발판은 작게(3m×3m).
   - 발사 경로는 하늘에서 잘 보이는 **밝은 점선(표지)**으로 그려 "도전할 만하다"고 알려 준다.

|---|---|
| ★모험 | 깃발에 닿으면 저장. 떨어지면 **약 2초 안에** 마지막 깃발에서 `Spawn_Air` 로 되살아남. 구간 안 그물 발판에 걸리면 그 자리에서 계속 |
| 도전 | 깃발 저장 없음. 떨어지면 **걸리는 가장 가까운 아래 발판**에서 계속, 없으면 맨 아래. 최고 높이만 기록 |
- 도전 모드는 모험 첫 완주 뒤 열림 【확인】. 1단계에서는 구간 1 완주가 기준.
- 추락 중에는 소리·시야 흐림 없음(멀미 방지). `떨어졌어요! 깃발에서 다시` 한 줄만.
- 낙하 속도 상한 35m/s. 슬로 모션은 추락 중에도 쓸 수 있지만 낙하 시간만 길어질 뿐 도움이 되지 않는다.

## 6. 캐릭터·물리

### 6-1. 움직임 (월드 단위 = KayKit 미터, 캐릭터 키 ≈ 2.2)
| 값 | 초기값 | 비고 |
|---|---|---|
| **이동 속도** | **7 m/s 한 가지** | 키보드·터치 동일, 항상 달리기 |
| 가속 | 지상 40, 공중 12 m/s² | 공중 조종 가능. 입력 없을 때 지상 정지 0.05초 |
| 중력 | 28 m/s² | |
| 점프 속도 | 9.5 m/s | 높이 1.61m, 체공 0.68초 |
| 점프 수평 거리 | 약 4.75m (평지) | **설계 최대 간격 = 이 값의 0.9** |
| 코요테 시간 | 0.12초 | 가장자리를 벗어난 직후 점프 가능 |
| 점프 예약 | 0.15초 | 착지 직전 누른 점프를 착지 때 실행 |
| 낙하 상한 속도 | 35 m/s | |
| 경사 한계 | 40° 넘으면 미끄러짐 | 얼음 12° |
| 작은 점프대 위 속도 | 15 m/s | 높이 약 4m |
| 발사대 | 6-7절 | |

점프 높이는 고정(누른 시간과 무관) — 터치 학생이 불리하지 않게. 정밀함은 공중 조종과 슬로 모션으로 만든다.

### 6-2. 충돌 방식 【제안】
- **물리 엔진을 쓰지 않는다.** 캐릭터는 세운 캡슐(반지름 0.4, 높이 2.0), 월드는 **AABB·회전 상자·경사면** 목록. 이유: 갤럭시탭 성능, 결과가 늘 같아 검사 가능.
- 충돌 상자는 모델 크기에서 자동 생성(`Box3`)하고 필요하면 손으로 줄인다(잎·장식은 충돌 없음).
- 고정 시간 간격(1/120초) 갱신 + 그리기 보간. 프레임이 느려도 점프 거리가 같다. 슬로 모션은 이 간격에 곱하는 배율로 처리해 **궤적이 같다**(6-6).
- 격자 분할: 구간 × 4m 셀에 상자를 넣고 캐릭터 근처 셀만 검사.

### 6-3. 매달리기·사다리 【제안】
- **매달리기(`E`)**: 점프 중 앞에 모서리가 가슴~머리 높이로 닿으면 `E` 로 잡는다. 0.4초 뒤 자동으로 올라타거나 `Space` 로 뛴다. 매달린 동안 좌우 이동 없음. 놓치면 그대로 낙하.
- **사다리(2구간부터)**: 영역 안에서 `E` 또는 위 입력으로 붙고, 위·아래 3 m/s, 끝에서 올라타거나 `Space` 로 이탈.
- 애니메이션: Rig_Medium 에는 사다리·매달리기 전용 클립이 없다 → ★`Jump_Idle` 포즈를 위아래 이동과 함께 쓴다. 안 어울리면 이 장면만 `PrototypePete`(`Climbing` 클립). 만들기 전 `kaykit-find.js climb` 로 다시 확인.

### 6-4. 카메라
- 3인칭 궤도: 거리 6m(조절 4~9), 위 15°. 마우스·오른쪽 드래그로 회전.
- **벽 뚫림 방지**: 캐릭터→카메라 광선이 충돌 상자에 닿으면 거기까지 당긴다.
- 달릴 때 카메라가 진행 방향으로 천천히 따라 돈다(켜고 끄기 가능). 추락 중에는 낙하 방향이 보이게 위쪽 5° 올림.
- 슬로 모션 중에도 **카메라 회전은 실시간**(느려지지 않음) — 조준이 쉬워진다.

### 6-5. 애니메이션 (KayKit `Rig_Medium`, 이름은 만들기 전 도감으로 확정)
- `Idle_A`, `Running_A`(걷기 클립은 쓰지 않음), `Jump_Start`·`Jump_Idle`·`Jump_Land`, 되살아나기 `Spawn_Air`, 튕김 `Hit_A`, 완주 `Cheering`(Simulation).
- 모델: `CharacterModelFactory`(공용), 닉네임·외형은 `portal_profile_v1` 한 곳.

### 6-6. 슬로 모션 【제안】
`Shift`(터치는 `슬로` 버튼)를 **누르고 있는 동안** 게임 시간이 느려진다.

| 항목 | 값 |
|---|---|
| 배율 | **0.3배**(이동·점프·낙하·움직이는 발판·무너지는 발판·애니메이션·이펙트 모두). 켜고 끌 때 0.15초에 걸쳐 부드럽게 전환 |
| 안 느려지는 것 | **카메라 회전·HUD·입력**(그래야 조준이 쉬움), 클리어·기록 시간(실제 시간) |
| 게이지 | ★**4초치**. 누르는 동안 1/s 감소, 누르지 않으면 0.5/s 회복(전부 차는 데 8초). **깃발에서 즉시 가득**. 비면 자동으로 풀리고 0.5초 쿨다운 |
| 화면 | 가장자리에 푸른 안개빛 비네트(`opacity` 만), 효과음 재생 속도 0.6배, 배경 소리 낮아짐 |
| 모드 | 모험·도전 둘 다 사용 가능 |
| 규칙 | 시간 기록은 실제 시간이라 **슬로를 써도 빨라지지 않고 정밀해지기만** 한다. 도달 검사(9절)는 슬로 없이 통과해야 한다(슬로는 보조) |

**왜 게이지인가**: 무제한이면 모든 점프가 쉬워져 긴장이 사라진다. 게이지를 아껴 쓰는 선택이 새 재미가 된다. 무제한으로 바꾸고 싶으면 【확인】 에서 알려 주세요.

### 6-7. 점프대·발사대 【제안】
**작은 점프대**: 밟으면 위 속도 15 m/s. 방향 조작은 공중 조종으로. 착지 쉼터가 넓고 보이게(4절). 연속으로 쓰면 구간 한 칸을 빠르게 올라가는 안전 보너스.

**발사대(대포 모양, 통나무 위에 올린 큰 술통 `barrel_large` 형태)** — 하이리스크·하이리턴
1. 위에 올라서면 **충전**이 시작된다(막대·빛이 차오름, 0.8초에 100%).
2. `Space`(터치는 `점프`)를 누르면 발사. **너무 일찍(60% 미만) 누르면 최소 60% 힘**, 자동 발사는 0.8초 뒤 100%.
3. **힘 = 충전량**. 같은 대포에서 가까운 발판(60~80%)과 먼 발판(100%)을 노릴 수 있다 — 힘 고르기가 숙련도 차이.
4. 발사 방향은 대포 방향으로 고정(수직 속도 27 m/s, 수평 6.5~9 m/s, 위쪽 +12m / 앞쪽 8m 지점이 기본 목표). 비행 중에는 **공중 조종 50%** 로 조정하고, 슬로 모션을 쓸 수 있다.
5. 비행 중에는 매달리기(`E`)로 착지 발판 모서리를 잡아 살릴 수 있다 — 한 뼘 모자랄 때의 구원.
6. 착지가 작고(3m×3m) 놓치면 마지막 깃발로 추락(4절 6항) → **리스크 = 지금까지 번 시간**, **리턴 = 40~60초 단축**.
7. 발사 궤적 점선과 목표 지점 표지는 항상 보인다. 접근 중인 어려운 길을 못 넘으면 발사대에 닿지도 못한다.
8. 도달 검사(9절)가 **모든 힘에서의 궤적**을 확인한다: 100% 에서 목표 착지, 60~80% 에서 다른 목표(또는 낙하), 천장·장애물 충돌 없음.

- **오른쪽 아래**: **슬로 게이지**(작은 막대, 비었을 때 깜빡임). 터치 버튼은 2-2 위치.

## 9. 검사 (화면 없는 규칙 코드 + 도달 검사)

- 규칙 엔진 `ts/games/43.tower-climb/43.climb-rules.ts` 는 **화면을 모른다**: 캡슐·충돌 상자·이동·점프·잡기·사다리·점프대·발사대·이동 발판·시간 배율 계산만 한다. 같은 입력이면 항상 같은 결과.
- `node tools/climb-unit.js`: 점프 높이·거리·코요테·점프 예약·경사 미끄러짐·매달리기·작은 점프대(높이 4m)·발사대 힘별 궤적·**슬로 모션 배율에서 같은 입력 → 같은 궤적**.
- **`node tools/climb-reach.js` — 도달 검사(가장 중요)**:
  - 모든 구간에 시작부터 깃발까지 **슬로 없이** 가는 **쉬운 길**이 최소 1개 있다(연속 점프 5회 이하).
  - 모든 점프의 필요 거리 ≤ 최대 거리의 0.9(구간별 상한 4절 4항, 95% 초과 금지).
  - 발사대: 100% 힘 궤적이 목표 착지 발판 안에 들어가고, 다른 힘 단계의 결과가 정의돼 있으며(착지 또는 낙하), 접근하는 어려운 길이 도달 가능.
  - 움직이는·무너지는 발판은 주기 전체를 돌려 검사.
- `node tools/climb-sim.js`: 간단 행동 규칙으로 5천 번 시뮬레이션해 깃발 도착 비율·평균 시간 보고.
- 모두 통과해야 푸시한다. 푸시 뒤에는 사이트 파일 일치까지 확인하고 보고한다.

## 10. 성능 (3D 성능 지침, 기준 SM-T733 터치 60fps)

- **구간 단위 그리기**: 탑을 30m 구간으로 나눠 **현재 구간 ±1 구간**만 장면에 둔다(셰이더 재컴파일 없이 붙이고 떼기). 1단계는 구간 1 뿐이라 전부 올라가 있다.
- **InstancedMesh**: 같은 모델(통나무·바위·나무)은 구간별 셀로 나눠 인스턴싱, `frustumCulled` 켬.
- **그림자**: 캐릭터 주변 한 영역만, 해상도 1024. **조명**: 방향광 1 + 반구광 1, 점·스포트 없음. 빛나는 표지는 `MeshBasicMaterial`.
- **화질 자동 조절** `QualityGovernor`(배율 0.25씩 1.0까지 → 블룸 끄기 → 그림자 줄이기). 터치 배율 상한 1.25~1.5. 단계·저장 키는 24·31번.
- **첫 사용 끊김 없애기**: 카운트다운 동안 쓸 재질·이펙트(먼지·착지·슬로 비네트·발사 점선)를 한 번 그려 본다. 게임 중 `clone`·`new` 금지(풀링).
- 텍스처 2048px 이하. 그리기는 `requestAnimationFrame`. `&fps` 로 확인.

## 12. 만드는 순서 (두 단계)

### 1단계 — 구간 1 완성 + 사이트 업로드
1. 이 사양서 확정(13절 답).
2. 규칙 엔진 + `climb-unit.js` 통과(이동 7 m/s·점프·점프대·발사대·슬로 배율 수치 확정).
3. 구간 1 레벨 데이터(3-4절)와 `climb-reach.js`·`climb-sim.js` 통과.
4. 화면: 조작(키보드·터치), 카메라, 캐릭터·애니메이션, HUD(슬로 게이지), 시작·결과 화면, 3D 배경, 효과음, 기록·계정.
5. 갤럭시탭(`?c=test`) 터치 60fps 측정(제어판 렉 진단 `SM-T733`) 후 화질 단계 조정.
6. **등록**: `초기데이터.json` 에 `towerclimb` 추가(title·url·memo·order·open·units·unitsSet), `pwsh ./링크제목맞추기.ps1`, `데이터베이스규칙.json` 점수 상한 한 줄, `.ts` 와 컴파일 `.js` 같이 커밋·푸시, 사이트 파일 일치 확인. 학생에게는 선생님이 제어판에서 반별로 연다.
- **1단계 완료 기준**: ① 도달 검사·단위 검사 통과 ② 구간 1을 처음부터 끝 깃발까지 내가 직접 플레이로 완주(쉬운 길·발사대 둘 다) ③ 터치 한 상태로 60fps 근처 ④ 콘솔 오류 없음(404 포함) ⑤ 기록 저장·표시 확인 ⑥ 배포 확인.

### 2단계 — 구간 2~7 추가 (구간마다 반복)
순서 2→7. 각 구간: 새 요소 클래스(3-2 표 "처음 나오는 요소") → 구간 데이터 → `climb-reach.js` 통과 → 터치 성능 확인 → 커밋·푸시·배포 확인. 구간 7 이후: **전체 클리어 시간 기록(`towerclimbtime`) 도입**, 도전 모드·같은 반 유령 후보 검토.
