# 30번 캐릭터별 스킬·공격 순간 프레임 저하 수정 지시서 (2026-11-05)

새 세션이 이 파일 하나만 읽고 작업을 이어갈 수 있게 쓴 지시서다. 작업 전에 `CLAUDE.md` 와 `docs/30.team-battle/30.team-battle-notes.md`(특히 "프레임 단계 진단"·"렉 개선 빌드 표시"·5-4·9·10절)를 읽는다. 항상 한국어로 답하고, 변경은 커밋·푸시까지 한다(`&test` 통과 + `&sim` 해시 확인 후).

## 1. 배경과 이미 끝난 것

- 갤럭시탭 S9 에서 스킬을 쓸 때마다 최저 프레임이 20 으로 떨어졌다. 원인은 글자·체력바를 그리는 겹침 캔버스(`Canvases.overlay`) 크기였다. 터치 기기에서 이 캔버스 픽셀 수를 70만으로 제한해(`CameraRig.overlayAreaCap`) **마리나는 전체화면·스킬 사용에서도 60/60** 이 됐다(2026-11-05, 커밋 `da033cb`). 닉네임이 살짝 흐려지는 것은 선생님이 받아들였다("프레임이 더 중요"). **겹침 캔버스 배율은 다시 건드리지 않는다.**
- 3D 그림 해상도(`&pix=`)는 원인이 아니었다.
- 이제 남은 것은 **캐릭터별로 특정 순간(처음 스킬 사용, 포탑이 사라질 때 등)에 생기는 순간 끊김**이다.

## 2. 진단 도구(이미 있음, 주소 끝에 붙인다)

- `&fps`: 초당 화면 수(평균·최저) + 그 아래 **프레임 단계 진단**(`FramePhaseMeter`, `services.phases`)이 블루 킬 상자 왼쪽에 뜬다.
  - 두 줄: `최악 NNms (코드 a, 나머지 b)` / `세계 · 전송 · 방장 · 그림 · 화면` (ms).
  - **코드** = 한 프레임 안에서 게임 코드가 쓴 시간(세계 갱신 `world`, 서버 전송 `net`, 방장 처리 `host`, 그리기 `render`, 화면 갱신 `hud`).
  - **나머지** = 프레임 코드 밖 시간: GPU 대기, 입력·Firebase 콜백 처리, 메모리 정리(GC), 브라우저 합성. 코드 숫자가 작은데 나머지가 크면 **GC·GPU·합성·콜백**이 원인이다.
  - 최악 프레임은 4초 동안 유지된다. 프레임 칸 왼쪽에는 지금 쓰는 실험 주소 꼬리가 뜬다(`&test&fps&ov=1` 꼴, `&fps` 외 값이 있을 때만).
- `&nowave`(해일 그림만 끔), `&pix=값`(3D 해상도), `&ov=값`(겹침 캔버스 배율, 터치 제한을 무시).
- 이 컴퓨터(M2)는 GPU·CPU 가 빨라 **나머지(GPU·GC) 문제는 재현되지 않는다.** 하지만 "처음 쓸 때 코드가 200ms" 같은 **코드 시간 문제는 이 컴퓨터에서도 보인다.** 브라우저 연습모드에서 `&sim` 주소 + 임시 `window.__svc = services; /*TEMPDUMP*/`(`TestBridge.start` 의 `TB_SIM` 줄 끝, 확인 뒤 반드시 제거)를 두고, 자바스크립트로 `services.<뷰>.<메서드>` 를 `performance.now()` 로 감싸 2ms 넘는 호출을 모으면 첫 사용 비용을 이 컴퓨터에서 잴 수 있다.
- 실제 효과는 선생님이 갤럭시탭 S9 에서 `&fps` 로 다시 재서 확인한다. 고친 뒤 선생님께 어떤 주소로 어떻게 재면 되는지 알려 준다.

## 3. 선생님이 모든 캐릭터를 한 번씩 재서 보고한 현상 (S9, 전체화면)

숫자는 ms. 평상시 코드는 대부분 7~9 이다.

**처음 한 번만 크게 튀는 것(첫 사용 비용 — 미리 만들어 두기/예열 대상)**
- 거신: 처음 스킬을 쓸 때 순간적으로 프레임이 크게 떨어지고 **코드가 200 넘게** 오른다.
- 선봉장: 스킬 사용 시 ms·그림이 크게 오른다. **그림이 첫 스킬에서 50**까지 오르다가 두 번째부터 낮아진다.
- 창술사: 처음 스킬에서 그림이 45(평소 7, 두 번째 9, 세 번째부터 8).
- 네크로: 평상시 8 인데 처음 스킬에서 **200**까지 오르고, 이후로도 스킬 때마다 40 정도로 높다.
- 공학자: 처음 포탑 설치 때 코드·그림이 20 정도, 몇 번 하면 문제 없음.

**쓸 때마다 반복되는 것**
- 드루이드: 스킬 사용 시 40ms, 코드 9 인데 **나머지가 크다**. 그림 20, 세계 1, 최저 프레임이 30 까지 내려갈 때가 있다.
- 얼음술사: 스킬 사용 시 40ms, 나머지 30 정도, 그림은 높지 않다.
- 클레릭: **기본 공격으로 회복할 때** 나머지가 30 정도, 프레임이 종종 30 으로 떨어진다.
- 공학자: **포탑이 사라질 때** 나머지가 순간적으로 20 늘고, 포탑 설치 때도 나머지가 잠깐 늘어난다.
- 궁수: 스킬 사용 시 나머지가 순간적으로 늘어난다.
- 뇌전사수: 기본 공격과 스킬 사용 중 나머지 +20, 스킬 중에는 세계도 5.
- 주술사: **패시브(저주 폭발)가 터질 때** 나머지가 20 정도 오른다.
- 투척병: 순간적으로 나머지가 20 정도 나오는 일이 종종 있다(어느 동작인지 특정 못함).
- 검무희: 기본 공격 시 나머지 +10.
- 은신자: 스킬 사용 시 몇 초 동안 나머지 +20.
- 자객: 원인을 알기 어렵고 가끔 나머지 30 정도.

**문제 없는 것(기준으로 삼는다)**
- 점성술사: 이펙트가 크고 화려한데 프레임·ms 모두 평상시와 같다. **이 캐릭터의 효과가 만들어진 방식(공용 재질·풀, 효과 물체를 미리 만들어 두기, 지오메트리 공유 등)이 이상적인 본보기다.** 문제가 있는 캐릭터를 같은 방식으로 맞춘다.
- 마리나: 이번 겹침 캔버스 수정 뒤 전체화면·스킬 사용에서도 60/60.

## 4. 원인 가설과 접근 순서

1. **코드가 크고 첫 번째만 큰 것(거신·네크로·선봉장·창술사·공학자)**: 스킬을 처음 쓸 때 지연 생성되는 것들(`new THREE.*Geometry/Material/Texture`, 모델 `clone`, `makeXxxVis`, 캔버스 텍스처 그리기, 셰이더 첫 사용)이 원인일 가능성이 크다. `ShaderWarmup`(`warmEffects`·`sampleViews`)이 일부 효과만 예열한다 — 거신·네크로·선봉장 등 빠진 효과를 예열 목록(`sampleViews` 의 `makers`)에 추가하거나, 경기 시작(`matchStarting`) 때 효과 물체·재질·텍스처를 미리 만들어 풀(`EffectMaterialPool`, 각 뷰의 `free` 목록)에 넣어 둔다. 기존 풀·예열 방식을 따르고 새 전역을 만들지 않는다.
2. **코드는 작은데 나머지가 큰 것(드루이드·얼음술사·클레릭·주술사·뇌전사수·은신자 등)**: 매번 새 물체·지오메트리·재질·캔버스를 만들고 지우는 **메모리 정리(GC)·`dispose`** 이거나, 투명 물체가 크게 겹치는 **GPU 채움**, 또는 DOM·겹침 캔버스(`Hud2D`, 떠오르는 글자 `strokeText`) 처리일 수 있다. 효과가 끝날 때 `dispose()` 하지 말고 풀로 돌려 쓰는지, 효과가 매번 `new Float32Array`·배열·객체 리터럴을 만드는지 본다. 효과가 사라질 때 나머지가 튀는 것(공학자 포탑)은 제거 때의 `dispose`·`scene.remove`·GC 를 의심한다.
3. 캐릭터마다 **무엇이 매번/처음에 만들어지는지** 먼저 코드를 읽고(캐릭터 클래스의 `cast`·`onStrikeShown`·`makeXxxVis`·`FieldEffects`·`EffectIntake`·각 `*View` 클래스), 이 컴퓨터에서 계측 가능한 것은 계측으로 숫자를 확인한 뒤 고친다. 추측으로 한꺼번에 바꾸지 말고 캐릭터 하나씩 고쳐 확인한다.
4. 겹침 캔버스에서 글자·체력바를 그리는 비용(`strokeText` 등)을 더 줄일 여지가 있으면(떠오르는 피해 글자 수 제한, 글자 캐시) 같이 본다. 단, 배율은 건드리지 않는다.

## 5. 게임 규칙 변경 2건 (프레임 문제와 별개, 시뮬레이션 결과가 바뀐다)

- **공학자 포탑 탄알 출발 위치**: 지금은 탄알이 **포탑 뒤(포탑 중심 근처)** 에서 출발한다. **포탑 총구에서 출발**하도록 고친다. 시각(탄알 그림)과 판정 시작점을 총구 위치와 맞추고, 총구가 벽 안쪽·벽 뒤로 나가 판정이 어긋나지 않는지 확인한다(`EngineerType`·포탑 `turrets`·`tshot` 효과·`services.models` 의 `muzzle` 계산 참고). 관련 테스트를 고치거나 추가한다.
- **궁수 스킬 사용 중 기본 공격 금지**: 궁수가 스킬(연사)을 쓰는 동안(`mkCount` 발사 중) 기본 공격을 할 수 없게 한다. 다른 캐릭터의 "스킬 중 기본 공격 불가"(`cannotAttack`, `isRooted` 계열)와 같은 방식으로 구현하고, 스킬 설명·카드 글을 5-4 규칙에 맞게 고치고, 봇(`BotBrain`)이 스킬 중에 기본 공격을 시도하지 않게 한다. 관련 테스트를 고친다.

이 두 가지는 규칙·밸런스를 바꾸므로 `&sim` 해시가 달라진다. 5,000판 시뮬레이션 결과·해시 기준값과 `docs/30.team-battle/30.team-battle-notes.md`(승률 줄, 해당 캐릭터 항목, `&sim` 해시)를 같이 갱신하고, 시뮬레이션을 돌릴지는 선생님께 먼저 물어본다(선생님이 따로 돌리겠다고 한 적이 있다).

## 6. 지켜야 할 것

- `CLAUDE.md`: 새 코드는 객체지향(전역 변수·맨몸 함수 금지), 게임 파일에는 주석 금지, 변경은 커밋·푸시까지, 브라우저 확인은 `?c=test` 주소.
- 시각만 바꾸는 수정은 시뮬레이션 결과(해시)를 바꾸지 않는다. 바뀌면 의도한 변경인지 확인한다.
- 고칠 때마다 `&test`(423개 기준) 통과 확인. 임시 계측 코드(`TEMPDUMP`·`__svc`)는 확인 뒤 반드시 지운다.
- 캐릭터별로 고친 뒤 선생님이 S9 에서 `&fps` 로 다시 잴 수 있게, 어떤 동작에서 어떤 숫자를 보면 되는지 안내한다(안 쓸 때와 쓸 때의 평균/최저, 코드·나머지·그림).
- 노트에 캐릭터별 원인과 고친 방법, 예열 목록에 추가한 효과를 적는다. 렉 개선 빌드 표시(`PerfProbe.BUILD`)는 렉 관련 수정이므로 `lag7` 로 올린다.
