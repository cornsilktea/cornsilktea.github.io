# 41번 야구 1대1 대전 — 사양서 (v0.2, 2026-11-12)

1대1 3D 야구. 한 명은 투수, 한 명은 타자로 겨루고, 점수가 높은 쪽이 이긴다. **지금 버전은 "9회 초·말, 1이닝"** 만 하지만 3이닝·9이닝 경기, 여러 타자, 투수 교체, 직접 주루·수비까지 **코드를 뜯지 않고 늘릴 수 있게** 만든다(1.1절).
이 문서는 다른 Claude Code 세션이 그대로 만들 수 있도록 쓴 구현 사양서다. 선생님이 읽고 고친 뒤 확정한다.

**표식**
- **【보충】** 선생님이 말씀하지 않아서 내가 채운 부분. 틀렸으면 고쳐 달라고 하면 된다.
- **【확인】** 선생님이 정해야 하는 값. 기본값(★)을 적어 두었다. 정하지 않으면 ★로 진행한다. 모음은 20절.
- 수치는 모두 **초기값**이다. 17절 시뮬레이션으로 분포를 본 뒤 선생님이 확인하고 고친다(3D 작업에 들어가기 전에 먼저).
- 야구 규칙·수비 분담은 일반적으로 알려진 정석으로 썼다. 구현 세션이 시작할 때 9.5절 수비 표를 웹에서 한 번 더 대조한다.

## 0. 동작 시연과 동작 품질 요구 (실제 제작 때 반드시 반영)

### 0.1 시연 페이지 (참고용 — 다시 만들지 않는다)
**파일**: `docs/41.baseball-duel/41.baseball-motion-demo.html` (KayKit 캐릭터 + 기존 애니메이션 팩만 사용). 미리보기 서버(`.claude/launch.json` 의 `static`)로 열면 세 장면(① 투구→스윙→타구, ② 땅볼→유격수 포구→1루 송구 아웃, ③ 플라이 포구·리터치·태그업·홈 슬라이딩)이 반복 재생된다.
**이 시연은 "KayKit 기존 클립만으로는 부족하다"는 것을 확인하는 데 쓴다. 고쳐서 쓰지 않고, 아래 0.2절의 결함을 실제 제작(M0a)에서 처음부터 제대로 만든다.** 시연 아래쪽의 설명 자막(`베이스를 밟고 환호` 같은 것)은 시연용일 뿐이며 **실제 게임에는 그런 설명 자막·환호 연출 문구가 없다**(경기 화면에 나오는 글자는 5절의 HUD·판정 토스트·결과 패널뿐).

### 0.2 시연에서 확인된 결함 → 실제 제작에서 지켜야 할 요구 (2026-11-12 선생님 지적)
**공통 원칙 `ActionSync`**: 모든 동작은 **키 프레임 메타데이터**(릴리스 / 접촉 / 포구 / 태그 프레임이 클립의 몇 초 지점인지)를 클래스에 두고, **사건 시각에서 거꾸로 계산해 동작 시작 시각을 정한다**(`시작 = 사건 시각 − 키 프레임 시각`). "공이 도착한 뒤에 동작을 시작"하는 방식은 금지. 자동 검사 `tools/baseball-motion-sync-check.js` 가 모든 동작에서 `|키 프레임 시각 − 사건 시각| ≤ 16ms(1프레임)` 인지 확인하고, 시험 페이지(`.claude/baseball-test.html`)에서 눈으로 확인한다. 선생님 확인 전에는 M1 이후로 넘어가지 않는다(M0a 완료 조건).

| 결함 | 요구 |
|---|---|
| **스윙이 왼쪽 타석(좌타)처럼 보임** | 우타자는 심판 시점에서 **왼쪽(3루쪽) 타석**에 서서 가슴이 홈플레이트를 향하고, 투수쪽 어깨는 **왼쪽 어깨**다. 스윙은 오른쪽 어깨 뒤(배트가 오른쪽 어깨 위·뒤)에서 시작해 몸 앞쪽에서 거의 수평으로 돌고 왼쪽 어깨 위로 팔로스루한다. **좌타는 이것의 거울**(`HandednessMirror` 한 곳에서 처리, 클립을 뒤집지 않고 절차 포즈의 좌우 부호를 바꾼다). 단위 확인: 우타·좌타 각각 접촉 순간 배트 헤드가 홈플레이트 위 존 안에 있고 몸 앞쪽(투수쪽)에 있는가. |
| **스윙 모션이 부실** | `Melee_2H_Attack_Slice`(칼 휘두르기)를 쓰지 않는다. **절차 포즈 `BatSwingPose`** 로 단계를 직접 만든다: ① 스탠스(양발 어깨 너비, 무릎 살짝 굽힘, 배트를 뒤 어깨 위로) ② 로드(체중을 뒷발로, 배트 약간 뒤로 당김) ③ 스트라이드(앞발 내디딤) ④ 회전(엉덩이 → 몸통 → 팔 → 배트 순서로 시간차를 두고) ⑤ **접촉(배트 헤드가 공 위치와 5cm 이내)** ⑥ 팔로스루(배트가 반대 어깨 위로). 전체 0.5~0.6초, **접촉 프레임 시각을 메타데이터로 두고 `SWING_DELAY`(8.1절)와 같게** 맞춘다. 헛스윙·빗맞음·번트용 변형이 같은 클래스의 인자로 나온다. |
| **배트가 제대로 만들어지지 않음** | 배트는 가는 선이 아니라 **실제 야구 배트 비율**: 길이 0.86m, 손잡이(가늘고 테이프 질감) → 점점 굵어지는 몸통(배럴, 최대 지름 약 6.5cm) → 끝 캡. `LatheGeometry` 단면을 이 비율로 만들고 나무 결·손잡이 테이프 텍스처를 입힌다. **두 손이 손잡이 위에 붙는다**: 오른손은 손슬롯에 부착, 왼손은 손잡이 아래쪽에 닿도록 **양손 위치 보정(`BatGrip` 에 손슬롯 로컬 축·오프셋 상수)**. 스윙 내내 두 손이 배트에서 떨어지지 않는다. 시험 페이지에서 확대해 눈으로 확인한다. |
| **투구 때 공이 손에서 나가지 않음** | 공은 **투수 손 뼈에 붙어 있다가 릴리스 프레임에 분리**된다(`BallActor.attachTo(손 뼈)` → 릴리스 시각에 `detach`, 그 순간 손의 속도 방향으로 출발). 공 첫 위치는 **릴리스 프레임의 손 위치**다(공중 임의 좌표 금지). 투구 전 공을 글러브/손에 쥔 모습이 보인다. `releaseAt`(7.6절)과 릴리스 프레임 시각이 정확히 같다. |
| **유격수 땅볼 포구가 공이 잡힌 뒤에 나옴** | **포구 모션이 공이 도착하기 전에 시작**해, 글러브가 **지면 근처에서 공과 만나는 프레임(포구 프레임)이 공 도착 시각과 같다**. 몸을 낮추는 동작은 도착 약 0.3~0.4초 전부터. 공은 도착 순간 글러브 손에 붙는다(`attachTo`). 뜬공·송구 포구도 같다(글러브를 미리 올리고 공이 글러브에 들어올 때 잡힘). 글러브 소품(왼손)을 만든다. |
| **송구가 너무 포물선** | 9.6절 `송구 궤적` 규칙(낮은 라인 송구). |
| **중계 장면에서 중계 수비수가 안 보임** | 10절 `RelayShot` 규칙(던지는 수비수·중계 수비수·받는 수비수·공이 모두 화면 안). |
| 슬라이딩·태그·주루 | 슬라이딩은 `SlidePose`(절차 포즈: 달리다 한쪽 다리를 접고 한쪽 다리를 앞으로 뻗어 엉덩이로 미끄러짐, 속도 감쇠, 먼지), 태그는 글러브가 주자 몸에 닿는 프레임에 맞춘다. 달리기는 기존 `Running_A` 에 팔 흔들기·몸 기울임을 속도에 맞게 보정. |
| 그 밖 | 시연의 헬멧·캐릭터 색은 임시. 실제는 공용 캐릭터 외형 위에 팀 유니폼·모자(11.0절). |

**핵심 설계 원칙**
1. **지금의 조작은 최소**: 타자는 **스윙 한 가지**, 투수는 **구종 고르기 + 위치 고르기**. 수비·주루·송구·중계는 전부 자동(항상 정석 플레이, 실수 없음 — 단 9.6절 수비 실책 5%만 예외로 켜 둠).
2. **미래 조작은 열어 둔다**: 타자의 노려치기·컨택하기·번트, 주루 직접 조작, 수비 직접 조작(송구·더블플레이)을 나중에 넣을 수 있도록 **"입력 한 가지 = 클래스 하나"** 로 만든다(1.1절). 지금은 만들지 않는다.
3. 자동으로 진행되는 장면(수비·주루·중계)도 화면에서 다 보여 준다.
4. 규칙 엔진(수치 계산)은 화면을 모른다. 같은 엔진이 AI 대전·연습·온라인 대전·시뮬레이션 검사에 모두 쓰인다.
5. 결과는 서버에 **한 번 쓰이면 바뀌지 않는다**(13절).
6. 새 코드는 TypeScript + 클래스, 게임 파일에 주석 없이 이름으로 설명, 전역 변수·맨몸 함수 금지.

### 1.1 확장 지점 (지금은 한 가지 구현만, 나중에 구현을 더하면 된다)
"지금"은 현재 만드는 것, "나중"은 만들지 않지만 **자리를 만들어 두는 것**이다. 확장은 규칙 엔진의 `if/else` 를 늘리는 방식이 아니라 **인터페이스 + 구현 클래스를 하나 더하는 방식**으로 한다.

| 확장 대상 | 지금 | 나중 | 자리(인터페이스) |
|---|---|---|---|
| 경기 길이 | 9회 1이닝(초·말) | 3이닝(7~9회), 9이닝 | `MatchFormat {startInning, inningsToPlay, extraInnings:{이닝별 시작 주자(10회 1·2루, 11~15회 만루), maxInning:15}, walkOff, skipBottomWhenLeading}` 와 프리셋 `OneInningFormat`·`ThreeInningFormat`·`FullGameFormat`. 규칙·HUD·결과표·통계는 이 값만 읽는다(회차를 코드에 박지 않는다) |
| 타자 행동 | `SwingAction` 하나 | 노려치기·컨택하기·번트 | `BatterAction` 인터페이스(`kind`, `timingRule(pitch)`, `resolve(ctx)`), `BatterActionSet`(허용 행동 목록). 타격 판정 `ContactModel` 은 행동 종류별 규칙 객체를 받는다 |
| 투수 행동 | 구종 + 위치 | 견제, 피치아웃 | `PitcherAction`, 같은 방식 |
| 주루 | `AutoBaseRunning`(자동) | 직접 조작, 도루, 리드 | `BaserunningController` 인터페이스. `AutoBaseRunning` 외에 `ManualBaseRunning` 을 더하면 된다. `PlayScript` 는 `runnerDecision` 이벤트를 받는 구조 |
| 수비 | `AutoFielding`(자동) | 송구·더블플레이 직접 조작 | `FieldingController` 인터페이스, 같은 방식 |
| 사건 종류 | 투구·타격 | 도루, 견제, 폭투, 포일, 번트, 고의사구 | `PlayEvent` 종류를 `Map<종류, 처리 클래스>` 로 등록(`EventHandlerRegistry`). 처리 클래스를 더하면 종류가 늘어난다 |
| 타자 | 1명(같은 캐릭터가 계속 선다) | 3명, 9명(타순) | `Lineup`(슬롯 목록, 현재 타순). 지금은 슬롯 1개를 순환 |
| 투수 | 1명, 체력 없음 | 선발·중간계투·마무리, 체력 소모 후 교체 | `PitcherRoster {starter, relievers, closer}`, `PitcherStamina` 인터페이스(지금은 `NoStamina`), `SubstitutionPolicy`(지금은 `NoSubstitution`), 교체 사건 `PitcherChange` |
| 대타·교체 | 없음 | 대타, 대수비 | `SubstitutionPolicy` 가 같이 맡는다 |
| 구장 | 기본 1구장 | 여러 구장, 구장 부품 조합 | `BallparkSpec {id, fence(FenceProfile), wallHeight, parts[]}`, `BallparkRegistry`. 규칙 엔진은 `FieldDimensions` 인터페이스로만 거리를 읽는다(9.1절) |
| 실책 | 내야 땅볼 5% | 끄기·확대 | `ErrorPolicy`(`InfieldGroundBallErrorPolicy(0.05)` / `NoErrorPolicy`). 방 규칙 한 줄로 교체 |
| 능력치 | 9포인트 3종 | 종 늘리기·타순별 설정 | `AbilityAllocator`(합계·최소·최대·항목 목록을 설정으로 받는 공용 클래스, 투수·타자 공용) |

규칙: **`1.1` 의 "나중"은 지금 만들지 않는다.** 단지 지금 짜는 코드가 위 인터페이스를 거치게 하여, 나중에 `Manual…`·`…Format` 클래스만 더해도 되게 한다. 구현 세션은 각 인터페이스에 현재 구현이 하나뿐이어도 인터페이스를 만든다. 선생님이 새 기능을 요청하면 이 표의 자리에 구현을 더하는 작업으로 시작한다.

## 3. 경기 규칙

### 3.1 한 판의 구조
- 선수 두 명. **추첨 없음: 방장이 말(후공) 공격, 손님이 초(선공) 공격.** 방 화면·대결 화면에 미리 표시한다. 랜덤 매칭에서는 방을 만든 쪽이 방장이다.
- 경기 형식은 `MatchFormat` 으로 정한다. **지금은 `OneInningFormat`: 9회 초(손님 타격) → 9회 말(방장 타격), 끝.** 점수가 높은 쪽 승리.
- **동점이면 연장 승부치기**(초·말을 한 번씩, 매 이닝 아웃 0개로 시작):
  - **10회: 무사 1·2루**에서 시작.
  - 10회에서 승부가 안 나면 **11회부터는 무사 만루**(1·2·3루)에서 시작. 11회 이후는 계속 무사 만루.
  - **15회까지 가도 동점이면 무승부.**
  - `MatchFormat.extraInnings = { 10: [1,2], 11~15: [1,2,3], maxInning: 15 }` 로 둔다(숫자만 바꾸면 규칙이 바뀐다).
- **끝내기(선생님 확정)**: 말 공격에서 후공이 앞서는 순간 경기 즉시 종료(`walkOff:true`). **끝내기 문구를 출력한다**: 결정타 종류에 따라 토스트·`MatchEndBanner` 에 `끝내기 홈런!` / `끝내기 안타!` / `끝내기 볼넷!` / `끝내기 희생플라이!` 등(5.4절). 종료 즉시 득점 주자 이후 연출은 생략하되 득점 주자가 홈을 밟는 장면까지는 보여 준다. 후공이 이미 앞선 채 초가 끝나면 말은 하지 않는다(`skipBottomWhenLeading:true`). 9회 시작은 0:0이라 1이닝 경기에서 건너뛰기는 일어나지 않고, 3이닝·9이닝으로 늘릴 때 쓰인다.
- **득점 상한 없음.**
- 공격은 타자가 아웃 3개가 될 때까지 계속 타석에 선다. 지금은 **같은 타자(학생 캐릭터)가 계속 서고**, 주자도 같은 외형(팀 모자로 구분)이다. 타순 확장은 1.1절.
- 투수는 하프 이닝 동안 교체 없음, 체력 없음(자리는 1.1절).

### 3.2 카운트·아웃 (실제 야구와 동일)
- 스트라이크 3개 = 삼진. 볼 4개 = 볼넷(타자 1루 진루, 만루면 밀어내기 1점).
- 아웃 3개 = 공수 교대.
- 파울: 스트라이크 2개 미만이면 스트라이크 +1. **2스트라이크 이후 파울은 카운트 변화 없음**. 파울 플라이를 잡으면 아웃.
- 헛스윙 = 스트라이크. 스윙하지 않은 공은 존 통과 여부로 판정한다.
- **판정은 흔들림 없이 결정적**: 공의 중심 `(u,v)` 가 `|u| ≤ 1` 그리고 `|v| ≤ 1` 이면(경계 포함) 스트라이크, 아니면 볼. 심판 오차 없음.
- **사구(몸에 맞는 공)는 영구히 없다.** 조준 범위가 처음부터 타자 몸 쪽으로 갈 수 없게 제한된다(7.5절 조준 제한). 보크도 없다.
- **희생플라이**: 1사 이하 3루 주자가 외야 플라이 아웃 때 태그업으로 득점하면 희생플라이(타수 불인정).
- **득점 인정**: 3아웃째가 포스 아웃이거나 타자 주자의 1루 도달 전 아웃이면 그 타구에서 3아웃 이전에 홈을 밟은 주자도 **득점 불인정**. 태그 아웃이면 3아웃 이전에 홈을 밟은 주자는 인정.
- **인플레이 중 포스아웃·병살·태그업·리터치**는 9.5~9.7절 정석대로 자동 처리한다(주자·수비 모두 실수 없음).
- **인필드 플라이**는 규정대로 적용(9.14절).
- **수비 실책**: 내야 땅볼에서만 5% 확률(9.6절). 코드 한 줄로 끈다(`ErrorPolicy`).
- 지금은 없지만 나중에 넣을 수 있게 자리를 둔 것: 번트, 도루, 견제, 폭투, 포일, 고의사구, 대타·교체(1.1절).

### 3.3 시간 제한과 시계 【확정·보충】
| 대상 | 제한 | 시간 초과 시 |
|---|---|---|
| 투수 구종+위치 선택 | **12초** (남은 **5초부터 숫자를 빨간색으로 강조**, 4·3·2·1초는 커졌다 작아지는 펄스) | 자동 투구: 직전과 같은 구종, 위치는 존 중앙 아래쪽 랜덤. 연속 3회면 "자리 비움" 표시, 연속 5회면 기권 |
| 타자 스윙 | 공이 날아오는 동안만 | 안 누르면 "치지 않음" |
| **공수 교대 장면** | **2초 고정**(건너뛰기 없음) | — 5.6절 |
- **시계는 방장 한 곳뿐이다.** 방장 기기가 `turn` 에 서버 시각 기준 마감 `deadline` 을 쓰고, 손님 기기는 그 값에서 `서버 현재 시각`을 빼서 남은 시간을 **표시만** 한다. 손님 기기가 따로 시간을 재거나 자동 투구를 만들지 않는다(타이밍 어긋남 방지). 마감 뒤 자동 처리는 방장이 기록한다(0.3초 여유).
- 연습·AI 판은 내 기기가 방장이다.
- 새로고침해도 마감 시각은 늘어나지 않는다(서버 시각).

### 3.4 진행 속도
**한 판 권장 3~5분**(넘어도 된다). 투구 사이클 = 투수 선택 최대 12초 + 투구 동작 0.9초 + 비행 1~1.4초 + 판정 1.5초 + (인플레이 장면 3~10초). 메뉴에 `연출 빠르게(×1.5)` 토글(자기 화면 속도만, 규칙 시간 불변)과 `인플레이 연출 건너뛰기`(자기 화면만).

## 4. 모드

| 모드 | 상대 | 통계 기록 | 방 코드 |
|---|---|---|---|
| 일반(사람 대결) | 사람 (방 코드 입장 또는 랜덤 매칭) | 기록함 | 있음 |
| 일반 + AI | 빈 자리에 AI 추가 | **기록 안 함** | 있음(관전 입장 가능) |
| 타격 연습 | AI 투수, 내가 1이닝 타격 | 기록 안 함 | 없음 |
| 투구 연습 | AI 타자, 내가 1이닝 투구 | 기록 안 함 | 없음 |

- 연습은 서버 방 없이 **내 기기에서만** 진행한다. **새로고침 이어하기**는 기기 저장소(`sessionStorage`)에 로그를 쌓아 지원한다.
- 연습 결과 창: 타격(득점·안타·최장 비거리·평균 타구 속도·홈런), 투구(실점·삼진·볼넷·투구 수·스트라이크 비율·구종별). 다시 하기 버튼.
- **연습의 기기 최고 기록은 저장하지 않는다**(확정).
- AI 난이도 3종(쉬움 / 보통 / 어려움, 12절). **방장이 방 대기 화면에서 설정**한다(5.2절).
- 일반 + AI 방은 사람 한 명이 방장이고 AI 판정·진행은 방장 기기가 맡는다. 통계·최근 매치·연승 어디에도 남지 않는다.

## 5. 화면 구성과 흐름

### 5.1 초기화면 (30번과 같은 `st-*` 시작 화면)
위에서 아래로: 제목(`야구 1대1 대전`, **부제 없음**) → **실행 카드** → **`📊 내 통계 · 최근 20매치`**(넓은 버튼 하나, `data-account-open="stats"`) → 기록 칸(통계가 있으면 `st-recs`) → 조작 방법(`st-keys`). **규칙 칸(`st-rules`)·규칙 코치 창·"가로로 돌려 주세요" 안내는 없다.**
```
[ 게임 만들기 ]
[ 랜덤 매칭 방 만들기 ]
[ 방 코드 입력 ........ ] [입장]
[ 📊 내 통계 · 최근 20매치 ]
```
- 네 줄의 세로 간격은 모두 10px(`.st-btn margin-top:10px`), 입력칸·빈 안내 줄이 간격을 벌리지 않게 한다.
- **우측 상단**: `선수 정보 만들기` 버튼 하나(좌측 상단은 가드의 `← 목록으로` 자리).
- **우측**: 랭킹 표(15.4절) `BaseballBoardPanel`. 우측 상단 버튼 아래부터 화면 끝까지. 세로 화면이나 좁은 폭에서는 카드 아래로 내려가 접이식(`FoldCard`)이 된다.
- 입장은 하나의 버튼만(관전 전용 버튼 없음). 방에 들어갔다 나오면 입장 칸에 그 방 코드를 미리 채워 둔다.
- **조작 방법 칸**: 타자 `Space`·`Enter`·스윙 버튼, 투수 `Q W E A S`(구종) → 위치 선택 → `Space`·`Enter`·던지기 버튼.

### 5.2 방 화면 (30번 방 화면 모양: 어두운 반투명 카드)
- 상단: 방 코드(크게) + 복사 버튼, 관전자 수.
- **게임 모드** 선택: `일반` / `타격 연습` / `투구 연습`.
- 일반: 두 자리 카드(손님 `초 공격`, 방장 `말 공격` 표기), 카드마다 캐릭터 3D 썸네일·닉네임·준비 상태.
  - 상대 빈 자리: `사람을 기다리는 중` + **`AI 추가`** 버튼. 누르면 같은 자리에 **AI 난이도 선택 3칸**(쉬움 / 보통 / 어려움, 방장만 변경, 시작 전 언제든 바꿀 수 있음)과 `AI 제거` 가 나타난다. 카드에는 `🤖 AI (난이도)`.
  - 방장 `시작` 버튼(자리 둘이 채워져야 활성). 시작하면 대결 화면 → 4초 뒤 경기 시작(`vsAt`).
  - 구장 선택 칸은 구장이 1개인 동안 **숨긴다**(자리만, 1.1절).
  - 선수↔관전 바꾸기 버튼은 둘 수 있다.
- 타격/투구 연습: 방 화면 없이 **모드 선택 카드 한 장**(난이도 선택 + 시작)만 거쳐 바로 시작.
- **우측 상단 `선수 정보 만들기`** 는 방 화면에도 있고 **경기 시작 후에는 숨긴다**.
- 선수 정보(능력치·구종)는 시작 시점에 방에 한 번 기록되고 이후 바뀌지 않는다.

### 5.3 경기 화면 HUD (30번 HUD 틀: `#hudTop`·`LiveScoreboard`·`MatchEndBanner`)
- **위쪽 가운데** 스코어 상자(`.hud-box`): `9회 ▲초 / ▼말`, 두 선수 닉네임·점수, **B S O 점등**, **베이스 다이아몬드**(주자 있는 베이스 주황 `#D97B4F`), 투구 수. 상자 바로 아래 작은 방 코드 `class="room-code-tag"`(`"방 코드 " + code`, 연습·솔로는 빈 글자).
- **왼쪽 카드 = 타자 정보**(가드 `← 목록으로` 아래 46px): 초상화(작게)·닉네임·**능력치 컨택/파워/주루(작은 막대)**·**비율 스탯 4개 `타율 · 출루율 · 장타율 · 홈런 수`**.
- **오른쪽 카드 = 투수 정보**: 초상화·닉네임·**능력치 제구/구위/변화**·**비율 스탯 3개 `평균자책점 · WHIP · 피OPS`**.
  - 비율 스탯은 그 선수 계정의 누적 값(15절). 기록이 없거나 AI·로그인 안 한 선수는 `-`.
  - 핫콜드존이 교사에 의해 켜져 있으면 카드 아래에 3×3 미니 존이 붙는다(15.5절).
  - 카드 폭은 화면의 약 20%, 어두운 반투명, 흰 글씨, 주황 강조선. 좁은 화면에서는 카드가 한 줄로 줄어든다(5.5절).
- **하단**: 내가 투수일 때 구종 버튼 5칸(7.2절)과 오른쪽 아래 `던지기` 버튼. 내가 타자일 때 오른쪽 아래 큰 `스윙` 버튼(엄지로 누르기 쉬운 크기, `touch-action:none`).
- **투구 정보판**(5.4절 TV 중계 스타일), **타이밍 게이지**(8.8절), **판정 토스트**, **결과 패널**(7.8절).
- 우측 상단 `⋯` 메뉴: 나가기, 연출 빠르게, 연출 건너뛰기, 효과음(11.5절).
- 경기 종료: `MatchEndBanner`(승리/패배 문구) → 결과표(14.4절).

### 5.4 투구 정보판 · 타이밍 게이지 · 판정 토스트 【보충】
- **투구 정보판**: 기존 야구 게임 중계 화면처럼 **스트라이크 존 바로 아래**에 `슬라이더  128km/h` 한 줄(구종 이름 + 구속). 공이 홈플레이트를 지난 뒤에만 나타나 1.5초 보인다. 타자·관전자 모두 지난 뒤에만 본다(미리 알려 주지 않음). 투수는 던지는 순간부터 본다. 위치는 홈플레이트 위 3D 존에 붙어 카메라를 따라간다.
- **타이밍 게이지**: 스윙한 뒤 화면 아래 중앙에 가로 막대(`빠름 ◀ 정타 ▶ 늦음`)가 1.2초 나타나 **정타 구간(초록)·양호(연두)·보통(노랑)** 띠와 내가 친 위치 표시(▲)를 보여 준다. 띠 폭은 그 공의 정타 폭 `W`(8.3·8.10절)에 비례해 컨택이 높으면 넓다. 막대 위에는 판정 글자(`PERFECT`/`GOOD`/`EARLY`/`LATE` 대신 한글 `정타`/`좋아요`/`빨라요`/`늦었어요`).
- **판정 토스트**(중앙 위쪽): 한 줄. **글꼴은 `Black Han Sans`(굵은 한글 디스플레이)** 를 쓰고 두꺼운 외곽선 + 기울임(`skewX(-8deg)`) + 팀색 그림자, 크기 `clamp(28px,5vw,56px)`. 글꼴 파일은 저장소 `common/fonts/` 에 두고 불러온다(외부 서버에 의존하지 않음) 【확인 ★】. 내용: "스트라이크!", "볼", "헛스윙", "파울", "삼진 아웃!", "안타!", "2루타!", "3루타!", "홈런!", "병살타", "희생플라이", "인필드 플라이!", "실책", **"끝내기 홈런!"·"끝내기 안타!"·"끝내기 볼넷!"·"끝내기 희생플라이!"** 등. 끝내기는 글자를 더 크게(1.4배) 오래(2초) 보여 준다. 설명 문장은 달지 않는다.
- 타구 정보와 결과는 7.8절 한 곳에 모아 겹치지 않게 그린다.

### 5.5 가로·세로 화면
- 가로(≥ 900px 폭 또는 가로가 더 긴 화면): 3D 화면 전체 + 위쪽 가운데 스코어, 좌우 카드, 하단 조작.
- **세로**: 3D 화면이 위쪽 약 58%, 조작·구종 버튼이 아래 42%. 좌우 카드는 위쪽에서 **한 줄로 합쳐진 작은 카드**(이름 + 비율 스탯 2~3개)로 줄어든다. 구종 버튼은 한 줄 5칸, 위치 선택은 화면 가운데 확대 창.
- 스코어 상자는 가장 위. 구성 요소가 겹치지 않게 `@media (orientation:portrait)` 로 배치를 따로 둔다.
- 확인 크기: 가로 1280×800·1600×900·640×360, 세로 390×844·820×1180. 결과표·대결 막도 같은 크기로 확인.

### 5.6 공수 교대 장면 (2초 고정)
- **구장 탑뷰**로 카메라가 올라가고, 수비 선수·투수·타자가 서로 자리를 바꾸는 모습을 **빠른 재생**(약 ×3)으로 2초 안에 보여 준다. 공격 팀 주자(있었다면)는 사라지고, 새 타자·새 투수가 자기 자리에 선다. 가운데에 작은 카드 `9회 말`.
- 건너뛰기·입력 없음. 서버 진행에 영향 없는 순수 연출이며, 2초가 끝나면 바로 다음 투구 입력이 열린다.
- 구현: `SwapChoreographer`(두 팀 캐릭터 위치 보간) + `HalfInningSwapShot`(탑뷰 카메라).

### 5.7 관전 화면
30번 관전 화면 틀(좌우 선수 카드 `compact`). 관전자는 **두 시점을 고를 수 있다**: ① **투수 시점**(마운드 뒤에서 홈을 봄) ② **타자 시점**(홈플레이트 뒤 심판 위치에서 마운드 방향을 봄). 투구 전후는 선택한 시점, 타구가 맞은 뒤에는 자동 추적 카메라로 따라가고 다음 투구에서 선택한 시점으로 돌아온다. 투구 중 구종·위치는 공이 지난 뒤 공개. 시점 전환 버튼은 화면 아래 가운데.

## 6. 선수 정보 만들기 (창)

`선수 정보 만들기` 버튼(초기화면·방 화면 우측 상단)을 누르면 창이 열린다. 맨 위 `투수` / `타자` 탭(나중에 `타순`·`불펜` 탭이 같은 자리에 붙는다). 창 상단에 현재 캐릭터 3D 미리보기와 `캐릭터 만들기` 버튼(공용 `CharacterMakerDialog.requestOpen()`). 외형은 항상 공용 `PlayerProfile`(`portal_profile_v1`)에서 가져오며 41번에서 따로 저장하지 않는다. 닉네임은 `PlayerProfile.storedNick()`.

### 6.0 구조 (확장 가능)
- 저장 형식 `baseballduel_profile_v2`(기기 `localStorage`): `{ version:2, lineup:[BatterSheet…], pitchers:[PitcherSheet…], ballpark:"main" }`. **지금은 `lineup` 1칸, `pitchers` 1칸(`role:"starter"`)** 만 만든다. 타자 3명·9명, 선발/중간계투/마무리는 칸 수와 `role` 만 늘리면 된다(창은 `lineup`·`pitchers` 배열을 돌며 그린다).
- `AbilityAllocator`: 합계·항목별 최소/최대·항목 목록(이름·아이콘·효과 한 줄)을 설정으로 받는 공용 클래스. 투수 시트·타자 시트가 같은 클래스를 다른 설정으로 쓴다(`PITCHER_ABILITIES`, `BATTER_ABILITIES`).
- 시작 시 방의 자기 자리에 **선수 시트 전체를 한 번 기록**하고 이후 고정. 대결·결과 화면에는 상대의 능력치 숫자만 보인다(구종 선택은 숨김).

### 6.1 투수 탭
**능력치 3개를 위에서 아래로**: 제구 / 구위 / 변화. 각 줄 오른쪽 `▲` `▼` 삼각형 버튼.
- 상단 `사용 9 / 여분 0`. 총 9포인트, 처음 **3/3/3**. `▲` 은 여분 ≥ 1 일 때, `▼` 은 그 능력치 > 1 일 때(**각 능력치 1~7**). 막힌 버튼은 흐리게 + 이유 한 줄.
- **좌투 / 우투 선택**(구종은 동일, 가로 모양만 거울).

| 능력치 | 효과 | 구현 |
|---|---|---|
| 제구 | 구종이 더 정확한 위치로 간다 | 도착 분포 σ 감소(7.5절) |
| 구위 | 구속이 더 빨라진다 | 직구 기준 +3.5km/h/포인트 |
| 변화 | 변화구 종류가 늘고 **변화구 각이 커진다** | 아래 구종 규칙 + `BREAK_SCALE` (7.5절) |

**구종 고르기 (변화 포인트 → 고를 수 있는 변화구 수)**
| 변화 포인트 | 1·2 | 3·4 | 5·6 | 7 |
|---|---|---|---|---|
| 고를 수 있는 변화구 수 | 1 | 2 | 3 | 4 |
- 변화구 칩 4개(순서: **커브 → 슬라이더 → 체인지업 → 너클**). 직구는 항상 사용 가능(칩 없음).
- **기본 선택은 순서대로 채워진다**: 변화 3이면 `직구 + 커브 + 슬라이더` 가 이미 켜져 있다(칩이 진하게). 변화 포인트를 올리면 칸이 늘어난 만큼 순서대로 다음 칩이 자동으로 켜지고, 내리면 가장 뒤 칩부터 꺼진다.
- 칩 위에 `고를 수 있는 구종 수` 숫자를 보여 준다. **켜진 칩을 누르면 꺼지고(진한 표시가 사라지고) 숫자가 1 늘어난다.** 모두 켜진 상태에서는 0. **숫자가 1 이상일 때 꺼진 다른 칩을 누르면 그 구종이 켜진다.** 이렇게 기본 순서와 다른 구종도 고를 수 있다(예: 커브 대신 체인지업).
- **너클은 변화 포인트 7에서만** 쓸 수 있다(확정). 변화 6 이하에서는 너클 칩이 잠금 표시(누를 수 없음)이고 커브·슬라이더·체인지업 중에서만 고른다(변화 5·6이면 셋 모두). 변화 7이면 4칸이라 너클 포함 전부 켜지며, 켜진 칩을 꺼서 구성을 바꿀 수도 있다. 변화 포인트를 7 밑으로 내리면 너클이 먼저 꺼진다.
- 선택 변경은 경기 시작 전에만.

### 6.2 타자 탭
**능력치 3개**: 컨택 / 파워 / 주루. 투수와 같은 방식(총 9포인트, 처음 3/3/3, 각 1~7, `▲▼`). **우타 / 좌타** 선택.
| 능력치 | 효과 | 구현(8.10절) |
|---|---|---|
| 컨택 | 타격 타이밍이 더 여유로워진다 | 정타 구간 폭·밴드 폭 배율 `TimingLeniency` |
| 파워 | 비거리 분포가 더 위로 올라간다 | 타구 속도(EV) 분포 상향 + 고에너지 가중치 증가 |
| 주루 | 땅볼 세이프 확률이 오르고, 루상에서 더 많은 베이스를 간다 | 타자 주자 1루 도달 시간 단축, 주자 최고 속도·진루 마진 보정 |
- 타이밍 가이드 링 켜기/끄기 토글(8.8절) 【보충】.
- **모든 배분이 비슷하게 좋도록** 17.2절 시뮬레이션으로 계수를 맞추고, 능력치가 의도대로 반영되는지 17.1절 검사 도구로 확인한다.

### 6.3 나중에 늘릴 것 (지금은 만들지 않음)
`타순` 탭(타자 3명·9명 능력치·순서 편집), `불펜` 탭(선발·중간계투·마무리 구성, 교체 순서·교체 기준 체력). 모두 6.0절 저장 형식과 `AbilityAllocator` 위에 얹는다.

## 7. 투구 시스템

### 7.1 좌표 정의 (모든 계산의 기준)
- **존 좌표** `(u, v)`: **투수 시점 화면** 기준. `u`는 오른쪽이 +, `v`는 위가 +. 스트라이크 존은 `|u|≤1, |v|≤1`(반폭을 1로 정규화). 존 확대 창은 `|u|,|v| ≤ 2.4`까지 보이고, 후보 범위 전체가 `±2.2` 안에 드는 점만 조준할 수 있다(7.5절 조준 제한).
- 투수 시점 화면에서 **오른쪽 = 3루쪽 = 우타자 타석쪽**이다(투수는 홈을 보고 서므로 자신의 오른쪽이 3루쪽). 그래서 우타자에게 몸쪽(inside) = `u+`, 좌타자에게 몸쪽 = `u−`.
- **타자 기준 좌표** `(s, y)`: `s = (우타 ? u : −u)`로 바꿔서 쓴다. `s=−1` 몸쪽 끝, `s=+1` 바깥쪽 끝, `y=−1` 무릎, `y=+1` 가슴 높이.
- 야구장 좌표(필드): 원점 = 홈플레이트, `+X` = 우익쪽(1루쪽), `+Z` = 중견수쪽, `+Y` 위. three.js로 옮길 때는 `FieldSpace.toWorld()` 한 곳에서 Z 부호를 뒤집는다(three는 -Z가 앞).

### 7.2 투구 순서 (투수가 하는 일)
1. 내 차례가 되면 하단에 **구종 버튼 5칸**이 한 줄로 뜬다: `Q 직구` · `W 커브` · `E 슬라이더` · `A 체인지업` · `S 너클`. 해금되지 않았거나 꺼 둔 구종은 흐리게(누를 수 없음).
   - **버튼 한 칸 안에 모두 들어간다**: 위쪽에 키 글자(`Q`)와 구종 이름(크게), 아래쪽에 **스트라이크 존을 배경으로 한 대략적인 궤적 그림**(공이 어디서 어디로 휘는지 곡선 + 끝 공 아이콘). 설명 문장은 없다.
   - 궤적 그림은 구종 클래스가 그린다(`PitchKind.trajectoryIcon(hand)`): 직구는 거의 직선, 커브는 위에서 우하/좌하로 크게 떨어지는 호, 슬라이더는 옆으로 휘며 떨어지는 곡선, 체인지업은 직구처럼 오다 느리게 가라앉는 곡선, 너클은 흔들리는 선. 좌투/우투와 후보 범위 모양(7.3절)이 같은 방향이 되도록 같은 축 각도로 그린다.
   - **글자와 그림은 크게**(화면이 넓다). 한 칸 최소 `min(17vw, 150px)` 폭. 선택된 칸은 주황 테두리.
   - 선택은 키보드(`Q W E A S`), 마우스 클릭, **화면 터치** 모두 가능.
2. 구종을 누르면 **스트라이크 존과 그 주변이 확장되어 열린다**(확대 존 창, 7.4절).
3. 창 안에서 위치를 **클릭하거나 드래그**해서 조준점을 정한다. **클릭 한 번에 바로 투구하지 않는다.** 조준점에 야구공 모양과 그 둘레 **연한 흰색 후보 범위**(공이 실제로 갈 수 있는 곳)가 나타난다.
4. **`Space` · `Enter` · `던지기` 버튼(화면 오른쪽 아래)** 중 하나로 확정한다. 확정하면 변경 불가.
5. **투구하면 확대 창이 꺼지고 일반 시점으로 돌아간다.** 투수 캐릭터가 와인드업 → 투구. 실제 도착 위치는 조준점이 아니라 후보 범위 안의 확률 위치다.
6. 공이 지나가면 결과는 7.8절 결과 패널에 존 모양과 함께 나온다.

### 7.3 구종 사양
**구속**: 구위 `p`(1~7)에 따라 직구 `V_FB = 126 + 3.5p` km/h (1→129.5, 3→136.5, 5→143.5, 7→150.5).
| 구종 | 구속 | 후보 범위 모양 (**우투 기준**, 화면 시계 방향) | 의도 |
|---|---|---|---|
| 직구 | V_FB | **원형** | 가장 안정적 |
| 커브 | V_FB − 32 | **1시–7시 방향으로 긴 타원** (우상 ↔ 좌하) | 아래로 크게 떨어지거나, 밋밋하게 높이 뜸 |
| 슬라이더 | V_FB − 17 | **2시–8시 방향으로 긴 타원** (우상 완만 ↔ 좌하 완만) | 글러브쪽(우타자 바깥쪽)으로 휨 |
| 체인지업 | V_FB − 22 | **11시–5시 방향으로 긴 타원** (좌상 ↔ 우하) | 팔쪽(우타자 몸쪽)으로 가라앉음 |
| 너클 | 104 + 1.2p | **직구 원형보다 조금 더 큰 원** (반지름 약 1.43배) | 흔들리는 도착 시각 |
- **좌투**는 가로를 뒤집는다(1시→11시, 2시→10시, 11시→1시 …).
- 시계 방향 → 수학 각도: 1시=60°, 2시=30°, 5시=−60°, 7시=−120°(=240°), 8시=−150°(=210°), 11시=120°. 축 각도: 커브 60°, 슬라이더 30°, 체인지업 120°.
- 이 모양은 우투/우타 조합에서 의미가 맞다: 우투 슬라이더는 우타자 바깥쪽으로, 우투 체인지업은 우타자 몸쪽으로 가라앉는다(별도 코드 없이 좌표만으로 자연스럽게 나온다).

### 7.4 확대 존 창 UI
- 구종 버튼을 누르면 존 창이 **0.18초 동안 커지며 열린다**(작은 존 → 확대). 정사각형 `min(52vh, 440px)`, 가로 화면에서는 오른쪽 가운데, **세로 화면에서는 화면 가운데**(폭의 86%). 던지면 닫힌다.
- 스트라이크 존은 굵은 선과 3×3 격자, 바깥(볼 구역)은 연한 회색 격자. 몸쪽/바깥쪽 글자(타자 손에 따라 좌우가 바뀐다), 타자 서 있는 쪽에 작은 실루엣.
- **조준**: 클릭·탭하면 그 점으로 이동, 누른 채 **드래그**하면 따라 움직인다. 조준점에 **야구공 아이콘**, 둘레에 **연한 흰색 반투명 후보 범위**(투명도 약 0.28, 점선 가장자리).
- **조준 가능 영역**: 후보 범위 전체가 `|u|,|v| ≤ 2.2` 안에 들어오는 점만 조준할 수 있다(7.5절 조준 제한). 영역 밖을 누르면 가장 가까운 허용 점으로 끌려 들어오고, 허용 밖은 어둡게 표시. 그래서 공이 타자 몸에 닿는 일은 없다.
- 구종을 바꾸면 같은 조준점에서 범위만 바뀐다(허용 영역이 달라지면 조준점이 안으로 밀린다).
- 오른쪽(또는 아래)에 현재 구종 이름과 예상 구속(`약 143km/h`). 핫콜드존이 켜져 있으면 상대 타자의 3×3 색이 존 안에 깔린다(15.5절).
- 키보드/터치: `Q W E A S` 구종, 클릭·드래그 조준, `Space`·`Enter`·`던지기` 확정.

### 7.5 도착 위치 샘플링 (정직한 범위)
- 조준점 `A=(au,av)`. 구종별 분산 `σ_c`는 **제구 포인트 c**에서 결정:
  `SIGMA_BY_CONTROL = {1:0.55, 2:0.46, 3:0.38, 4:0.32, 5:0.27, 6:0.23, 7:0.20}` (존 반폭 1 기준)
- 범위 모양:
  - 직구: 등방 정규분포 σ=σ_c, **반지름 2σ_c 원 안으로 절단**(범위 밖이면 다시 뽑기).
  - 커브: 장축(축 각도 60°) σ_a=1.45σ_c, 단축 σ_b=0.65σ_c, 정규화 타원 반경 2로 절단 → 표시 타원의 반축은 `2σ_a`, `2σ_b`.
  - 슬라이더: 축 30°, σ_a=1.50σ_c, σ_b=0.65σ_c.
  - 체인지업: 축 120°, σ_a=1.35σ_c, σ_b=0.70σ_c.
  - 너클: 등방, σ=1.30σ_c, 반지름 2.2σ=2.86σ_c 원으로 절단.
  - (면적은 구종 간에 비슷하게 맞춰 두었다.)
- **변화구 각(변화 포인트 h)**: 변화구(커브·슬라이더·체인지업)의 **장축 σ_a 에 `BREAK_SCALE(h) = 1 + 0.10×(h−1)`** 을 곱한다(h=1 → 1.0, h=7 → 1.6). 변화 포인트가 높을수록 변화구의 휘는 폭(후보 범위가 긴 방향)이 커진다. 직구·너클에는 곱하지 않는다. 화면의 후보 범위(타원)도 같이 길어진다.
- **조준 제한(사구 방지)**: `AimLimiter` 가 구종·제구·변화 포인트로 후보 범위의 경계 상자를 계산해, 범위 전체가 `|u| ≤ 2.2`·`|v| ≤ 2.2` 안에 들어오도록 조준점을 안쪽으로 민다. 그래서 어떤 공도 타자 몸에 닿지 않는다(사구는 영구히 없음). AI도 같은 제한을 쓴다.
- **화면에 그린 후보 범위 = 절단 경계**이다. 공은 **절대 그 밖으로 가지 않는다**(표시와 실제가 어긋나지 않게).
- 확인용: 제구 3에서 직구를 존 정중앙에 던지면 반경 0.76 원이므로 항상 스트라이크지만 타자에게 가장 위험한 한가운데. 존 모서리 `(0.9,0.9)`를 노리면 범위의 일부가 볼 구역. 이 긴장이 투수의 재미다.
- 난수는 **서버가 정한 시드**(13절)로 만든다. 클라이언트가 임의로 뽑지 않는다.

### 7.6 비행 시간·시각
- 실제 비행시간 `T_real = 17.0m / (V_km/h ÷ 3.6)` (릴리스~홈플레이트 앞). 화면 비행시간 `T = T_real × FLIGHT_SCALE`, `FLIGHT_SCALE = 2.4`(터치 반응 가능하게 늘림). 직구 140km/h ≈ 1.05초, 체인지업 118 ≈ 1.24초, 너클 110 ≈ 1.33초.
- 투구 모션: 와인드업 0.9초(정지된 투수 `Idle` → `Throw` 클립을 늘려 릴리스 프레임이 정확히 `releaseAt`에 오게). 릴리스 시각은 서버가 미리 정한 `releaseAt`.
- 경로는 구종별로 다르게 보이되 **도착점은 샘플링된 값에 정확히 일치**:
  직구 직선(미세하게 뜨는 느낌), 커브 크게 호를 그리며 낙하, 슬라이더 막판에 옆으로 급변, 체인지업 직구와 같은 모션 후 천천히 낙하, 너클 불규칙 좌우 흔들림(시각 전용, 도착 시각에도 ±22ms 잡음).

### 7.7 투구·타격 카메라 (플레이어와 관전자 공통)
- **투수 시점(`PitcherViewShot`)**: 마운드 **바로 뒤**(중견수 쪽)에서 홈을 본다. 필드 `(X 0.9 · 투수 손 반대편으로 약간 비켜서, Y 2.4, Z 18.44+3.4)` → 홈 위 존 중심을 화면 중앙 약간 아래에. 좌투는 X 부호를 뒤집는다. 시야각 40~45°. 투수 몸이 존을 가리지 않게 어깨 위에서 바라본다.
- **타자 시점(`BatterViewShot`)**: **홈플레이트 바로 뒤 심판 위치**에서 마운드 방향을 본다. 필드 `(0, 1.6, −3.2)` → `(0, 1.1, 14)`. 타자 실루엣이 한쪽에 보이고 공이 마운드에서 날아오는 것이 정면으로 보인다. 시야각 38~42°.
- 내가 투수면 투수 시점, 타자면 타자 시점. 관전자는 두 시점 중 고른다(5.7절).
- 확대 존 창(7.4절)은 3D 화면 위에 겹쳐 올린다.

### 7.8 투구·타격 결과 표시 (`ResultPanel`)
- 투구가 끝나면 화면의 **빈 공간**(가로: 오른쪽 가운데, 세로: 3D 화면 아래쪽 가운데)에 패널 한 장을 띄운다. 새 투구가 시작되면 사라진다.
- 패널 안에는 **작은 스트라이크 존 그림**(3×3 격자 + 바깥 구역) 위에 **조준점(작은 점) → 실제 도착 위치(공 아이콘)** 를 선으로 잇고, 타격했으면 **접촉 위치**와 타이밍 한 줄을 함께 표시한다.
- 존 아래에 판정 한 줄(스트라이크/볼/헛스윙/파울/안타…), 그 아래 `구종  구속`.
- **타구 정보는 같은 패널에서 세로 목록**으로 쓴다: `타구 속도 148km/h` / `발사각 27°` / `비거리 112m`. 글자가 공이나 선수 위를 따라다니지 않고, 한 슬롯에만 그려서 **겹치는 글씨가 없게** 한다.
- 글자는 미리 만들어 둔 요소를 바꿔 끼우는 방식(성능 지침). 확인: 가로 1280×800·640×360, 세로 390×844 스크린샷에서 겹침 0.

## 8. 타격 시스템 (타이밍 판정)

### 8.1 조작
- `스윙` 버튼 한 개(+`Space`/`Enter`/마우스 클릭). 누르면 즉시 스윙 모션 시작, **접촉 프레임은 누른 뒤 `SWING_DELAY = 120ms`** 에 온다.
- 한 투구에 스윙은 한 번(두 번 못 누름). 누르지 않으면 "치지 않음".
- 지금은 노려치기·컨택하기·번트가 없다. 치거나 안 치거나, 그리고 타이밍만 결정한다(`SwingAction`). 나중에 다른 타격 행동을 `BatterAction` 구현 클래스로 더한다(1.1절).

### 8.2 타이밍 변수
- `t_arrive` = `releaseAt + T`(+너클 잡음 `N(0,22ms)`) — 공이 접촉 지점(홈플레이트 앞 0.3m)에 오는 시각.
- `t_contact = t_press + 120ms`.
- 원시 오차 `Δ = t_contact − t_arrive` (음수 = 일찍, 양수 = 늦게).
- **위치에 따른 이상적 접촉 시각**(선생님 규칙):
  `μ(s) = 28ms × s + n`, `s`는 타자 기준 몸쪽/바깥쪽(−2~+2로 클램프), `n ~ N(0, 7ms)`는 **투구마다 서버가 한 번 뽑아 기록**(항상 딱 떨어지지 않고 분포를 갖는다).
  - 몸쪽 공: 이상적 타이밍이 **더 빠르다**. 바깥쪽 공: **더 늦다**. 존 바깥쪽으로 더 벗어날수록 더 늦어진다(`s`가 2까지 늘어남).
- **보정 오차** `Δ_adj = Δ − μ(s)`. 이것이 0에 가까울수록 "정확한 타이밍"이다.

### 8.3 정타 구간 폭 `W` (가운데일수록 넓다)
`r = max(|s|, |y|)` (존 가운데 0, 존 가장자리 1, 바깥으로 더 커짐).
| r | W (ms) |
|---|---|
| 0 | 55 |
| 1.0 | 28 |
| 1.6 | 12 |
| ≥ 2.0 | 6 |
(사이는 선형 보간.) 구속 보정 `f_v = clamp(1 − 0.004×(V−140), 0.85, 1.15)`를 곱한다(빠를수록 좁아진다). **타자의 컨택 배율 `TimingLeniency`(8.10절)도 곱한다.** 이로써 **가운데로 오는 공은 정타 구간이 넓어 더 위험**하다.

### 8.4 타이밍 구간(밴드)과 접촉 여부
`|Δ_adj|`를 `W`와 비교:
| 밴드 | 조건 | 접촉 확률 |
|---|---|---|
| 정타 | `≤ W` | 1.0 |
| 양호 | `≤ W+40` | 1.0 |
| 보통 | `≤ W+80` | 0.90 |
| 빗맞음 | `≤ W+130` | 0.70 |
| 헛스윙 | 그 이상 | 0 |
- **선구 보정**(존 바깥 공을 건드릴 때): `chase = 1.0 (r≤1.15)`, 1.15~1.9에서 선형으로 0.35, 1.9 초과 0.10. 접촉 확률에 곱한다.
- 헛스윙이면 스트라이크.

### 8.5 타구 방향 (스프레이)
- 정확한 타이밍보다 **빠르면 당겨치기**(우타자는 좌익쪽), **늦으면 밀어치기**(우익쪽). 몸쪽 공은 같은 "정확함"에서도 더 당겨진다.
  `ψ(당김+, 도) = −0.30°/ms × Δ_adj − 8° × s + N(0, 7°)`
- 필드 각도 `φ`(중견수 0°, 좌익선 −45°, 우익선 +45°):
  `φ = −ψ`(우타자), `φ = +ψ`(좌타자).
- `|φ| > 45°` 이면 **파울 방향**. `|φ| ≥ 70°`는 포수 뒤쪽 백네트 파울 팁 【보충】.
- 매우 이르거나 매우 늦은 타이밍(빗맞음 밴드)은 `ψ`가 커져 **파울이 자연스럽게 많이 나온다**.

### 8.6 발사각
`θ = 12° + 10°×y − 0.06°/ms × Δ_adj + N(0, σ_θ)`; `σ_θ` = 정타/양호 7°, 보통/빗맞음 11°. 범위 −15°~70°.
- 낮은 공(`y`↓)은 땅볼 경향, 높은 공은 뜬공 경향. 늦으면(Δ_adj>0) 낮아지고 이르면 높아진다.
- 분류: `θ < 8°` 땅볼, `8~22°` 라인드라이브, `22~50°` 뜬공(플라이), `> 50°` 높이 뜬 내야 뜬공(팝플라이).

### 8.7 타구 속도(EV)와 비거리 — 확률 요소
EV는 **밴드별 혼합 분포**에서 뽑는다(정확해도 매번 달라진다). 표의 `p`는 확률, `N(평균, 표준편차) km/h`. **아래 값은 이전 목표(타율 .260)용 초기값이다.** 새 목표(타율 .400·장타율 .600·홈런 10%, 12.3절)에 맞추려면 M0에서 고속 성분 비중과 가운데 보정을 올리고 파워 능력치(8.10절)를 얹어 조정한다:
| 밴드 | 구성 |
|---|---|
| 정타 | 8% N(168,6) · 22% N(156,7) · 30% N(145,8) · 25% N(130,10) · 15% N(112,12) |
| 양호 | 3% N(150,8) · 17% N(138,9) · 35% N(124,10) · 30% N(108,12) · 15% N(90,14) |
| 보통 | 10% N(125,10) · 30% N(108,12) · 40% N(92,14) · 20% N(75,14) |
| 빗맞음 | 25% N(100,14) · 75% N(80,16) |
보정: `+ 8×(1 − min(r,1))`(가운데일수록 +), `+ 0.15×(V_pitch − 135)`(빠른 공일수록 +). 범위 40~185km/h.

**비거리** `D(EV, θ)` (공기저항 포함 수치 적분으로 만들되 아래 표에 ±5% 안으로 맞춘다):
| EV (km/h) | 120 | 130 | 140 | 150 | 160 | 170 | 180 |
|---|---|---|---|---|---|---|---|
| θ=28°일 때 D (m) | 62 | 73 | 85 | 98 | 110 | 123 | 136 |
발사각 효율(28° 대비): 10°→0.55, 15°→0.75, 20°→0.90, 28°→1.0, 35°→0.97, 40°→0.88, 45°→0.75, 50°→0.60, 60°→0.35, 70°→0.15. 체공시간은 EV 150·θ28°에서 약 4.8초가 되도록 맞춘다(다른 값은 같은 공식으로).
- 땅볼은 `EV×0.8`로 출발해 잔디에서 감속(약 2.8m/s²).

### 8.8 판정 결과 흐름
1. 스윙 안 함 → 공 중심이 존에 닿으면(`|u|≤1`, `|v|≤1`) 스트라이크, 아니면 볼 (흔들림 없음).
2. 스윙 → 8.4 접촉 여부 → 헛스윙이면 스트라이크.
3. 접촉 → 8.5로 방향 → 파울이면 파울(포구 가능성은 9.9절) / 페어면 8.6·8.7로 타구 → **9절 PlayResolver**로 넘긴다.
4. 하이라이트: 접촉 순간 정타 밴드이면 0.35초 슬로모션 【보충】.
5. **타이밍 게이지**(5.4절): 스윙 직후 `Δ_adj` 와 그 공의 `W`·밴드 폭으로 게이지(빠름 ◀ 정타 ▶ 늦음)를 1.2초 그린다. 헛스윙·치지 않음도 내 타이밍 위치를 보여 준다(치지 않음은 게이지 없음).

**타이밍 가이드 링(쉬운 모드)** 【보충】: 중앙 투구 기준의 정확한 시각에 완성되는 얇은 링이 홈플레이트 위에서 줄어든다. 위치별 `μ` 보정은 보여 주지 않는다(몸쪽/바깥쪽 읽기는 실력). 처음 10번 스윙은 자동 켜짐, 설정에서 끌 수 있다.

### 8.9 사양 검증 예 (선생님 예시, 펜스 중앙 120m·좌우 100m·능력치 3/3/3 기준 — 비거리 표를 바꾸면 17.1절 검사에서 다시 계산)
- 예 A. 존 한가운데 직구(r=0, W=55). `Δ_adj=−5ms`: 정타. `ψ=+1.5°`, 거의 중견수 방향. EV 162, θ 27°, D≈118m. 중견수 펜스 거리 `F(φ)=120 − 20×|φ|/45`=119.3m → **D<F, 펜스 앞쪽에 떨어져 굴러 가거나 펜스를 맞는 장타**(홈런 아님). ✔ (비거리 표를 올려 홈런 10%를 맞추면 이 예는 홈런이 될 수 있으니 값은 M0에서 다시 계산한다.)
- 예 B. 몸쪽 공(s=−0.8, y=0, r=0.8, W≈33), 원시 `Δ=−75ms` → `μ=−22ms`, `Δ_adj=−53`: 양호 밴드. `ψ=15.9+6.4+잡음(+7.7)=30°` → 우타자 좌익 쪽 `φ=−30°`, `F=106.7m`. EV 150(행운 구간), θ 28° → D=110m ≥ F → **홈런**. ✔ (정타보다 약간 이른 몸쪽 타구가 당겨져 홈런이 되는 장면.)
- 예 C. 바깥쪽 공(s=+0.8), 원시 `Δ=+30ms` → `μ=+22ms`, `Δ_adj=+8`: 정타 구간. `ψ=−2.4−6.4=−8.8°` → 우타자 기준 약간 밀려 우중간. 바깥쪽 공은 약간 늦게 쳐야 정타라는 규칙. ✔

### 8.10 타자 능력치 반영 (컨택·파워·주루) 【보충 — 계수는 17.2 시뮬레이션으로 확정】
`c, p, r` 는 각각 컨택·파워·주루 포인트(1~7, 기준 3). 모든 계수는 `BatterAbilityModel` 한 곳에 표로 둔다.
| 능력치 | 적용 위치 | 초기 계수 |
|---|---|---|
| 컨택 `c` | 8.3 정타 폭 `W` 와 8.4 밴드 가산폭(40/80/130ms)에 곱함 | `TimingLeniency = 1 + 0.10×(c−3)` → 0.8 ~ 1.4 |
| 파워 `p` | 8.7 EV 평균에 더함 + 고에너지 성분 가중치 증가 | `ΔEV = +4.0×(p−3)` km/h, 상위 성분 가중치 `×(1+0.12×(p−3))` 후 정규화. EV +4km/h ≈ 비거리 +5m |
| 주루 `r` | 9.7 주자 속도·타자 주자 1루 도달 시간·진루 판단 마진 | 최고 속도 `8.0 + 0.25×(r−3)` m/s, 1루 도달 `4.10 − 0.07×(r−3)` 초, 진루 마진 임계 `0.40 − 0.04×(r−3)` 초 |
- **주루 효과**: ① 땅볼 1루 승부에서 타자 주자 도착이 빨라져 세이프(내야안타)와 병살 회피가 늘어난다 ② 루상에서 `margin` 임계가 낮아져 더 많은 베이스를 노린다(자동).
- 투수 능력치 계수는 7.5절 표(제구 σ), 6.1절(구위 +3.5km/h), 7.5절 `BREAK_SCALE`(변화) 에 있다.
- **균형 목표**: 28가지 배분(9를 3칸에 1~7로 나눈 경우의 수) 중 어떤 것을 골라도 **같은 수준의 상대에게서 기대 득점(하프 이닝)이 전체 평균의 ±8% 안**(타자·투수 각각). 벗어나는 배분이 있으면 그 계수만 조정한다(17.2절).

## 9. 타구 처리 · 수비 · 주루 (PlayResolver)

화면을 모르는 TS 클래스. 입력: 경기 상태(아웃·주자·카운트) + 타구(`EV, θ, φ` 등) + 시드. 출력: **`PlayScript`** — 시간순 이벤트 목록과 최종 상태. 화면(Choreographer)은 이 스크립트만 보고 연출한다.

### 9.1 구장 치수 (m)
- 베이스 간격 27.43(90피트): 1루 `(19.40, 19.40)`, 2루 `(0, 38.80)`, 3루 `(−19.40, 19.40)`, 홈 `(0,0)`.
- 투수판 `(0, 18.44)`. 마운드 반경 2.74, 중심 높이 0.25.
- 파울선 = 홈에서 ±45° 선. 펜스 거리 `F(φ) = 120 − 20×|φ|/45` (**중앙 120, 좌우중간(±22.5°) 110, 파울 폴(좌우) 100** — 선생님 확정). 펜스 높이 3.0m 【확인 ★3.0】. 워닝트랙 폭 4.5m. **펜스 거리는 위 값으로 고정하고, 홈런 10%(12.3절)는 비거리(8.7절 EV·비거리 표)를 조정해서 맞춘다.** 규칙 엔진은 거리·높이를 `FieldDimensions` 로만 읽으므로 구장(11.6절)이 값을 정한다.
- 파울 지역: 백네트 홈 뒤 17m. 측면은 파울선 바깥 18m에 펜스.

### 9.2 홈런·펜스·낙하 판정
비행 모델로 비거리 `D`와 펜스 위치에서의 높이 `h(F)` 계산.
- `D ≥ F(φ)` 이고 `h ≥ 3.0m` → **홈런**.
- `D ≥ F(φ)` 이고 `h < 3.0m`(낮고 빠른 타구) → **펜스 직격** → 펜스를 맞고 튀어 나옴.
- `D < F` → 필드 안 낙하. 낙하 지점에서 수비수가 잡으면 아웃, 아니면 바운드·굴러 가며 펜스까지 갈 수 있음.
- 펜스 위를 넘었으나 파울 폴 바깥이면 파울 홈런(파울).

### 9.4 담당 수비수 결정
- 뜬공/라인드라이브: 낙하점에 가장 일찍 닿을 수 있는 수비수 중 **외야수 우선, 중견수 > 좌·우익수 > 내야수**(콜 우선권). 내야수는 외야수보다 0.5초 이상 일찍 닿을 때만 담당.
- 땅볼: 공 경로 위 가로채기 시각을 계산해 가장 일찍 막는 수비수. 못 막으면 **내야를 빠져나가 안타**, 외야수가 주워 처리.
- 팝플라이: 내야수가 담당(콜: 유격수 > 2루수 > 3루수 > 1루수 > 투수 > 포수).
- 잡은 순간 이후 흐름은 9.6.

### 9.5 정석 수비 분담표 (커버·백업·중계)
**내야 땅볼 (주자 없음)**
| 타구 | 처리 | 1루 커버 | 2루/3루 커버 | 백업 |
|---|---|---|---|---|
| 3루수 쪽 | 3B → 1B 송구 | 1B 베이스 | — | RF가 1루 뒤 백업 |
| 유격수 쪽 | SS → 1B 송구 | 1B | — | RF 1루 뒤 |
| 2루수 쪽 | 2B → 1B | 1B | — | RF 1루 뒤 |
| 1루수 쪽 | 베이스에 가까우면 **1B 직접 밟기**, 멀리 빠지면 투수에게 토스(3-1) | P가 1루 커버 | — | RF 1루 뒤 |
| 투수 앞 | P → 1B | 1B | — | RF 1루 뒤 |
**주자 1루(병살 가능)**: 3B·SS·P 앞이면 **2루로 송구 → 1루로 연결**(5-4-3, 6-4-3, 1-6-3), 2B·1B 쪽이면 **유격수가 2루 커버**(4-6-3, 3-6-3, 3-6-1). 규칙: **왼쪽(3유간) 타구면 2루수가 2루 커버, 오른쪽(1·2루 쪽)이면 유격수가 2루 커버.**
**주자 만루/포스**: 홈 포스(만루, 2아웃 미만)를 먼저 노린다(포수 포구 → 1루 연결).
**외야 안타(단타)**
| 타구가 간 곳 | 줍는 사람 | 중계(컷오프) | 베이스 커버 | 백업 |
|---|---|---|---|---|
| 좌익 | LF | **SS**가 외야로 나가 중계 | 3B 3루 커버, 2B 2루 커버, 1B 1루 | CF가 LF 뒤 백업, P는 홈 백업 |
| 중견 | CF | 좌중간은 **SS**, 우중간은 **2B**가 중계 | 위와 같음 | LF·RF가 CF 백업 |
| 우익 | RF | **2B**가 중계 | 위와 같음 | CF가 RF 뒤 백업, P는 3루 또는 홈 백업 |
- 홈 송구가 목표일 때 중계: LF 쪽 3B, CF·RF 쪽 1B가 컷오프 위치(홈-공 사이 직선, 홈에서 약 30m).
- 홈 송구가 늦으면 중계맨이 **컷**하고 타자 주자를 2루에서 막는다(9.7).
- 투수는 항상 "가장 앞선 주자가 노릴 베이스" 뒤로 이동해 백업(홈 or 3루).

**장타 (2루타 이상)**: 코너 외야수가 펜스에서 주워 3B/1B 컷오프에 송구, 중계는 SS/2B. 3루타는 우익선 쪽이 우익수, 중견수-우중간이 중견수.
**플라이 아웃**: 외야수 포구 후, 태그업 주자가 있으면 송구(9.7), 없으면 마운드로 가볍게 던져 넘긴다.
**라인드라이브**: 반응 시간이 짧아 포구 성공률을 낮춘다(포구 반응 지연 0.15초만 쓰고 다이빙 범위 1.0m 증가).

### 9.6 송구 결정 알고리즘 (자동 수비)
잡은(주운) 시각 `t_f`, 위치 `P_f`. 가능한 송구 목표 베이스 후보를 순서대로 평가해 **처음 이길 수 있는 목표**로 송구:
1. 홈 포스/태그(득점 위협 주자) 2. 3루 3. 2루(병살 시 연결) 4. 1루.
각 목표 `b`에 대해
- 공 도착 시각 `t_ball(b) = t_f + 포구 후 지연(내야 0.45s / 외야 0.60s) + 거리 / 송구 속도(내야 33m/s, 외야 36m/s)` (+중계가 있으면 중계 지연 0.5s 추가)
- 주자 도착 시각 `t_runner(b)` (9.7)
- **마진** `= t_runner(b) − t_ball(b)`. 포스 아웃: 마진 > 0이면 아웃. 태그 아웃: 마진 > 0.25초(태그 시간)이면 아웃. 동시면 주자 우선(세이프).
**선택(정석, 실수 없음)**: **1루 주자가 있고 아웃이 2개 미만인 내야 땅볼을 정상적으로 잡았으면 항상 병살을 시도**한다(2루 포스 → 1루). 두 번째 아웃은 타자 주자가 1루에 먼저 닿는지로 정해지며(주루 능력치·8.10절), 타자가 먼저 닿으면 병살은 빠지고 선행 주자만 잡는 야수선택(`FIELDERS_CHOICE`)이 된다. 병살 상황이 아니면 확실한 아웃을 우선한다. 모든 마진이 음수이면 "가장 앞선 주자의 다음 베이스"로 형식적으로 던져 진행을 막는다.
- **실책(선생님 지정)**: **내야 땅볼을 처리하는 장면에서만 5% 확률**(`FIELDING_ERROR_RATE = 0.05`, 서버 시드로 결정). 포구 실패(공을 흘림) 또는 송구 실패로 **타자 주자 1루 세이프**, 포스로 밀린 주자는 한 베이스 진루. 외야 타구·뜬공·파울에서는 실책이 없다. 결과 코드 `ERROR`. 나머지 모든 자동 수비·송구는 실수가 없다.
- 실책은 `ErrorPolicy` 인터페이스 뒤에 둔다: `InfieldGroundBallErrorPolicy(0.05)`(지금) / `NoErrorPolicy`(끔). **방 규칙의 정책 한 줄을 바꾸면 없어진다**(코드 삭제 불필요).
- 통계 처리: 실책 출루는 타수 1·안타 아님·출루율 분자 제외, 득점은 자책 아님(15.1절).

**송구 궤적 (낮은 라인 송구, 선생님 지적 2026-11-12)** — 포물선으로 높이 뜨지 않는다. 비행 시간은 항상 `거리 ÷ 송구 속도`이고 궤적 모양만 아래 규칙으로 그린다(`ThrowTrajectory` 클래스, 목표 도착 시각은 위 `t_ball`과 같다).
| 송구 | 궤적 |
|---|---|
| 내야 송구(거리 ≤ 40m: 땅볼 → 1루, 병살 연결, 3루 → 1루 등) | **거의 직선 라인**: 릴리스 높이(약 1.5m)에서 목표 글러브 높이(1.0~1.4m)로, 정점은 릴리스 높이 +0.3m 이내. 공은 어깨~허리 높이로 일직선으로 날아간다. 1루 송구는 1루수 가슴 높이로 |
| 외야 → 중계수(거리 40~75m) | **낮은 호**: 정점 높이 ≤ 3.0m(거리 ×0.04). 외야수는 크로우 홉(한 걸음 딛기)으로 던진다. 중계수는 가슴 높이에서 받는다 |
| 외야 → 홈/3루 직접(75m 이상) | **원바운드 라인 송구**: 낮게 날아가 목표 앞 8~12m 지점에서 한 번 튀고 포수/3루수 글러브로. 정점 ≤ 2.5m |
| 중계수 → 홈/베이스(거리 ≤ 40m) | 내야 송구와 같은 직선 라인 |
- 공에는 **백스핀 회전**을 준다(시각 전용, 송구 방향 축). 속도는 9.6절 값(내야 33 / 외야 36 m/s)과 같고, 화면의 비행 시간이 이 값과 어긋나지 않는다.
- 릴리스 시각·위치는 던지는 수비수의 **손 뼈**에서(0.2절 `ActionSync`), 포구 프레임은 도착 시각과 같다.

### 9.7 주자 판단 (자동 주루)
- 주자 최고 속도 8.0m/s(타자의 **주루 능력치**로 `8.0 + 0.25×(r−3)`, 8.10절), 가속 6m/s². 베이스 간 시간: 정지 출발 1루까지 약 4.1초, 이후 구간 약 3.5초, 리드 있는 주자 구간 약 3.2초. 반응 지연 0.1초.
- **포스 상황**(타자가 주자가 되어 뒤 주자가 밀림)에서는 무조건 진루.
- 외야 안타 시: 주자는 다음 베이스까지 달리는 도중 **3루 코치 판단**을 한다. 송구 목표 베이스 `b`에 대해 `margin = t_ball − t_runner` 가 **+0.40초 이상이면 진루(홈 쇄도/한 베이스 더)**, 아니면 멈춘다. 판단은 수비가 공을 잡은 시각과 중계 시각마다 다시 한다.
- **자동 주루는 실수하지 않는다**(항상 정석): 잡힐 타구에서 더블 아웃되거나 잘못된 베이스로 달리는 일이 없다.
- **리터치·태그업 (정석)**: 외야 플라이가 떠 있는 동안 2·3루 주자는 베이스에서 한두 걸음 **리드**했다가, 공이 높고 깊어 **잡힐 것으로 판단되면 베이스로 돌아와 발을 대고(리터치) 대기**한다. 포구 순간 출발(태그업). 이벤트 `retouch`(복귀·밟음) → `tagUp`(출발)이 `PlayScript` 에 들어간다. 낮고 빠른 타구는 리터치 없이 안타 판단(아래).
- **태그업**: 플라이 아웃 때 주자는 베이스로 돌아가 있다가 포구 시각에 출발. 3루 주자: 포구 지점이 홈에서 **55m 이상**이면 시도. 2루 주자: 85m 이상(우익 쪽 우선). 1루 주자: 100m 이상. 시도 후 마진 판단은 같음.
- **타자 주자**: 땅볼이면 1루로 전력 질주(9.10). 안타 방향/비거리에 맞춰 2루 이상 노린다.
- 슬라이딩: 태그 가능성이 있는 베이스(마진이 0.4초 미만)에서 슬라이딩(절차 애니메이션, 10.4절).

### 9.8 결과 코드
`PlayScript.result` 는 다음 중 하나: `SINGLE, DOUBLE, TRIPLE, HOME_RUN, GROUND_OUT, FLY_OUT, LINE_OUT, POP_OUT, DOUBLE_PLAY, SAC_FLY, FIELDERS_CHOICE, FOUL_CAUGHT(아웃), FOUL, INFIELD_FLY, ERROR`. 주자별 최종 위치와 득점 리스트를 포함.

### 9.9 파울 타구
- 파울 방향이거나 뒤로 간 타구는 **궤적을 끝까지 그리고** 낙하/바운드한다.
- 가장 가까운 수비수(내야수/포수/외야수)가 **자연스럽게 쫓아간다**(달리기 → 포구 자세). 파울 지역 안에서 낙하 전 잡을 수 있으면 **파울 플라이 아웃**.
- 못 잡으면 낙하 후 가까운 수비수가 주워 **포수/투수에게 되던진다**. 카메라는 공을 따라가다 줍는 수비수 쪽으로 이동, 투수가 받으면 다음 투구로 복귀.
- 파울 지역 한계: 백네트·펜스에 막힘. 벽에 맞고 튀는 연출 포함.

### 9.10 땅볼 1루 송구 장면 (선생님 지정 연출)
1. 타자 스윙 접촉 후 **타자는 곧바로 1루로 질주**. 마지막 구간은 파울선 바깥쪽(1루 파울 지역 쪽) 달리기 레인에서 달려 **베이스 앞쪽/안쪽 모서리를 밟는다**.
2. **오버런**: 밟은 뒤 감속하며 1루 파울선 바깥쪽(우익쪽 파울 지역)으로 4~5m 미끄러지듯 지나가고, 안타 후 더 갈 수 없으면 베이스로 돌아와 선다(포구 후 아웃이면 걸어서 더그아웃으로).
3. 수비수는 공에 달려가 **포구 자세(몸을 낮추는 동작)** → 잡는 순간 정지 0.2초 → 방향 전환 스텝 → **송구**. 송구는 원 포구 위치에서 1루수의 글러브까지 궤적 그림.
4. 1루수는 베이스 발을 대고 몸을 뻗어 포구. **타자가 베이스를 밟은 시각과 공이 글러브에 도착한 시각을 비교**해 아웃/세이프를 결정(위 마진 규칙) 하고 심판 판정 동작.
5. 아웃이면 짧은 "아웃!" 연출 + 투수에게 되돌림. 내야 안타(세이프)이면 타자는 1루에 선다(환호·세리머니 동작 없음).

### 9.11 홈런 장면
공이 펜스를 넘어가는 동안 외야수가 펜스 쪽으로 달려가 올려다본다. 관중석에서 공이 사라진다. 타자는 홈런 트롯: 1루 → 2루 → 3루 → 홈 베이스를 차례로 밟으며 **팔을 들고 들어온다**(주자가 있었으면 같이). 타자·동료의 세리머니(환호·하이파이브) 동작은 없고, 관중 반응(11.3절 파도타기)과 소리(11.5절)로 표현한다.

### 9.12 득점·교대 장면
- 득점: 홈 플레이트로 들어오는 주자(슬라이딩 또는 서서). 득점 순간 HUD 점수 증가(작은 +1 팝업).
- 아웃 3개: 5.6절 공수 교대 장면(탑뷰 2초, 자리 바꾸기)으로 넘어간다.

### 9.13 `PlayScript` 이벤트 형식 (네트워크로 전달되는 값)
```
{ seq, result, outsAfter, basesAfter:[1B,2B,3B 비어있음/주자id], runsScored, ballOutcome,
  events:[ {t:ms, kind:"ballFlight", from, to, apex, hang},
           {t, kind:"fielderMove", who:"SS", to:[x,z], arriveT},
           {t, kind:"catch"|"fieldGround", who},
           {t, kind:"throw", from:"SS", to:"1B", arriveT},
           {t, kind:"runnerMove", who:"batter", path:[[x,z,t]…]},
           {t, kind:"callOut"|"callSafe", base},
           {t, kind:"retouch"|"tagUp", who, base},
           {t, kind:"score", runner},
           {t, kind:"cameraHint", shot:"…"} ] }
```
- 이벤트는 대략 20~40개, 1~2KB. 화면은 이 이벤트를 보간해 재생한다(서로 다른 기기의 부동소수점 차이가 결과에 영향을 주지 않는다).
- 스크립트는 **진행 규칙을 계산한 쪽(해결자)이 한 번 서버에 쓴다**(13절). 다른 클라이언트는 계산하지 않고 재생만 한다.

### 9.14 인필드 플라이 (규정대로)
- **성립 조건(모두)**: ① 무사 또는 1사 ② 주자 **1·2루 또는 만루** ③ **페어 방향 뜬공**(플라이·팝플라이, 라인드라이브·번트 제외) ④ **내야수가 평범한 수비로 잡을 수 있다**: 낙하점이 홈에서 45m 이내이고 낙하 시각보다 0.3초 이상 먼저 내야수가 그 점에 닿을 수 있음.
- 성립하면 **타자는 즉시 아웃**(공이 떨어져도 마찬가지), 심판이 한 손을 올리는 동작 + 토스트 `인필드 플라이!`. 공은 살아 있고 주자는 **정석대로 제 자리에 머문다**(포스가 풀려 위험).
- 내야수가 잡으면 `INFIELD_FLY`(아웃 +1). 못 잡아 떨어지면 타자는 이미 아웃이고 수비수가 공을 주워 마운드로 돌려준다.
- 파울 방향·바깥 낙하는 일반 파울 규칙. 결과 코드 `INFIELD_FLY`(9.8절).

## 11. 구장 · 캐릭터 · 관중 · 연출


### 11.0 품질 기준 — 실제 제작 때 구장과 에셋은 고품질로 (선생님 요청 2026-11-12)
시연(0절)처럼 평평한 색 바닥과 임시 소품으로 끝내지 않는다. **실제 중계 화면처럼 보이는 구장과 소품**을 목표로 하고, 선생님 확인(M1 관문)을 통과해야 다음 단계로 간다.
- **구장**: 잔디는 두 방향 깎기 줄무늬(밝고 어두운 띠)와 외야·내야 색 차이, 내야 흙은 갈퀴 자국·베이스 주변 마모·타석 박스 선·베이스 패스 흙 길·파울선 분필(번짐 없이 깨끗하게), 마운드는 실제 단면과 투수판·디딤 자국, 홈 주변 흙 원, 펜스는 패딩 쿠션과 가상 광고판(**실제 브랜드 금지**, 학교·가상 이름), 노란 홈런선, 거리 표시, 파울 폴, 백네트, 더그아웃(지붕·벤치·헬멧 걸이·음료통), 관중석(좌석 줄·계단·난간·출입구), 전광판, 조명탑, 불펜, 원경(도시·나무·하늘 그라데이션·구름).
- **빛**: 실시간 조명은 방향광 1·반구광 1뿐이므로 **그림자·앰비언트 오클루전을 텍스처에 구워서**(내야 흙·베이스 주변·스탠드 아래·펜스 아래) 입체감을 낸다. 홈 주변 그림자는 방향광 그림자 1개(1024).
- **선수 에셋**: 공용 캐릭터 외형 위에 **야구 유니폼**(상의·바지·벨트·스타킹·스파이크 색 구분, 등번호는 불필요), **팀 모자·타자 헬멧(귀덮개)**, **투수·수비 글러브**, **포수 장비(마스크·가슴보호대·정강이보호대)**, **심판 복장(검은 옷·마스크)**, 배트(0.2절)·공(실밥 노멀감 + 약한 회전). 팀 색 두 가지(방장 팀/손님 팀)가 멀리서도 구분된다.
- **예산(성능 지침과 함께)**: 한 장면 삼각형 ≤ 약 250k, 선수 한 명 ≤ 8k, 텍스처 ≤ 2048px, 드로 콜 ≤ 약 150. 정적 구장 메시는 병합·인스턴싱. 예산 안에서 최대한 정교하게 만든다.
- **에셋이 모자라면**: 먼저 `kaykit-catalog` 에서 찾고(`node tools/kaykit-find.js 단어`), 코드·텍스처로 직접 만든다. 그래도 부족하면 필요한 에셋이 무엇인지 선생님께 알린다.
- **검수**: 투수 시점·타자 시점·외야 와이드·홈런 장면 스크린샷 4장(가로 1600×900)과 갤럭시탭 해상도 1장을 보고서에 붙인다.

### 11.2 캐릭터·소품
- **외형**: 공용 `CharacterModelFactory`(`ts/common/character-kit.ts`)로 만든 학생 캐릭터 한 명을 투수/타자/주자 모두에 사용.
- **상대 수비수 8명**: 같은 방식으로 카탈로그 외형 중 임의 선택(고정 시드). 수비 팀은 팀 색 모자(코드로 만든 반구 + 챙)로 구분.
- 소품(코드): 야구공(구 + 실밥 캔버스 텍스처), 배트(LatheGeometry 길이 0.86m, 손에 붙임), 글러브(납작한 반구, 왼손), 헬멧(타자). 부착 위치 보정은 시험 페이지에서 눈으로 맞춘다.
- 애니메이션 클립(`kaykit-catalog/names.md` 확인, 실제 이름은 구현 때 `kaykit-find`로 재확인):
  | 장면 | 후보 클립 |
  |---|---|
  | 스윙 | **절차 포즈 `BatSwingPose`**(0.2절). 칼 휘두르기 클립은 쓰지 않는다 |
  | 투구 | `Throw` 기반 + 릴리스 프레임에 공이 손 뼈에서 떠나도록 메타데이터·보정(0.2절). 부족하면 `PitchPose` |
  | 포구(땅볼·뜬공·송구) | 절차 포즈 `CatchPose` + 글러브 소품. 포구 프레임이 공 도착 시각과 같게 **미리** 시작 |
  | 송구 | `Throw` 기반 + 릴리스 프레임·손 뼈 부착(0.2절), 궤적은 9.6절 |

- 환호·세리머니·실망 동작은 만들지 않는다. 분위기는 관중과 소리로만 표현한다.
- 애니 재생 시 타이밍이 중요한 클립(투구 릴리스, 스윙 접촉)은 **메타데이터(릴리스/접촉 프레임 비율)** 를 클래스에 둔다.

### 11.3 관중 `CrowdSystem` (모두 같은 동작 금지)
- 구성: **가까운 줄 24명 정도는 스킨드 캐릭터**(애니메이션 믹서), 나머지 수백 명은 **InstancedMesh의 간단한 사람 모양**(몸통+머리+양팔, 인스턴스 색 랜덤)으로 CPU 20Hz 갱신(보이는 구역만).
- 개인 변수: 반응 지연 0~0.6초, 속도 0.85~1.15배, 위상 랜덤, 강도 랜덤, 응원 팀 소속(홈/원정/중립), 동작 변형 3~4종. 약 20%는 반응하지 않거나 늦게 반응.
- 상태 기계: `앉아 있음` → `박수` → `환호(두 팔 번쩍)` → `점프` → `파도타기` → `탄식(고개 숙임)`.
- 사건별 반응:
  | 사건 | 반응 |
  |---|---|
  | 투구 대기 | 일부 앉아 있음, 일부 작게 흔들림 |
  | 2스트라이크 또는 풀카운트 | 일부 일어나 리듬 박수 |
  | 삼진/아웃 | 수비 팀 응원 환호, 공격 팀 응원 탄식 |
  | 안타/득점 | 공격 팀 응원 환호·점프, 깃발(KayKit BoardGame `flag_*`) 흔들기 |
  | 홈런 | 전원 환호 + **파도타기(관중석 각도에 따른 지연 전파)** |
  | 위기(득점권 주자) | 박수 리듬 강화 |
- 성능: 갤럭시탭에서 카메라가 주로 필드를 보므로 관중은 LOD로 줄이고 `QualityGovernor` 단계에서 가장 먼저 줄인다(스킨드 수 → 인스턴스 갱신 주기 → 인스턴스 수).

### 11.4 효과
흙먼지(슬라이딩·베이스 도착), 타구 순간 작은 스파크, 공 트레일, 홈런 시 불꽃(저비용 입자, **미리 풀을 만들어 재사용·게임 중 생성 금지**), 득점 시 +1 팝업, 카운트다운 중 이펙트를 한 번 그려 첫 사용 끊김 제거(성능 지침).

### 11.5 사운드 `SoundDirector` 【보충】
응원·투구·타격·포구 등 효과음을 **파일 없이 WebAudio 합성**으로 만든다(저장소 용량·로딩 시간 절약, 나중에 실제 녹음 파일로 바꿔 끼울 수 있게 `SoundCue` 가 합성/파일 둘 다 받는다).
| 사건 | 소리 | 만드는 법 |
|---|---|---|
| 관중 기본 | 낮은 웅성임, 천천히 출렁 | 분홍 잡음 + 저역 필터, 음량 느린 LFO |
| 투구 와인드업·릴리스 | 슉 | 대역 통과 잡음 스윕 0.25초, 구속 빠를수록 높음 |
| 포구 | 팡(글러브) | 짧은 잡음 버스트 + 저음 사인 감쇠 0.12초, 빠른 공일수록 큼 |
| 스윙(헛) | 휙 | 잡음 스윕 |
| 타격 | 딱/빡 | 아주 짧은 클릭 + 450Hz~1.2kHz 공명 감쇠. 정타는 맑고 높게, 빗맞음은 둔탁하게 |
| 파울 | 틱 | 작은 딱 |
| 땅볼 굴러감·송구 | 구르는 낮은 잡음 / 슉 → 포구 팡 |
| 베이스 밟기·태그 | 퍽 / 탁 |
| 슬라이딩 | 쓰으윽 | 잡음 + 저역 필터 0.5초 |
| 안타·득점 | 환호 + 박수 2초 | 대역 상승 잡음 + 박수 임펄스 |
| 홈런 | 큰 환호 + 박수 + 짧은 팡파르(사각파 3음) 4초 | |
| 삼진·아웃 | 수비측 환호 짧게, 공격측 탄식 | 하강 필터 잡음 |
| 2스트라이크·풀카운트 | 리듬 박수 | 짝짝 짝짝짝 임펄스 |
| 득점 +1 | 짧은 종소리 | 사인 배음 |
| 공수 교대 | 짧은 징글 | 사각파 3음 |

- 첫 터치 때 `AudioContext` 를 깨운다(브라우저 정책). 소리 버퍼는 **로딩/카운트다운 때 `OfflineAudioContext` 로 미리 만들어 두고** 게임 중에는 재생만 한다(성능 지침). 동시 발음 8개 제한.

- 클래스: `SoundDirector`(사건 → 소리), `SynthBank`(버퍼 만들기), `CrowdVoice`(관중 층), `SoundCue`.

### 11.6 구장 확장 `BallparkSpec` (지금은 `기본 1구장` 하나)
- 구장은 `BallparkSpec {id, name, fence: FenceProfile, wallHeight, parts: BallparkPart[]}` 로 정의한다. `BallparkPart` 는 잔디·내야 흙·펜스·스탠드·배경·조명탑 같은 **조립 부품**이라, 나중에 여러 구장을 부품 조합으로 만들 수 있다.
- `BallparkRegistry` 가 구장 목록을 가진다. 지금은 `MainBallpark`(9.1절 치수) 하나. 방과 매칭 표에 `parkId` 를 적어 두고 모두 같은 구장을 만든다.
- **규칙 엔진은 구장 모양을 모른다**: 펜스 거리·높이·파울 지역은 `FieldDimensions` 인터페이스로만 읽는다(`MainBallpark` 가 구현). 구장이 바뀌어도 규칙·시뮬레이션이 그대로 돈다.
- 구장 선택 UI(방 화면)는 구장이 2개 이상일 때 나타난다(5.2절).

## 12. AI

**AI 능력치는 어떤 난이도에서도 고정 `3/3/3`(투수 제구·구위·변화, 타자 컨택·파워·주루)** 이다. 난이도는 **판단력**으로만 나눈다(이전 초안의 "어려움 4/4/1" 같은 값은 폐기 — 특정 배분이 더 강한지 시험한 적이 없었고, 포인트 배분 사이의 유불리를 크게 두지 않는다는 방침과 어긋난다).

### 12.1 AI 투수 (`AiPitcher`)
- 구종 선택은 켜진 변화구(기본 순서)에서. 변화 3이면 `직구·커브·슬라이더`.
- 구종·위치 전략(카운트 기반):
  - 투수에게 유리(볼 < 스트라이크): 존 바로 바깥 `|s|≈1.15` 부근을 노려 유도, 변화구 비중 증가.
  - 불리(볼 ≥ 3 또는 풀카운트): 존 안 가장자리(중앙은 피함) 직구 위주.
  - 직전 구종과 다르게 섞는다(타이밍 흔들기).
- 난이도: 쉬움 = 목표점 오차 큼(가끔 한가운데)·구종 혼합 약함, 보통 = 위 전략, 어려움 = 목표점 정밀·카운트별 구종 최적화·같은 위치 반복 회피.
- AI도 조준 제한(7.5절)을 지킨다.

### 12.2 AI 타자 (`AiBatter`)
- 스윙 판단: 공의 진짜 위치 `(s,y)` 에 읽기 오차 `σ_read`(쉬움 0.45, 보통 0.30, 어려움 0.18)를 더해 "존 안"으로 판단되면 스윙. 2스트라이크면 존 확대(`r<1.15`), 3볼이면 거의 안 침.
- 타이밍: `Δ_adj ~ N(m, σ_t)`, `σ_t` 쉬움 85ms / 보통 62ms / 어려움 45ms. 느린 구종 직후에는 빨리 휘두르는 편향(−15~−30ms).
- AI는 **같은 판정 엔진**을 쓴다(점수 따로 주지 않음).

### 12.3 목표 지표 (선생님 지정, 보통 vs 보통 — 17.2 시뮬레이션이 맞춘다)
| 지표 | 목표 |
|---|---|
| 타율 | **.400 ± .030** |
| 출루율 | **.450** (± .030) |
| 장타율 | **.600** (± .050) |
| 타석당 홈런 | **10%** 정도(8~12%) |
| 그 밖의 값(삼진률·볼넷률·땅볼:뜬공·하프 이닝 득점·투구 수) | **미정 — 시뮬레이션하며 조정**(출발점: 삼진률 12~16%, 볼넷률 약 8%, 땅볼:뜬공 1:1) |
- 목표: **타격이 시원시원해서** 재미있게. 기존 초안의 .260/.330/.400/2% 는 폐기.
- **초기 값이 목표에 못 미친다**: 8.7절 EV 혼합표와 8.4절 접촉 확률은 이전 목표용이므로 M0에서 **EV 분포를 위로(정타·양호의 고속 성분 비중·가운데 보정을 키움), 접촉 확률 상향**으로 올려 맞춘다. **펜스는 중앙 120m·좌우 100m로 고정**(9.1절)이므로 홈런 10%는 **비거리(EV 분포와 8.7절 비거리 표)를 올려서** 맞춘다. 표를 바꾸는 곳은 `ExitSpeedModel`·`ContactModel` 두 클래스뿐.

## 13. 네트워크 · 재접속 · 부정 방지

기본은 `ts/common/room-kit.ts`(`Rk*`, 35번 방식)로 방·관전·방장을 처리한다. 방 경로 `baseballduel/rooms/<code>` (정확한 이름은 35번 노트의 규칙에 맞춘다).

### 13.1 쓰기 규칙: **한 번 쓰면 바꿀 수 없다**
방 아래 `log/<seq>`에 투구마다 항목을 **append-only**로 쌓는다. Firebase 규칙에서 해당 경로는 `!data.exists()`일 때만 쓸 수 있게 한다(덮어쓰기·삭제 금지).
| 키 | 쓰는 사람 | 내용 |
|---|---|---|
| `turn/<seq>` | 해결자 | 카운트·아웃·주자 상태, 마감 서버시각 `deadline`, 어느 쪽이 투수/타자 |
| `pitch/<seq>` | 투수(또는 AI 대행) | 구종, 조준점, 쓴 시각 |
| `roll/<seq>` | 해결자 | **시드**, 실제 도착 위치, 구속, `releaseAt`(서버시각 +0.9초), 이상 타이밍 잡음 `n` |
| `swing/<seq>` | 타자 | 누른 서버시각(`t_press`). 마감까지 안 누르면 해결자가 "없음"을 쓴다 |
| `play/<seq>` | 해결자 | 판정 + `PlayScript` |
- 경기 상태는 **로그를 처음부터 접어서(fold) 만든다.** 누구든 로그만 있으면 같은 상태를 재현한다.
- 결과 난수(도착 위치·타구)는 **투구 확정 직후 서버가 정한 시드**로 결정한다. 시드는 투수가 확정(`pitch`)하는 순간 해결자가 쓰므로 새로고침으로 다시 뽑을 수 없다.
- 해결자는 기본적으로 방장. **방장이 끊기면 경기는 정지**하고(13.3절), 45초 안에 돌아오지 않으면 **상대 선수가 해결자(와 시계)를 이어받아** 같은 입력·시드로 계산해 쓴다(먼저 쓴 쪽이 이김, 규칙이 덮어쓰기를 막는다). 순수 함수이므로 누가 계산해도 같다.

### 13.2 시간 동기
- 클라이언트는 `.info/serverTimeOffset`으로 서버 시각 오차를 구한다.
- **시계는 방장 한 곳**(3.3절): 모든 마감(`deadline`)·릴리스 시각·자동 투구·"치지 않음"은 **방장 기기가 서버 시각 기준으로 기록**하고, 손님·관전자는 그 값으로 남은 시간·연출 시각을 계산해 표시만 한다. 손님 기기가 독자적으로 시간을 재거나 자동 처리를 만들지 않으므로 두 화면의 타이밍이 어긋나지 않는다.
- 투구는 `releaseAt = 서버 now + 0.9초`로 **예약**한다. 두 화면 모두 서버 시각 기준으로 같은 순간에 릴리스·비행을 시작하므로 네트워크 지연이 타자에게 불리하게 작용하지 않는다(메시지가 릴리스 전에 도착한다는 전제).
- 스윙 시각도 서버 시각 기준으로 기록한다. 판정 `Δ`는 `t_press`와 `releaseAt`로 해결자가 계산.

### 13.3 끊김·재접속 (선생님 요구)
요구: 끊겼다 다시 들어오면 **끊기기 전까지의 모든 상황을 보존**하되 **진행된 플레이를 되돌릴 수 없다**.
- 방 코드·내 id·내 정보는 기기에 적어 둔다(`RoomResumeStore`, 30번과 같은 규칙. `ts/common/room-drop-recovery.ts` 재사용). 새로고침/탭 복원/와이파이 복귀 시 같은 id로 같은 자리에 다시 들어간다.
- 복귀하면 `log`를 읽어 접기 → 점수·카운트·주자·현재 이닝 복원. 진행 중이던 연출은 재생하지 않고 **최종 상태로 맞춘다** + 토스트("방금 상황을 불러왔어요").
- 단계별 처리:
  | 끊긴 시점 | 복귀 후 |
  |---|---|
  | 투수가 구종/위치를 고르는 중(아직 확정 안 함) | 같은 화면에서 계속 고름. **마감 시각은 늘어나지 않음** |
  | 투수가 확정한 뒤 | 선택 변경 불가. 시드·도착 위치는 이미 기록됨 |
  | 타자: 공이 오는 중 | 마감 전이면 스윙 가능(서버 시각 기준), 지났으면 "치지 않음"으로 이미 기록됨 |
  | 타구 연출 중 | 결과는 이미 `play`에 기록되어 있으므로 되돌릴 수 없다 |
- **악용 방지**:
  1. 홈런을 맞고 새로고침해도 결과는 로그에 영구 기록 → 되돌릴 수 없다.
  2. 새로고침으로 투구 결과를 다시 뽑을 수 없다(시드 고정).
  3. 한 계정의 두 탭: 마지막 탭만 유효, 이전 탭은 "다른 화면에서 접속했어요" 표시.
  4. **상대가 끊기면 게임을 정지한 채 잠시 기다린다**(`PauseCoordinator`): 마감 시계도 멈추고 화면에 "상대 재접속 대기 중"을 표시. **상대가 다시 접속하면 3초 뒤(`3·2·1` 표시) 경기를 재개**하고 남은 시간은 멈춘 시점 그대로 이어 간다. 대기 한도는 한 번 45초, **한 판에서 선수 한 명당 누적 90초**를 넘으면 그 선수 기권 패 【확인】. 방장이 끊긴 경우도 같고, 45초가 지나면 손님이 방장을 이어받는다(13.1절).
  5. 서버 시각 기준 마감이라 기기 시계를 바꿔도 영향 없음.
  6. 제한: DB를 F12로 읽으면 투수의 확정된 구종·위치가 투구 직전 짧은 시간 보일 수 있다. 수업용 수준에서는 허용하되, `pitch` 노드는 **투구 확정 후에만** 쓰고(구종 선택 중에는 기기 안에만 보관) 노출 시간을 최소화한다 【보충】.
- 방장이 완전히 나가면 상대가 방장을 승계(`host-takeover-unit.js` 방식). 상대도 없으면 방은 3시간 뒤 청소.
- 랜덤 매칭: 14절의 `MkParty` 복구와 표(`ticket`) 보존으로 같은 방에 돌아온다.

### 13.4 쓰기 빈도 (선생님 확인 필요) 【확인】
투구 한 번에 쓰기 약 4회(`pitch`, `roll`, `swing`, `play`), 읽기는 이미 구독 중인 경로만. 한 판(약 30~45투구) 약 120~180회 쓰기. 폴링 없음, 모두 `on('value'/'child_added')` 구독. 이보다 늘리려면 먼저 묻는다.

### 13.5 DB 규칙 (데이터베이스규칙.json) 【보충】
- `baseballduel/rooms/$code/log/$seq/*`: `.write = !data.exists()`, 값 범위(좌표 ±2.5, 구속 80~170, 시각 증가) 검증.
- `matchQueue/baseballduel`, 팀 대기실 경로 추가(다른 게임과 같은 형식).
- `users/$uid/stats/baseballduel`(15.3절 구조: `bat`·`pit`·`byType`·`best`·`zones`·`byAbility`·`rm`), `recent/baseballduel/$slot`, `pending·streak·gameRanks`의 `$game` 정규식에 `baseballduel` 추가.
- `baseballduel/board/$uid`(공개 읽기, 본인만 쓰기, 값은 증가만) — 랭킹 표·핫콜드존용. `baseballduel/settings/zones`(교사만 쓰기, 핫콜드존 스위치).
- 득점 상한이 없으므로 점수·타석 수 검증은 현실적인 최대치(예: 한 판 타석 ≤ 60)만 둔다.
- 바꾼 뒤에는 **선생님이 콘솔에 다시 게시해야 한다고 알린다.**

## 14. 랜덤 매칭 · 대결 화면

### 14.1 방식
24번 터보 랩의 1대1 매칭 구조를 그대로 쓴다: 공용 `ts/common/match-kit.ts`의 `MkRandomFlow` + `MkVersusMatcher`(2명 한 판), 방은 `RkMatchHooks`로 연결(35번 방식).
- 초기화면 `랜덤 매칭 방 만들기` → 팀 대기실(1인 팀) → `매칭 시작` → 대기열.
- **AI 대체**: 24번과 같이 `aiFallbackMs`(2분) + "🤖 AI와 바로 시작" 버튼 【보충】. AI 판은 통계·연승·최근 20매치에 남지 않는다("vs AI" 표시).
- 표(`ticket`)에 상대 정보를 싣는다(방장 = 말 공격이라 선공 추첨 정보는 없다).
- `MkVersionGate`로 버전이 다른 클라이언트끼리는 매칭하지 않는다(캐시 때문에 규칙이 다른 두 기기가 붙는 사고 방지).

### 14.2 **이전에 겪은 버그 방지 체크리스트** (random-match-prompt.md 기록 기반)
구현 세션은 아래를 하나하나 확인하고 시뮬레이터로 검사한다.
1. 취소 직후 다시 매칭할 때 "표 없이 사라짐" 복구 타이머가 새 매칭을 지우던 문제 → 취소 중에는 복구를 걸지 않고, 복구는 자기가 시작한 찾기(`since` 같음)만 푼다(`localEcho` 시뮬).
2. 끊긴 팀 대기실 코드를 새 대기실이 덮어쓰던 문제 → `MkPartyDirectory.create`는 빈 자리에만. 기기에 `MkPartyMemory`로 코드·닉네임·id를 적어 새로고침 뒤 `reclaim`으로 이어 쓴다.
3. 같은 상대 반복·AI 판 한 팀에 몰림 → `avoid`/`owed`, `MkBusySign`, `rematchWaitMs`(AI 대체 + 30초). `MATCHER_TIMING`을 24번처럼 41번 전용으로 둔다.
4. 결과 화면에서 바로 팀 대기실로 나가면 전적 기록이 빠짐 → **나가기 전에 먼저 기록**(`recordBeforeLeave`).
5. 표의 상대가 끝내 안 와서 AI와 한 판이 사람 이름으로 남음 → 실제 방에 들어온 상대만 전적에 남긴다(`rivalIds`, `presentIds`, `seenRivals`). 아무도 안 왔으면 "vs AI".
6. 대결 화면에 방의 기본값/지난 판 값이 먼저 보임 → 상대 정보는 **표(ticket)** 에서 읽는다.
7. 판이 끝나 팀 대기실로 돌아올 때 표(`match`) 지우기(`backToParty → clearTicket`).
8. 일반 방에서 시작할 때 `vsAt`을 쓰고 모두가 구독해 같은 막을 띄운다. `vsAt` + 표시 시간 + 3초 뒤 자동 닫기, 경기 시작 시 2초가 안 됐으면 채우고 닫기.
9. 잠깐 끊김 복구: `MkParty`는 스스로 나간 게 아니면 자리를 되살리고 `onDisconnect`를 다시 건다. 방은 `RoomDropRecovery`.
10. 중간 이탈 패배: 나가기 버튼으로 경기 중 나가면 진행도가 절반 이상일 때 확인 문구 + 패 기록(`MkForfeit`). **진행도** = (끝난 하프 이닝 수 + 현재 아웃/3) ÷ (`MatchFormat` 의 전체 하프 이닝 수; 지금은 2). "← 목록으로"·탭 닫기는 세지 않는다. 재접속 대기 누적 90초 초과 기권도 패.
11. 매칭 시뮬 `node tools/match-sim.js`가 통과해야 하고, `tools/match-result-check.js`에 41번을 등록해 "매칭 → 대결 화면 → 경기 시작과 함께 닫힘 → 결과 기록"을 검사한다. 새 게임 키는 `tools/account-stats-unit.js`에도 추가.
12. 핫 리로드·캐시: 고친 `.js`는 HTML의 `?v=` 값을 올리고 `sw.js` 캐시 목록 갱신 필요 여부를 확인한다 【보충】.

### 14.3 대결(매칭) 화면 — 공용 모듈 `VersusCurtain` + 게임별 내용
**공용 틀과 게임 내용을 나눈다.** 30번 `ArenaVersusCurtain`·24번 `TurboLapVersusView`·41번이 모두 쓰도록 `ts/common/versus-curtain.ts` 로 새로 만들고, 게임마다 필요한 줄이 달라도 코드를 복사하지 않게 한다.
| 클래스 | 책임 |
|---|---|
| `VersusCurtain` (공용) | 화면 전체를 덮는 어두운 반투명 막, 왼쪽 선수 \| VS \| 오른쪽 선수 틀, 크기(vw·vh), 760px 이하 위아래 쌓기, 등장·퇴장 애니메이션, `vsAt` + 표시 시간 + 자동 닫기, "경기 시작과 함께 닫힘" 훅(14.2절 8번) |
| `VersusSideData` (공용) | 한쪽 선수 데이터: 닉네임, 초상화(3D 썸네일 또는 이미지), `kind`(`player`/`ai`/`pending`), 게임이 채우는 `payload`(임의 자료) |
| `VersusCurtainContent` (공용 **인터페이스**) | 게임이 구현한다: `rowsFor(side): VersusRow[]`(그 선수 아래에 쌓을 줄들), `centerBadge()`(VS 자리), `footer()`(선택) |
| `VersusRow` 부품 (공용) | `TextRow`(한 줄 글), `StatRow`(이름·값 묶음 여러 개), `PortraitStripRow`(작은 초상화 여러 개), `ChipRow`(작은 칩). 게임이 새 줄 종류를 `VersusRow` 를 상속해 더할 수 있다 |
- 공용으로 뽑는 것은 **틀·타이밍·반응형·줄 부품**이고, **어떤 줄을 어떤 값으로 보여 줄지는 게임의 `VersusCurtainContent` 구현**이 정한다. 기존 24·30번은 41번이 끝난 뒤 이 공용으로 옮긴다(별도 작업, 옮기기 전과 화면이 같은지 확인하고 선생님께 알린다).
- 41번 구현 `BaseballVersusContent` 가 만드는 줄(선생님 지정):
  1. **초상화(각자 꾸민 캐릭터) + 닉네임**
  2. 그 아래 줄: **승률 · 평균 득점 · 평균 실점**
  3. 그 아래 줄: **타격 성적 — 타율 · OPS · 홈런 수**
  4. 그 아래 줄: **투수 성적 — 평균자책점 · WHIP · 피OPS**
- 데이터는 **랜덤 매칭 판만** 센 값(`stats/baseballduel/rm`, 15.3절). 일반 방에서 띄울 때도 같다(2026-10-29 결정). 기록이 없으면 `기록 없음`, AI는 `🤖 AI`, 아직 안 들어온 사람은 `입장하는 중…`.
- 각자 자기 요약(`rm` 의 위 숫자들)을 팀 대기실에 들어갈 때 한 번 읽어 방에 들어갈 때 자기 자리에 함께 쓴다(쓰기 횟수 늘리지 않음). 다른 학생 계정은 읽지 않는다.
- 방장은 막이 뜬 지 4초가 지나야 경기를 시작한다. 일반 방(사람 대 사람)도 같은 막을 띄우고 AI·연습은 띄우지 않는다.
- 크기 확인: 1600×900·1280×800·760px 이하(위아래 쌓기), 세로 390×844. 예시 사진을 찍어 보고한다.

### 14.4 결과 화면 (30번 아레나 흐름)

## 15. 통계

### 15.1 무엇을 기록하나 — **사람과의 대전만** (AI·연습은 기록하지 않음)
일반 방(사람 대 사람)과 랜덤 매칭(사람 대 사람)은 계정 통계에 쌓는다. 랜덤 매칭 판은 `rm` 에도 따로 센다 【확인 ★ 일반 방도 포함】. 판이 끝날 때 **한 번만** 기록한다.

**원자료(저장하는 것)** — 모든 표시 통계는 이 원자료로 계산한다.
- `BatCounts` (내가 타자였을 때): 타석 `pa`, 타수 `ab`, 안타 `h`, 2루타 `d2`, 3루타 `d3`, 홈런 `hr`, 볼넷 `bb`, 삼진 `k`, 희생플라이 `sf`, 타점 `rbi`, 득점 `r`, 실책 출루 `roe`.
- `PitCounts` (내가 투수였을 때, **상대 타자 기준으로 센 값**): 상대 타자 수 `bf`, 타수 `ab`, 피안타 `h`, `d2`, `d3`, 피홈런 `hr`, 볼넷 `bb`, 탈삼진 `k`, `sf`, 잡은 아웃 수 `outs`, 실점 `r`, 자책점 `er`, 투구 수 `pitches`, 스트라이크 수 `strikes`.
- 대전: 게임 수 `g`, 승 `w`, 패 `l`, 무 `t`, 득점 합 `rf`, 실점 합 `ra`. 구종별 `byType`, 최고 기록 `best {dist, exit}`.
- **자책점 규칙(단순화)** 【보충】: 실책(9.6절)으로 출루·진루한 주자의 득점, 그 실책 이후 같은 하프 이닝의 득점, **승부치기 시작 주자**의 득점은 자책점이 아니다.
- 실책으로 출루하면 타수 1(안타 아님), 출루율 분자에는 들어가지 않는다.

### 15.2 화면에 보이는 통계 (선생님 지정)
**타자**: 게임 수 · 타석 수 · 타수 · **타율** · **출루율** · **장타율** · OPS · 득점 · **홈런율** · 삼진 · **삼진율** · 볼넷 · **볼넷율** (+ 홈런 수, 2·3루타)
**투수**: 게임 수 · 이닝 · **평균자책점** · **WHIP** · 삼진 · **삼진률** · 볼넷 · **볼넷율** · 피홈런 · **피홈런율** · **피OPS**
**플레이어**: **승률** · **평균 득점** · **평균 실점** (+ ○승 ○패 ○무)

**계산식**
- 타율 = H ÷ AB / 출루율 = (H + BB) ÷ (AB + BB + SF) / 장타율 = TB ÷ AB (TB = 1루타 + 2×2루타 + 3×3루타 + 4×HR) / OPS = 출루율 + 장타율
- 홈런율 = HR ÷ PA / 삼진율 = K ÷ PA / 볼넷율 = BB ÷ PA (타자)
- 이닝 = 아웃 ÷ 3 (표기 `5.2` = 5⅔) / 평균자책점 = 9 × ER ÷ 이닝 / WHIP = (BB + H) ÷ 이닝
- 삼진률 = K ÷ BF / 볼넷율 = BB ÷ BF / 피홈런율 = HR ÷ BF (투수)
- 피OPS = 상대 출루율 + 상대 장타율 (`PitCounts` 로 같은 식)
- 승률 = W ÷ (W + L + T) / 평균 득점 = RF ÷ G / 평균 실점 = RA ÷ G
분모가 0이면 `-`. 율은 `.xxx`, 평균은 소수 둘째 자리, 이닝은 `5.2` 식. 계산은 `BaseballFormulas` 한 클래스.
(1대1이라 개인 득점 R 은 팀 득점과 같다 【보충】.)

### 15.4 랭킹 표 (초기화면 우측, `BaseballBoardPanel`)
1. 위쪽 토글 `타자` / `투수`.
2. **타자**를 누르면 계산되는 **스탯 이름 버튼**이 나온다: 게임 수·타석·타수·타율·출루율·장타율·OPS·득점·홈런·홈런율·삼진·삼진율·볼넷·볼넷율. **투수**는 게임 수·이닝·평균자책점·WHIP·삼진·삼진률·볼넷·볼넷율·피홈런·피홈런율·피OPS.
3. 이름 버튼을 누르면 **하단에 그 스탯 상위 10명**(순위·닉네임·값)이 나온다. 스탯마다 "좋은 쪽이 위"(타율·홈런은 높은 순, 평균자책점·WHIP·피OPS·타자 삼진율은 낮은 순).
4. 비율 스탯은 **규정 최소치**를 넘은 선수만 랭크한다(확정): **타자 10타석 이상, 투수 3이닝(아웃 9) 이상**.
5. 범위 버튼 `우리 반` / `전체` 로 **학생이 고른다**(기본 우리 반). **교사 제어판은 전체 학생이 모두 보인다**(반 필터 선택 가능).
6. 데이터는 `baseballduel/board` 를 **화면을 열 때 한 번** 읽는다(폴링 없음, `새로고침` 버튼으로만 다시). 교사 제어판에는 모든 플레이어의 성적이 있다(15.7절).

### 15.5 핫콜드존 (교사가 켜고 끈다)
- **9분할**: 스트라이크 존을 3×3(구역 0~8)으로 나눈다(존 밖은 `out` 로 따로 셈).
- 기록(계정별 누적, 사람 대전만, `board/$uid/zones` 에 공개):
  - 타자: 구역별 `{n 받은 공 수, ab, h, tb}`. 구역 타율이 그 선수의 전체 타율보다 `+0.08` 이상 높으면 **핫(빨강)**, `−0.08` 이하이면 **콜드(파랑)**, 사이는 연한 색. 표본이 부족하면(구역 타수 5 미만) 회색.
  - 투수: 구역별 던진 공 수 `n` 의 비율. **많이 던지는 구역일수록 진한 색.**
- **누가 무엇을 보나**: **투수는 상대 타자의 핫콜드존**을(투구 확대 창 안 + 타자 카드), **타자는 상대 투수가 많이 던지는 위치**를(투수 카드의 미니 존) 본다. 상대가 AI·로그인 안 한 사람·기록 없음이면 표시하지 않는다.
- **교사 스위치**: 교사 제어판 `핫콜드존 보이기` 켜기/끄기(`baseballduel/settings/zones`, **기본 꺼짐** ★). 꺼져 있으면 화면에도 안 나오고 데이터도 읽지 않는다.

### 15.6 포인트별 성적 (교사 전용)
- 경기 중 능력치는 바뀌지 않으므로, 한 판의 타격·투구 원자료를 **그 판에 쓴 배분**에 묶어 계정에 쌓는다: `byAbility.bat["컨택-파워-주루"]`, `byAbility.pit["제구-구위-변화"]` = `{g, …BatCounts / PitCounts}`.
- **교사 제어판에서만** 보인다. `포인트별 성적` 탭: 타자 28행(컨택·파워·주루 배분)과 투수 28행(제구·구위·변화 배분) 표. 열: 게임 수, 타석(또는 상대 타자), 타율, 출루율, 장타율, OPS, 홈런율, 삼진율, 볼넷율(투수는 피OPS·평균자책점·WHIP·승률). 정렬 가능, 표본이 적은 행은 회색. 학생 화면에는 없다.
- 목적: 어떤 배분이 지나치게 유리하지 않은지 실제 플레이 자료로 확인하고 8.10절 계수를 고친다(17.2절 시뮬레이션과 대조).

### 15.7 교사 제어판
`admin.html` 의 `RankGame.GAMES` 에 41번을 넣고, 학생 이름을 누르면 학생이 보는 것과 같은 개인 통계 창(최근 20매치 → 결과표 포함)이 열리게 `account({profile, view})` 를 넘긴다. 반 별 정렬 기준 기본 OPS와 승률 【확인】. 추가 탭: `포인트별 성적`(15.6), `핫콜드존 보이기` 스위치(15.5).

## 17. 검사 도구와 수치 확정 절차

**3D 작업 전에 규칙 엔진을 먼저 만들고 시뮬레이션 보고서를 선생님께 보여 수치를 확정한다.** 검사 도구는 다른 컴퓨터에서도 쓰도록 `tools/` 에 커밋한다.

### 17.1 `node tools/baseball-unit.js` (단위 검사)
1. `PitchLocationSampler`: 모든 표본이 절단 범위 안(구종 5개 × 제구 1~7 × 좌/우투 각 1만 번).
2. **조준 제한(사구 0)**: 모든 구종·제구·타자 손·조준 후보에서 `AimLimiter` 가 돌려준 조준점의 후보 범위가 `|u|,|v| ≤ 2.2` 안이고, 어떤 표본도 `±2.2` 밖으로 가지 않는다.
3. **스트라이크 판정**: `|u|=1`·`|v|=1` 경계 점은 스트라이크, 바로 바깥은 볼. 같은 입력 100번 → 같은 판정(흔들림 없음).
4. 능력치 규칙(`PitcherAbilities`·`BatterAbilityModel`·`AbilityAllocator`): 합 9, 각 1~7, 3/3/3 시작, 28가지 배분 열거, 변화 포인트별 구종 수(1·2→1, 3·4→2, 5·6→3, 7→4), **구종 칩 규칙**(순서대로 켜짐, 켜진 칩을 누르면 꺼지고 남은 수 +1, 남은 수가 있을 때 꺼진 다른 칩을 켜면 교체, 포인트를 내리면 뒤 칩부터 꺼짐).
5. 카운트/아웃/주자 전이 50가지 이상: 볼넷 밀어내기, 삼진, 파울(2스트라이크 뒤 불변), 병살, 희생플라이, 포스/태그, 득점 인정(3아웃째 포스 시 불인정), **득점 상한 없음**(20점 넘게 나는 시나리오), 연장(10회 무사 1·2루, 11~15회 무사 만루, 15회 동점이면 무승부), 끝내기(끝내기 문구 포함), 말 생략, **인필드 플라이**(성립·불성립 조건), **실책 5%(내야 땅볼만, 끄면 0)**, 태그업·리터치, 병살 상황에서 병살 성립.
6. 스프레이·펜스: 8.9절 예 A·B·C 재현.
7. 결정성: 같은 입력·시드 → 같은 `PlayScript`. 로그를 임의 지점에서 끊고 접어도 같은 상태.
8. `MatchFormat`: `OneInningFormat` 으로 9회 초·말, 같은 엔진에 `ThreeInningFormat`·`FullGameFormat` 을 넣어도 진행(회차를 코드에 박지 않았다는 증명).
9. 통계 공식(타율·출루율·장타율·OPS·홈런율·삼진율·볼넷율·평균자책점·WHIP·피OPS·이닝 표기), AI/연습 제외, 자책점 규칙.
10. 구장 치수: 베이스·펜스 함수 값, `FieldDimensions` 교체 시 규칙이 그대로 동작.

**`node tools/baseball-ability-check.js` (능력치 반영 검사 — 투수·타자 모두)**
각 능력치를 1~7로 바꿔 가며(다른 능력치는 기준 3 고정) **의도한 값이 의도한 방향으로 바뀌고, 다른 값은 안 바뀌는지** 확인하고 표와 `정상/이상` 판정을 출력한다(단조성 위반이면 FAIL).
| 대상 | 능력치 | 확인하는 것 |
|---|---|---|
| 투수 | 제구 | 도착 σ·후보 범위 면적 단조 감소(표본 표준편차로 측정), 구속·구종 수는 불변 |
| 투수 | 구위 | 직구 구속 `126+3.5p` 정확, 모든 구종 구속 단조 증가, 범위 불변 |
| 투수 | 변화 | 고를 수 있는 변화구 수 1·1·2·2·3·3·4, **변화구 각(장축 반경) `BREAK_SCALE` 단조 증가**(구종별 표본 측정), 직구는 변화 포인트에 영향 없음 |
| 타자 | 컨택 | 정타 폭 `W`·밴드 폭 배율이 포인트에 비례, 같은 스윙 타이밍 분포에서 접촉률·정타율 단조 증가 |
| 타자 | 파워 | 같은 타이밍·코스에서 타구 속도 평균·비거리 평균·홈런율 단조 증가 |
| 타자 | 주루 | 타자 주자 1루 도달 시간 단조 감소, 땅볼 세이프율·병살 회피율·외야 안타 시 추가 진루율 단조 증가 |
출력은 콘솔 표 + `sim-reports/baseball-ability-check.csv`.

### 17.2 `node tools/baseball-sim.js` (밸런스 시뮬레이션)
- **기본 보고서**: 보통 vs 보통 AI(3/3/3 대 3/3/3) 2만 하프 이닝. 타석 결과 분포, 타율·출루율·장타율·OPS, 타석당 HR, 삼진률·볼넷률, 땅볼/라인드라이브/뜬공 비율, **타이밍 밴드별 비거리 히스토그램**(10m 단위), 위치(중앙/모서리/바깥)별 정타율, 하프 이닝 평균 득점·투구 수, 홈런 방향 분포, 구종별 스트라이크율·피안타율, **12.3절 목표표와 나란히** 비교.
- **능력치 균형 보고서 `--abilities`**: ① 타자 28가지 배분 × 표준 투수(3/3/3) ② 투수 28가지 배분 × 표준 타자 ③ 28 × 28 전체 교차(784쌍). 배분마다 OPS·홈런율·삼진률·**하프 이닝 기대 득점**을 구해 **전체 평균 대비 편차(목표 ±8% 이내)**, 가장 유리한/불리한 배분 5개, **능력치 1점당 한계 효과**(컨택+1, 파워+1, …)를 표와 CSV 로 낸다. 벗어난 배분이 있으면 8.10절 계수 조정안을 같이 적는다. "모든 선택지가 고르게 능력치를 뽑아낼 수 있는가"의 답은 이 보고서다.
- **선생님이 검토하는 지표**: 12.3절 목표표, 8.7절 비거리 분포, 능력치 균형 표. 숫자는 `ExitSpeedModel`·`ContactModel`·`BatterAbilityModel`·펜스 거리 표만 바꾼다.

### 17.3 타이밍 연습장 `tools/baseball-timing-lab.html` + `node tools/baseball-timing-sim.js`
**타이밍은 실제로 눌러 보고 정해야 한다.** 3D 없이 간단한 2D 화면에서 AI 투수가 던지는 공에 사람이 `스윙` 을 눌러 본다.
- 슬라이더로 `SWING_DELAY`, `FLIGHT_SCALE`, 정타 폭 `W` 표, 몸쪽/바깥쪽 보정 `28ms`, 컨택 포인트 배율을 **실시간으로** 바꿔 가며 칠 수 있다.
- 결과: 내 타이밍 오차 히스토그램, 정타율·헛스윙율·파울률, 8.8절 타이밍 게이지 미리보기. 설정값을 JSON 으로 내보내 `TimingModel` 표에 옮긴다.
- **갤럭시탭 S7 FE 에서 터치로** 같은 페이지를 열어 입력 지연까지 느껴 본다.
- `baseball-timing-sim.js`: 가상 사람(타이밍 표준편차 40~120ms, 반응 편향)을 만들어 파라미터 조합별 타율·정타율을 계산해 "어느 값에서 목표 타율(.400)이 나오는지" 찾는다.

## 18. 성능 (SM-T733, 터치한 채로 60fps)
- `docs/common/3d-performance-guide.md`를 만들기 전·끝내기 전에 읽는다.
- 드로 콜 절약: 구장 정적 메시 병합, 관중 인스턴싱, 실시간 조명 0개(방향광 1+반구광 1), 그림자 1개.
- 캐릭터는 한 장면에 투수·포수·타자·수비 7·주자 최대 3·심판 1 = 약 14명 이하의 스킨드 메시 + 가까운 관중 24명 이하.
- 이펙트·공·배트·입자 풀을 **카운트다운 때 한 번 그려 보기**. 게임 중 복제/생성 금지.
- HUD는 `transform`·`opacity`만 움직인다. 글자는 미리 그려 둔다.
- `QualityGovernor`(공용): 단계 예시 — 관중 스킨드 수 줄이기 → 관중 갱신 주기 → 그림자 해상도 → 픽셀 배율(1.5→1.0) → 블룸 끄기.
- 주소 끝 `&fps`로 프레임 확인. 터치 기기 픽셀 배율 상한 1.25~1.5.
- 카메라가 따라가는 동안 보이지 않는 관중석 구역은 갱신하지 않는다(구역별 컬링).
