HTML 은 스크립트를 **motion → field → (pitch → batting → running → defense → play → game → ai) → drills → choreo → actors → park → stage → camera → (live) → lab** 순서로 불러온다(정적 상수 초기화 순서).

**동작 방식**: KayKit 클립은 `Idle_A`·`Running_A`·`Walking_A` 만 쓰고 나머지는 전부 절차 자세다. 자세는 "몸통 각도 + 손·발 목표점(+배트 위치)" 이고 `BbRigPoser` 가 뼈를 맞춘다. **두 손은 배트의 손잡이 점을 따라가므로 떨어지지 않는다**(배트는 손 뼈가 아니라 선수 기준 공간에 놓인다 — 사양서 0.2절의 `BatGrip` 손슬롯 부착 대신 이 방식을 썼다).
모든 동작은 `시작 = 사건 시각 − keyTime` 으로 예약한다(`BbActionSync.startFor`). 공은 손 뼈에 붙어 있다가 릴리스 시각에 그 위치에서 출발하고, 포구 시각에 글러브 뼈에 붙는다.

**캐릭터 비율**: KayKit 은 키 약 1.8m 에 머리 지름 약 0.9m, 어깨 높이 0.89m, 팔 0.54m, 다리 0.30m 다. 그래서 스트라이크 존은 중심 높이 0.62m·반높이 0.24m·반폭 0.25m 로 잡았고(`BbStrikeZoneBox`), 사양서 7.7절 카메라 값(투수 뒤 2.4m, 심판 위치 1.6m)은 머리에 가려 그대로 쓸 수 없다. 시험 페이지 값: 타자 시점은 포수·심판을 숨기고 홈 뒤 2.7m·높이 1.0m·시야각 30°, 투수 시점은 옆 1.9m·뒤 4.2m·높이 3.5m·시야각 26°. **M1 에서 선생님과 확정한다.**

## 3. 선생님 피드백 기록

**2026-11-12 1차 (M0a 시험 장면)** — 모두 반영
1. 배터박스 안으로 파울라인이 넘어옴 → 파울라인을 홈에서 1.72m 지점(박스 앞 모서리 밖)부터 그린다.
2. 외야 펜스 광고판 글씨 → 전부 없앰(패딩 무늬·노란 윗줄만).
3. 전광판 → 실제 모양(이닝 1~9·R·H·E 표, 원정/홈 두 줄, B·S·O 등). 지금은 고정 그림이고 실제 점수 연결은 M3 HUD 때.
4. 플라이 때 외야수 클로즈업 금지 → 넓은 추적 화면만.
5. 타격 시점 → 심판 위치, 포수·심판 숨김, 존이 화면 세로의 약 30%. 존 테두리 표시.
6. 공이 작음 → 보이는 반지름 0.045 → 0.07m(판정용 공 크기와 별개).
7. 포수 장비가 글러브와 겹침 → 가슴 보호대를 몸에 붙는 둥근 판으로, 미트는 몸 앞·옆으로 더 뺌. 심판 보호대는 없앰.
8. 조명에 쇠 기둥이 겹침 → 기둥을 조명판 아래에서 끝냄.
9. 폴대 쪽 거리 표시가 가려짐 → 100 표지를 ±41° 로 옮기고 벽 앞으로 띄움.
10. 송구를 서서 함 → 포구 0.4초 뒤부터 목표 쪽으로 걸어 나가며 던진다(내야 1.1m, 외야 크로우 홉 2.2m).

**2026-11-13 3차 (M2 시험장)** — 반영
1. 타자 시점에서 판정 때 공이 왼쪽 아래에 나타남 → 숨긴 포수가 공을 쥐는 신호는 건너뛰고 투구가 그대로 지나가게 함(`BbDrillScript.ballAt(초, 숨긴 역할)`). 존을 지나는 순간 그 자리에 공 자국(`BbStage` 의 stamp)을 찍는다.
2. 파울·홈런 타구가 관중석·벽을 뚫음 → `BbParkBounds`(경기장 경계·벽 높이·관중석 기울기)와 `BbBlockedFlight` 로 막는다. 관중석에 들어가면 사라지고, 벽에 맞으면 그 자리에서 떨어진다. 추적 카메라도 벽 안쪽 5m 에서 멈춘다.
3. 구속이 느려 보임 → **표시 구속(km/h)을 올리면 정타 폭·타구 속도·AI 타이밍이 함께 바뀌어 시뮬 결과가 달라진다. 그래서 유지.** 화면에서 공이 날아오는 시간만 줄이는 값(`BbPitchTuning.FLIGHT_SCALE` 2.4)은 AI 시뮬 수치와 무관하지만 사람의 반응 시간이 줄어든다(바꾸지 않음, 선생님 결정 대기).
4. 홈런: 접촉 순간 빨간 불꽃(`BbSparkBurst`, 미리 만들어 둔 점 48개), 타자는 타석에서 타구를 보다가 공이 넘어간 뒤 돈다(일주 속도 9m/s).
5. 공 그림자가 두 개 → 의도한 것이 아니었다. 조명 그림자를 끄고 바닥 원 그림자만 남김.

**2026-11-13 4차** — 반영
1. 공이 타자에게 오는 시간을 30% 줄임: `BbPitchTuning.FLIGHT_SCALE` 2.4 → 1.68(직구 137km/h 약 0.75초). 표시 구속·정타 폭·AI 타이밍은 그대로라 `baseball-sim`·`baseball-timing-sim` 결과가 바꾸기 전과 한 글자도 다르지 않다(2000경기 출력 비교). 사람이 치기에는 더 어려워지므로 M3 타격 조작 때 다시 본다.
2. 주루 궤적: 두 베이스 이상 가는 주자는 베이스를 지나며 둥글게 돈다(`BbRunningLane`, 베이스를 지나는 에르미트 곡선을 잘게 나눈 이동). 2루타는 베이스선 밖으로 최대 약 2.7m 부풀고, 2루 → 홈도 3루를 돌아 들어온다. 홈런 일주는 더 각지게(`SQUARED` 0.5, 최대 약 1.7m). 한 베이스만 가면 직선 그대로. 도착 시각은 규칙 그대로라 곡선만큼 조금 더 빨리 달린다.
3. 주루 HUD: 점수판 다이아몬드에 주자의 실제 위치를 점으로 계속 그린다(9절).

**2026-11-13 5차 (조작 시험장을 해 보고)** — 반영
1. 결과를 미리 알리지 않는다: 공이 맞은 순간에는 아무 멘트도 띄우지 않고, 아웃은 실제로 아웃되는 순간 `아웃!` 만, 안타는 타자가 베이스에 닿을 때(`안타!`·`2루타!`), 실책·야수선택은 `세이프!`, 파울은 공이 떨어질 때 띄운다. 아웃카운트와 점수도 그 순간에만 오른다(득점은 홈을 밟는 순간, 홈런 주자도 한 명씩). `BbCallCue.tally`(`out`·`run`·`settle`)와 `BbBoardTicker`(hud 파일)가 한다. 아웃 시각은 규칙 시각이 아니라 **화면에서 공이 그 베이스에 닿는 시각**(`ballReaches`)이다.
2. 1루수 땅볼: 1루수가 타자보다 먼저(여유 0.3초) 베이스에 갈 수 있으면 직접 밟는다. 안 되면 투수가 전력으로 커버를 들어가고 공은 투수가 닿기 0.3초 전보다 일찍 도착하지 않는다. 아웃되는 주자는 공보다 늦게 닿는다.
3. 실책: 공이 수비수 밑으로 빠져 외야로 구르고, 그쪽 외야수가 주워 2루로 던진다(`ballGetsThrough`). 규칙 결과(타자 1루, 주자 한 베이스)는 그대로다. `실책!` 멘트는 없앴다.
4. 점수판 다이아몬드 선이 베이스 사각형 안으로 들어가지 않게 끊어 그림.
5. 홈런 일주: 약 21초 → 약 15초. 일주 속도 9 → 12.8m/s, 타자는 타구를 최대 2.2초만 보고 출발, 홈을 밟은 뒤 걷는 구간을 줄임.

## 15. M7·M8 — 관중·소리·화질 조절·선수 외형·한 번 더 (2026-11-14)

- **소리**(`41.baseball-sound.ts`, 사양서 11.5절): 파일 없이 숫자로 합성한다(`BbSynthBank`, 22050Hz 한 채널, 17종 약 18초·1.5MB). 사양서는 `OfflineAudioContext` 였지만 같은 일을 JS 배열로 미리 만들어 두고, 첫 터치 때 `AudioContext` 를 깨우며 버퍼로 옮긴다 — 게임 중에는 재생만 한다. 효과음·응원 두 칸, 동시 8개 제한, `⋯` 메뉴의 `효과음`·`응원 소리` 켜기/끄기와 `음량: 크게/보통/작게`(기기 저장 `baseballduel_sound_v1`). 나중에 녹음 파일로 바꾸려면 `BbSoundCue.file(칸, 주소)` 로 바꿔 끼운다.
  - 장면 소리 시점은 연출(`BbPitchChoreographer.sounds`: 투구 `release`·포수 `mitt`·헛스윙 `whiff`·타격 `crack`/파울 `tick`·포구 `glove`·송구 `throw`·슬라이딩 `slide`)이 만들고 `BbScenePlayer` 가 시각이 되면 낸다(건너뛰기 때는 안 냄). 거리 18m 밖은 카메라와 멀수록 작게.
  - 관중 반응은 판정 글자(`BbCallCue`)에서 나온다: 아웃 → 수비 쪽 환호+공격 쪽 탄식, 안타·세이프·볼넷 → 환호, 득점 → 종소리+환호, 홈런 → 큰 환호+팡파르+파도타기, 삼진 → 아웃과 같음. 2스트라이크·득점권 주자 때 리듬 박수(2.2초마다), 공수 교대 징글, 투수 시계 5초부터 매초 틱.
- **관중**(`41.baseball-crowd.ts`, 11.3절): 관중석 자리(약 3900명)를 섞은 순서로 인스턴싱(몸통·머리·팔 둘·깃발 = 그리기 4번). 한 사람마다 반응 지연 0~0.6초·속도 0.85~1.15·위상·세기·동작 4종·20% 느린 반응·30% 흔들기, 1루 쪽(x>12m)은 말 공격 팀, 3루 쪽은 초 공격 팀, 가운데는 중립. 분위기: 앉음 → 박수 → 환호(팔 번쩍)·점프 → 탄식, 홈런은 각도 순서로 지나가는 파도타기. 20Hz 갱신, 14구역 중 카메라에 보이는 구역만 고치고, 조용하면 흔드는 사람만 고친다. 깃발은 응원 팀 색(12%).
  - **사양서와 다른 점**: 가까운 줄 스킨드 캐릭터 24명은 넣지 않았다 — 카메라가 대부분 필드를 보고, 스킨드 24명은 갤럭시탭에서 애니메이션 비용이 커서 인스턴싱 사람(팔이 움직임)으로만 했다.
